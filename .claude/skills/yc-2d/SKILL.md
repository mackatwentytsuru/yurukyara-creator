# 2D のキャラ(SVG の部品を板に描く)

正本の説明は `creator/d2/README.md`。ここは、作りながら分かった事と落とし穴。

## 形
- 1 枚の SVG、部品は `<g id>`。顔は `face.<表情>.<枠>`(枠 = eyes・brows・mouth_closed・mouth_half・mouth_open)。部品の中をさらに `<g id>` で分けてよい(耳・手袋など)。
- `Svg2DCharacter` は CharacterBase を継ぐ。3D と同じ呼び方なので、会話の側(dialogue.js の setEmotion・play・setMouth・lookAt)は何も変えずに 2D を動かせる。
- 動きは gestures.js の骨の回転をそのまま使い、`pose2d.js` で 2D に直す。新しい動きを 3D に足せば 2D でも動く(腕は z 回りだけ使う。point の前後の振り = y 回りは 2D では出ない)。
- 表情は混ぜずに差し替える(いちばん強い物 1 つ。0.25 未満は neutral)。
- parts.json の足した項目: `faceLayers`(鼻など、顔と一緒に動く動かない部品)・`arms.front`(false で腕を頭の前に出さない)・`gains`(腕の効き・顔の部品のずれの量・おじぎ・ひじ)・`parts.<名前>.parent`(前腕を上腕に付ける)・`arms.foreBehind`(大きく曲げた前腕を上腕の後ろへ)・`back`(後ろ姿の板)。

## 手描きの絵から作る(主役ノリーで通した、2026-11-06)
- **元の絵を「よく」しない。** 色は元の絵の色だけ(ノリーは 6 色。試験で SVG の色を数える)、ふつうの顔は元の絵のまま。足すのは表情の目・眉・口だけ。
- 輪郭はなぞるのがいちばん忠実だった: 色で領域に分ける → 黒い線を近い領域へ半分ずつ配る(距離の変換で「いちばん近い領域」)→ 部品のマスク → 4 倍に広げてぼかし → 輪郭 → 間引き(0.6 画素)→ なめらかな曲線(角は 58 度より急なら角のまま)。元の絵との差は平均 1.1/255。
- 線は「塗り+黒い線の形」で描く(線の太さの揺れも元のまま)。塗りは線の真ん中までの領域を 2 画素縮める(縮めないと線の外へはみ出す)。
- 部品の境めの線は、前の部品が持つ。後ろの部品も、自分のふちの線(お腹のふち・体の外の輪郭)は持つ。前の部品の輪郭(あごの線・手袋の輪郭・前腕の下の線)は後ろの部品から外す。
- 隠れた所を埋める: 腕の下は体の茶色とお腹のふち、頭の下は胴の茶色(胴の凸包の中だけ)、手袋の下はお腹のふちを上下の線の端からなめらかな曲線でつなぐ。埋めないと、動かした時に穴か線の切れ目が出る。
- 鼻と口を分ける時は、切る所で 5 画素重ねる(すき間の細い線が見える)。鼻を頭の板に置くと、頭が横を向いた時に口だけずれて鼻からはなれる → 鼻は `faceLayers` にする。
- 左右対称の絵は、真ん中の x を測って(ノリーは 296.5)、目・口の形をそこに合わせる。

## 撮る(GPU)
- `creator/d2/record_preview.mjs`: 自分で小さなサーバーを立て、`creator/d2/preview.html` を GPU の Chrome で開き、1 コマずつ進めて撮る(`--stills` 18 枚・`--video 10`。10 秒の台本は まばたき → 話す → 手を振る → 考え中で話す → おじぎ → 後ろを向く)。時間がページの中で決まるので、毎回同じ絵になる。GPU の札(`machine_lock.py run --kind gpu`)の中で流す。
- Windows で札の道具から命令を起こす時は、`npx` は見つからない(`node node_modules/vite/bin/vite.js build` と書く)。`bash` は WSL の bash になるので、Git の bash を full path で書く。
- 会話の画面での確かめ: サーバーを鍵なしで別の番号に立て(`env -u ANTHROPIC_API_KEY -u ELEVENLABS_API_KEY PORT=8823 HOST=127.0.0.1 timeout 600 node server/index.mjs`)、`/?character=<id>&look=2d&place=test_room&auto=0` を開く → 「カメラなしで試す」→ `#textInput` に打って Enter。止めるのは、その番号で待っている PID だけ(`netstat -ano` → `taskkill //PID <番号> //T //F`)。
- 部品の板の線の無いふち(大きく回した袖のふち)に、うすい暗い筋が出る(透明な所が黒として混ざる)。`texture.premultiplyAlpha = true` と「1・1−α」の足し方を試したが、SVG の絵では透けが掛からず、鼻のピンクのまわりに白い輪が出た → 元のまま(透けを掛けない)にした。GPU で 3 通りを並べて決めた(白い輪の方が目立つ)。

## 落とし穴(2026-11-06 に踏んだ物)
- **privacy の試験**(web/test/privacy.test.mjs)が web/src の全部を見る。2D のコードでも次は書けない:
  - `new Image(`・`drawImage(`・`createImageBitmap`・`toDataURL` など → SVG を絵にするのは `THREE.TextureLoader` に blob の URL を渡す。
  - 変数を宛先にした `fetch(` → 読み込みは `character/index.js` の決まった所に任せ、2D の入口は「中身を受け取るだけ」にした。
  - `http://` の文字 → SVG の `xmlns` の値もこれに当たる。部品の SVG には、元の SVG の頭の xmlns を写す(`rootXmlns`)。
- 視線の先が上(人の顔 1.4m)だと、背の低い 2D キャラは頭が上を向いて少し上がる。うなずきの試験は「下がったか」でなく「上下に動いた幅」で見る。
- Bash の heredoc の中の python で `\b` を書くと、ファイルに後退の文字(0x08)が入った。正規表現を直すときは Edit を使うか、`chr(92)` で組む。
- 部品の箱は、ぼかし(feGaussianBlur)のはみ出しまで入れる。filter の範囲も `x="-50%" width="200%"` にしておく。
- 腕が 1 枚の板だと、手を振る時は腕ごと横へ上がる(ひじで曲がらない)。腕の長いキャラは `gains.arm` を下げる(ノリー 0.7 で、手が肩より少し上)。
- 作業フォルダの `.claude/skills/` へは、ファイルを書く道具では書けないことがある。下書きは札の作業フォルダに置く。

## 判定の直し(2026-11-07、主役ノリー)
- **おじぎ**: 前は首の傾き(head・neck の x 回り)と bow の両方で頭を下げ、胸の蝶ネクタイを隠した。`gains.bowHoldHead 1` で、おじぎの間は首の傾きで頭を下げない。頭の板はあごのあたり(頭の pivot)を中心に縦に少しつぶし(`bowHeadSquash`)、顔の部品を下げる(`bowFaceDrop`)と「下を向いた」に見える。試験は板の上下のふちをワールド座標で比べ、蝶ネクタイの見える割合を数える(80% 以上。SVG の書き出しで緑は 88%)。
- **腕を 2 枚に**: 上腕は**胴の後ろ**(z 0.5)。止まっている時は胴にすっかり隠れ、上げると胴の肩の線の後ろから出る → 線の無い袖のふちが見える所に来ない(前の「肩の細い線」はこれ)。前腕(手袋つき)は胴の前(z 2)。ひじは、上腕の先に線つきの丸(半径 = 切る高さの袖の幅の半分)、前腕の元に少し小さい丸(線なし)。parts.json の前腕に `"parent": "arm_r"` と、ひじの pivot。
  - 切る高さは袖がいちばん外へふくらむ所(ノリー y 622)、肩の回る中心は肩の丸の中心(181, 496)。マスクを cv2 で回して重ねる画素の試し(9 通りの角度を 1 枚に)で、20 分で決まった。
  - 曲げ方(`pose2d.js`): 骨の上腕の角度の大きさが 0.3 → 2.25 で、ひじを 0 → `gains.elbow` ラジアン(なめらかに)。手を振る山で上腕 -80 度・前腕 -126 度 ± 17 度(前腕の振りは骨の前腕の z × `swing`)。指さし(point)は少しだけ曲がり、ほぼまっすぐ。
  - 大きく曲げると、太い腕どうしが重なり、前腕の内側の線が上腕の上へ 80 画素ほどはみ出す。線を切ると止まっている時の絵が崩れる → 曲げが `arms.foreBehind`(0.6)を超えたら前腕を上腕の後ろへ回す(renderOrder だけ替える)。戻ると胴の前。
- **後ろ姿の板**: 三面図の後ろ姿は正面と同じ高さ・同じ縮尺で描いてある。横のずれは耳の先と背中の筋の真ん中で測る(ノリー -124)。`<g id="back" transform="translate(-124 0)">` にして、マスクは後ろ姿の絵の座標のまま。板は y で半回りに置き、前の板は表だけ(FrontSide)にする → 後ろから見ると前の板は消え、後ろ姿が出る(S5 のコードは要らない)。2D だけの `play('turn')`(0.55 秒で後ろ・1.4 秒そのまま・0.65 秒で 1 回り)と `setFacing('back'|'front')`。
- **色を足さない**: 後ろ姿の筋の真ん中は、とても暗い灰色 (41,40,38)。正面の 6 色に無いので黒にした(試験で back の中の色が 3 色だけか見る)。
- **隠れた線のつなぎ目**: 止まっている時に隠れている線(手袋の下のお腹のふち)は、動かすと見える。つなぐ線の端は「端の 1 画素」でなく端から 7 画素までの線の重心でとり、太さは元の線と同じにし、両端を今の線へ 7 画素重ねる。足した線は、止まっている時に前の部品が隠す所だけに描く(元の絵との差を変えない)。体の板だけを SVG で描き、輪郭の内側で透けている画素を数えると、すき間が見つかる(165 → 29 画素)。
- **考え中のまま話す口**: 描いていない話す口は、考え中 → のんびり → ふつう(元の絵の笑顔)に落ちる。表情を保ちたい表情は `mouth_half`・`mouth_open` を描く(ノリーは波の形のまま開き、前歯を上のふちに)。
- **GPU を待つ間の確かめ**: `creator/d2/pose_svg.mjs` で姿を 1 枚の SVG に書き出し、SVG として絵にする(WebGL を使わない)。板ごとの matrixWorld を SVG の matrix に直すだけで、GPU の写真とほぼ同じ並びになる。写真の正は GPU で撮る。
- **GPU の札の落とし穴(11-07 に踏んだ)**: `machine_lock.py run ... -- bash x.sh` は WSL の bash を起こし、J: が見えず全部失敗して順番を 1 回むだにした → `"C:/Program Files/Git/bin/bash.exe"` と full path で書く。バックグラウンドの命令を止めても machine_lock の python は残り、待ちの札も残る → 自分の PID だけを `taskkill //PID <番号> //T //F`。待ちは種類をまたいで先着で、動画の生成が先頭にいると、ほかの GPU も待つ(25 分〜1 時間)。台本は 1 回の札で全部(写真・2 倍・動画・会話の画面)撮る形にする。

## 試験の作り方
- 画像にする所(rasterize)を外から渡すので、node --test では `new THREE.Texture()` を返す偽物で済む(DOM が要らない)。
- 意図の列の試験は K2 の `web/src/character/intent.js` の `applyIntent` を使う。キャラごとに、描いた表情に合わせて「どの目・眉・口が出るか」を書く(描いていない枠は近い表情 → neutral)。
- 見える板を数えて確かめる: どの表情・口の値でも、目 1 枚・口 1 枚が必ず出る。
- 手描きの絵から作ったキャラは、色の数(元の絵の色だけ)・部品の `<g id>`・前歯などの目じるしが開いた口に残るか、も試験にする。

## 測った数
- ようこそくん: SVG 8KB。試験 12 件。
- ノリー: SVG 87KB(なぞった線のため)。部品の板 6+鼻 1+顔の差し替え 28。試験 11 件(`char2d_norrie.test.mjs`)。GPU(RTX 5090)で 14 枚と 10 秒(300 コマ)を撮って 1 分ほど。
- ノリー(11-07 の直しの後): SVG 119KB(後ろ姿の板で +30KB)。部品の板 8(上腕・前腕が 2 枚ずつ)+鼻 1+顔の差し替え 30+後ろ姿 1。試験 16 件。正面の元の絵との差は 1.12/255 のまま(腕を 2 枚にしても、止まっている時の絵は変わらない)。後ろ姿の板は 2.07/255。

## ノリーの 2D に「大きな目と光・ほお」を足した記録(11-07 夜、3D の案 C にそろえた)
3D を案 C(大きな目に白い光が大小 2 つ・桃色のほお)に決めたので、2D も同じ可愛さにして 3D と 2D の切り替えで別人に見えないようにした。変えたのは `body.svg` と `parts.json` と試験だけ。
- **目**: 黒い丸を絵の 1.3 倍(半径 16 → 20.8、驚きは 19.5 → 25.4)にし、白い光を円で 2 つ足した(大 = 半径 0.34、中心を目の中心から左上へ 0.32・0.34。小 = 0.16、右下へ 0.36・0.38。単位は目の半径)。目を開く表情(neutral・surprised・sad・angry・think)の `face.<表情>.eyes` にだけ足し、目を閉じた線の happy・relaxed には足さない。目の枠(parts.json の face.eyes.box)の中に収まる(驚きの目で上下 5 の余り)ので、枠は変えない。眉とも重ならない。
- **ほお**: 鼻と同じ桃色(#E4B2BC、色を足さない)の楕円 2 つを、顔の上の部品 `cheeks`(parts.json の faceLayers に足す。目の枠でなく鼻と同じ仲間)に置いた。目の枠に入れると、まばたきの縦つぶしで消えて桃色がちらつくので、別の板にした。位置は鼻の横・口の高さ(顔の絵の座標で 219 と 374・高さ 341、半径 16×10.5)。クリーム色の中で、外側の黒い輪郭から約 10 空く。
- **まばたき**: 光は目の板と一緒に縦につぶれる(最小 0.08 倍)。全閉の写真で、目の高さの帯の純白(最小値 > 235)の画素は 0。黒い線の中に、1 画素ほどの薄い明るい筋が残る(拡大でだけ見える)。完全に消したい時は、光を別の板にして `_apply` で出し入れする(コードの変更が要る)。
- **試験**: `char2d_norrie.test.mjs` の「ふつうの顔」は、黒い丸が 2 つで半径が 14〜18 という昔の目を前提にしていたので、黒い丸 2 つ(半径 14 超〜20.9)+ 白い光 4 つ(目の円の中に収まる)に直した。新しい試験で、目を開く 5 表情の光・閉じた 2 表情に光なし・ほおの色と板を確かめる。
- **確かめ方**: 描く前に、SVG だけを Chrome で絵にして(WebGL を使わない)顔の部分を拡大すると、位置が数分で決まる。ただし `<g id="back">` は前の絵と重なるので `display="none"` で隠す。アプリで見るなら web を vite build し、`PORT=<自分のポート> node server/index.mjs` を起こす(vite dev は /characters を別のサーバーへ回すので 502 になる)。

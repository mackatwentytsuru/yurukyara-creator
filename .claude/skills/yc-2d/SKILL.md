# 2D のキャラ(SVG の部品を板に描く)

正本の説明は `creator/d2/README.md`。ここは、作りながら分かった事と落とし穴。

## 形
- 1 枚の SVG、部品は `<g id>`。顔は `face.<表情>.<枠>`(枠 = eyes・brows・mouth_closed・mouth_half・mouth_open)。部品の中をさらに `<g id>` で分けてよい(耳・手袋など)。
- `Svg2DCharacter` は CharacterBase を継ぐ。3D と同じ呼び方なので、会話の側(dialogue.js の setEmotion・play・setMouth・lookAt)は何も変えずに 2D を動かせる。
- 動きは gestures.js の骨の回転をそのまま使い、`pose2d.js` で 2D に直す。新しい動きを 3D に足せば 2D でも動く(腕は z 回りだけ使う。point の前後の振り = y 回りは 2D では出ない)。
- 表情は混ぜずに差し替える(いちばん強い物 1 つ。0.25 未満は neutral)。
- parts.json の足した項目: `faceLayers`(鼻など、顔と一緒に動く動かない部品)・`arms.front`(false で腕を頭の前に出さない)・`gains`(腕の効き・顔の部品のずれの量)。

## 手描きの絵から作る(主役ノリーで通した、2026-11-06)
- **元の絵を「よく」しない。** 色は元の絵の色だけ(ノリーは 6 色。試験で SVG の色を数える)、ふつうの顔は元の絵のまま。足すのは表情の目・眉・口だけ。
- 輪郭はなぞるのがいちばん忠実だった: 色で領域に分ける → 黒い線を近い領域へ半分ずつ配る(距離の変換で「いちばん近い領域」)→ 部品のマスク → 4 倍に広げてぼかし → 輪郭 → 間引き(0.6 画素)→ なめらかな曲線(角は 58 度より急なら角のまま)。元の絵との差は平均 1.1/255。
- 線は「塗り+黒い線の形」で描く(線の太さの揺れも元のまま)。塗りは線の真ん中までの領域を 2 画素縮める(縮めないと線の外へはみ出す)。
- 部品の境めの線は、前の部品が持つ。後ろの部品も、自分のふちの線(お腹のふち・体の外の輪郭)は持つ。前の部品の輪郭(あごの線・手袋の輪郭・前腕の下の線)は後ろの部品から外す。
- 隠れた所を埋める: 腕の下は体の茶色とお腹のふち、頭の下は胴の茶色(胴の凸包の中だけ)、手袋の下はお腹のふちを上下の線の端からなめらかな曲線でつなぐ。埋めないと、動かした時に穴か線の切れ目が出る。
- 鼻と口を分ける時は、切る所で 5 画素重ねる(すき間の細い線が見える)。鼻を頭の板に置くと、頭が横を向いた時に口だけずれて鼻からはなれる → 鼻は `faceLayers` にする。
- 左右対称の絵は、真ん中の x を測って(ノリーは 296.5)、目・口の形をそこに合わせる。

## 撮る(GPU)
- `creator/d2/record_preview.mjs`: 自分で小さなサーバーを立て、`creator/d2/preview.html` を GPU の Chrome で開き、1 コマずつ進めて撮る(`--stills` 14 枚・`--video 10`)。時間がページの中で決まるので、毎回同じ絵になる。GPU の札(`machine_lock.py run --kind gpu`)の中で流す。
- Windows で札の道具から命令を起こす時は、`npx` は見つからない(`node node_modules/vite/bin/vite.js build` と書く)。`bash` は WSL の bash になるので、Git の bash を full path で書く。
- 会話の画面での確かめ: サーバーを鍵なしで別の番号に立て(`env -u ANTHROPIC_API_KEY -u ELEVENLABS_API_KEY PORT=8823 HOST=127.0.0.1 timeout 600 node server/index.mjs`)、`/?character=<id>&look=2d&place=test_room&auto=0` を開く → 「カメラなしで試す」→ `#textInput` に打って Enter。止めるのは、その番号で待っている PID だけ(`netstat -ano` → `taskkill //PID <番号> //T //F`)。
- 部品の板の線の無いふち(大きく回した袖のふち)に、うすい暗い筋が出る(透明な所が黒として混ざる)。`texture.premultiplyAlpha = true` と「1・1−α」の足し方を試したが、SVG の絵では透けが掛からず、鼻のピンクのまわりに白い輪が出た → 元のまま(透けを掛けない)にした。GPU で 3 通りを並べて決めた(白い輪の方が目立つ)。

## 落とし穴(2026-11-06 に踏んだ物)
- **privacy の試験**(web/test/privacy.test.mjs)が web/src の全部を見る。2D のコードでも次は書けない:
  - `new Image(`・`drawImage(`・`createImageBitmap`・`toDataURL` など → SVG を絵にするのは `THREE.TextureLoader` に blob の URL を渡す。
  - 変数を宛先にした `fetch(` → 読み込みは `character/index.js` の決まった所に任せ、2D の入口は「中身を受け取るだけ」にした。
  - `http://` の文字 → SVG の `xmlns` の値もこれに当たる。部品の SVG には、元の SVG の頭の xmlns を写す(`rootXmlns`)。
- 視線の先が上(人の顔 1.4m)だと、背の低い 2D キャラは頭が上を向いて少し上がる。うなずきの試験は「下がったか」でなく「上下に動いた幅」で見る。
- Bash の heredoc の中の python で `\b` を書くと、ファイルに後退の文字(0x08)が入った。正規表現を直すときは Edit を使うか、`chr(92)` で組む。
- 部品の箱は、ぼかし(feGaussianBlur)のはみ出しまで入れる。filter の範囲も `x="-50%" width="200%"` にしておく。
- 腕が 1 枚の板だと、手を振る時は腕ごと横へ上がる(ひじで曲がらない)。腕の長いキャラは `gains.arm` を下げる(ノリー 0.7 で、手が肩より少し上)。
- 作業フォルダの `.claude/skills/` へは、ファイルを書く道具では書けないことがある。下書きは札の作業フォルダに置く。

## 試験の作り方
- 画像にする所(rasterize)を外から渡すので、node --test では `new THREE.Texture()` を返す偽物で済む(DOM が要らない)。
- 意図の列の試験は K2 の `web/src/character/intent.js` の `applyIntent` を使う。キャラごとに、描いた表情に合わせて「どの目・眉・口が出るか」を書く(描いていない枠は近い表情 → neutral)。
- 見える板を数えて確かめる: どの表情・口の値でも、目 1 枚・口 1 枚が必ず出る。
- 手描きの絵から作ったキャラは、色の数(元の絵の色だけ)・部品の `<g id>`・前歯などの目じるしが開いた口に残るか、も試験にする。

## 測った数
- ようこそくん: SVG 8KB。試験 12 件。
- ノリー: SVG 87KB(なぞった線のため)。部品の板 6+鼻 1+顔の差し替え 28。試験 11 件(`char2d_norrie.test.mjs`)。GPU(RTX 5090)で 14 枚と 10 秒(300 コマ)を撮って 1 分ほど。

# CC5 でアニメ調のキャラを作る

> **先に守ること(偽の窓口の比べで、読んだのに破って落ちた回が出た):** 調べている間は保存しない。Refine Face を開く前に `GetLandmarks` を呼ばない(CC5 が落ちる)。飾り付きと男性用のプリセットを当てない。

2026-10-31〜11-04 に、アニメ調の女性 1 体を作った記録から書いた。数字は「実測」、確かめていないものは「未確認」と書く。効かなかった見立ても残す(同じ失敗を避けるため)。CC5 と、その外の道具(cc5-mcp-server)は部品として使うだけで、このリポジトリには入れない。

## 1. 使う場面

- アニメ調の絵(平たい顔)から、CC5 の頭・体・目を持つ 3D のキャラを作る。
- 写実の人間は別のスキル(cc5-human-character)。アニメ調の平たい顔の絵は、Headshot の写真の道では顔の点が取れなかった。この記録では、頭を自前のメッシュで用意し Mesh to Head で入れた。

## 2. 期間内の新作だけを使う決まり

- ハッカソンの期間は 2026-11-02 から。**提出に映す物は期間内に作った物だけ。**
- 期間前に作った頭・髪・帽子・羽根・服・体は、**CC5 に読み込まない・写さない**。比べの手本として画面で見るのは良い(形や色の目安)。
- 手本を見て作り直した物は、新しい形・新しい絵として作る。手本のファイルを加工して使うのは、作り直しにならない。
- 部品の日付は、ファイルの更新日だけでは作った日と限らない(写した日が出る)。出どころが分からない物は「不明」として使わない。
- 期間前の部品の一覧は、別に表で持つ(社内の文書)。このスキルには中身を書かない。

## 3. 工程の順(前に通した記録)

1. **体**: 服なしの全身の絵 4 枚(正面・左・背面・右)から 3D 生成の道具で体を作る。Blender で 158 cm・足元 0 にし、190 万三角を 20 万へ減らした。ずれは中央値 0.13 cm(実測)。
2. **Body Wrap**: Template-based → Create Guides → Generate Skeleton → GENERATE WRAP POINTS。
   - 自動の骨で 207/218 組、腕・手・指の 108 点に相手がついた(実測)。数字で作った骨を読み込むと、腕と手に相手がなく 92 組になった。**自動の骨を使う。**
   - 点 36〜38 が肩や背中に付くと首が崩れる。首の前寄りに置き直すと、内向きの面が 67 → 30(実測)。
   - REFINE MESH は Subdivide 2 回 → Auto Projection Apply(Exact、マスクなし)。指先と胸のぎざぎざが消えた。
3. **頭**: Mesh to Head。後ろが開いた頭だと頭が円すいになる。Blender で後ろを閉じると Entire Head が通る。頂点数と順が同じなら、点の .ini を読み直せる。
4. **Generate Character**: Keep Neck Shape オン、Keep Head Size オフ、Apply Head Color to Body オン、Body Type Current、2048、No Mask。Normal は From Source で作った記録がある(その版は、5 章の試験で法線が効いていなかった)。**押すと戻せないので、先に別名で保存する。**
5. **肌の絵の掃除**: 肌の絵に元の絵の目(白目・アイライン)が描かれていると、閉じた時に黒い帯と白い三日月が出る(確認済み)。頭を入れる前に絵から消すと消えた。
6. **目**(4 章)。
7. **髪・服・靴**: 作り直した物を入れる。靴を外すと体が上がる(6.7 cm の記録)ので、靴を入れたら足元を確かめる。
8. 撮影(7 章の合格の線)。

## 3b. 外の頭の向きと肌(実測)

- **FBX の前後の軸を、読み直して鼻の座標で確かめる。** 前後を逆に書き出した頭は、Mesh to Head を通っても後頭部が前を向く失敗作になる(正面の撮影に後頭部が写る)。正しい頭は Blender で読み直して鼻が -Y。前 +Z・上 Y の OBJ は `forward_axis="NEGATIVE_Z"` で読む(`"Z"` で読むと鼻が +Y になる)。元の OBJ の前後は資料でなく生の座標で測る。
- 点の .ini は三角形の番号と重心の座標で持つので、向きだけを直すなら作り直さなくてよい(頂点の順が同じ事を先に確かめる。実測の差 0.0004 mm)。
- 3D 生成の道具の体や頭に UV も材質も無いと、生成の時に Textureless を選ぶしかなく、肌が暗い灰色になる。肌色は生成の後で CC の UV へ描いて差す。
- Generate Character の Normal に「入れない」の選択肢は無い(From Source Mesh か From High Poly)。輪が出たら生成の後で平らな絵に差し替える。
- **肌や材質を直す前に、入力の形を確かめる。** 入力を色なしで正面と斜めから撮り、元の絵と並べて、目のくぼみ、鼻の大きさ、あごの細さを見る。形が違えば、肌をいくら直しても似ない。目のくぼみが無い頭は、目の点を頭の幅の約 0.29 に広げて置いても、開いた目は小さいままだった(目の開き / 顔の幅は元の絵 0.23、生成後 0.16。絵から手で読んだ概算、1 体の実測。原因は未確認)。
- 外の頭を Mesh to Head に入れたあと、歯と歯ぐきがあごの下へ出る事がある(撮影の正面と笑顔で見る)。肌の形が変わり、歯が低い位置に残ったのが原因と見ている(骨は正規の親子のまま)。頭と歯の高さは OBJ で測れる。`Teeth Height`、`Teeth Lower Height`、`Actor/Head/Mouth/Teeth` の `Teeth Lower Height` を各 1.0 にすると、歯の下端が約 1.5 cm 上がって、皮膚の内側に入った(1 体の実測。笑うと歯がくすんで見えるのは残った)。
## 4. 目の作り方

順番は **補正 → まつげのプリセット → 目のモーフ → 補正**。補正は Character > Correct Eyeblink。

- まつげのプリセットは、目のモーフを戻す疑いがある(1 回の観察: モーフの後に当てると目が丸くなった)。**撮る前にモーフの値を読み戻して確かめる。**
- 目のモーフの値の例: Eye Scale 0.5、Eye Round A 1.0、Eye Thin -1.0、Eyelid Lower Height -0.6、Eye Width -0.4、Eyeball Iris Scale 1.0。目の開き(高さ÷幅)は 0.61 → 0.69(実測)。
- 目を大きくすると閉じきらない。Correct Eyeblink を流すと閉じる。
- **目の絵**: 角膜の Shader Type を Traditional にすると、角膜の Diffuse の絵が見える。左右とも切り替える(Symmetrical Shader では片目しか変わらなかった)。CC5 の Python(RLPy)で `mc.SetShader("CC_Base_Eye", "Std_Cornea_R", "Traditional")` が通った(実測。マウスは要らない)。
- 虹彩は縦長に描く(横 0.85・縦 1.25)。白目は無地。角膜の AO は白(黒い外側が灰色の見え方の原因の一つ、という見立て。因果は推し)。
- 下まつげの絵を太くすると、下まぶたが黒い帯になる。**太くするのは上だけ。**
- まつげのプリセット Lush and Dramatic は濃い線に見える。下は Short Sparse_Low で薄くできる。

## 5. 目のまわりの輪・皺と黒い線の切り分け

部品を順に外して撮り、1 つ前の段との目のまわりの平均の差を見た(実測)。数字は 開いた目 / 閉じた目。差が大きい部品が原因。

| 外した物 | 今の体 | 比べの版 |
|---|---|---|
| 目の影の部品 | 0.00 / 0.00 | 0.00 / 0.01 |
| 涙の線 | 0.14 / 0.00 | 0.18 / 0.01 |
| 肌のまつ毛 | 0.70 / 1.00 | 4.29 / 4.93 |
| 角膜の AO を白 | 0.12 / 0.00 | 0.00 / 0.00 |
| **肌の法線を平ら** | **4.70 / 6.36** | **0.00 / 0.00** |
| 肌の AO を白 | 0.00 / 0.00 | 0.00 / 0.00 |
| 肌の色の絵を平ら | 6.52 / 7.16 | 6.93 / 7.90 |

- **結論**: 輪と皺の原因は肌の法線の絵。平らな絵(128, 128, 255)を `load_texture` の `normal` で当てると消えた。比べの版で法線が効かない理由は**未確認**。
- 下まぶたの外側の黒い線は、肌の絵を平らにしても残る。肌色で塗っても消えない。肌の絵ではなく、形(元の目の穴の縁の段差)と見ている。形を直して消えるかは**未確認**。
- 閉じた目のピンクと皺の模様は、肌の色の絵を平らにしても残る。出どころは**未確認**。
- **誤った見立て(繰り返さない)**:
  - 「法線の強さを変えても輪は残る」と一度結論した。使った命令(`GetChannelTextureWeight`)が存在せず、失敗していた。
  - AO が原因という見立ても、差 0 で外れた。
  - **命令が効いたかは、前後の絵の差で確かめる。** 返事が来ただけでは効いた証拠にならない。
- 直した版の残り: 目が丸く飛び出して見える、下まつげが長い、笑顔であごの下に筋が出る。原因は**未確認**。
- 切り分けのやり方: 1 回で全部を比べるには、部品を順に積み上げて外す。絵を元に戻す命令がないので、**保存せず閉じる**。

## 6. 測りの場所を確かめる順番

測った数字を信じる前に、次の順で確かめる。

1. **自分の確認**: 答えの分かる試験と、別の方法で同じ場所を測る。
2. **本人の確認**: 測った線を絵に描いて、A / B で本人に聞く。
3. **合わせる**: 1 と 2 が合ってから使う。確認前の数字は「未確認の測り」と書く。

- MediaPipe の黒目の点は、実際の黒目の大きさに追随しない(相関 0.34、実測)。径は、中心から水平 ±15 度の線で明るさの勾配の頂を取って中央値にする(相関 0.999、12 枚中 3 枚は測れない。写実の頭での試験で、アニメの目では未確認)。
- 小鼻の点 129・358 は、小鼻より外の頬に出る。鼻の幅は小鼻の高さの行の勾配の頂で測る。
- 試験の基準は流す前に書き、落ちた試験は落ちたまま残す。
- `RLPy2.Headshot3.GetLandmarks` は、Refine Face を開かずに呼ぶと CC5 が落ちた(1 回の観察)。開いた後は読めるが、モーフを動かしても 1 点も動かず、今の頭の測りには使えない。

## 7. 合格の線(何を撮って何を見るか)

同じ枠・同じ光で撮る。判定は作った人がしない。見た目の最後の確認は本人。**撮る前に 5 章の線が出ていないか、前後の絵の差で確かめる。**

| 撮る物 | 見る物 |
|---|---|
| 正面 | 顔が左右対称、目の高さがそろう、首の継ぎ目なし |
| 3/4 | 目頭・目尻の飛び出しなし、まつげのはみ出しなし、髪や帽子と顔の突き抜けなし |
| 真横 | 鼻・あごの輪郭、後頭部の継ぎ目、首の崩れなし |
| 閉じた目 | 黒い帯・白い三日月なし、完全に閉じる、輪と皺とピンクの模様なし |
| 半目 | まぶたの破れなし、白目が不自然に見えない |
| 笑顔 | 目が不自然に丸くならない、あごの下に筋が出ない、口の両脇に灰色の点なし |
| 視線の上下左右 | 黒目(虹彩)がまぶたを突き抜けない、縦長の形が崩れない、左右がそろう |

- 笑顔の口の両脇の灰色の点は、犬歯が頬の皮膚を貫通していた(実測 0.045 cm)。Teeth Depth を -0.5 にすると消えた。
- 「閉じない」は 4 章の補正、「黒い帯」は 3 章の 5 を見る。

## 8. つまずき表

| 症状 | 原因・直し |
|---|---|
| `/ui/*` の仕事が番号だけ返して戻る | 終わりを待つ。結果が出る前に次を送らない |
| 処理中の窓で命令が断られる | 待ってやり直す |
| 返事が途中で切れる | 返事は 1 万字で切れる。小さく分けて読む |
| `RVector2f` の `.x` が無い | 使えない。値は別の形で取る |
| Qt の撮影で 3D の画面が黒い | Qt の撮影は 3D を写さない。CC5 の撮影の命令を使う |
| `qtHeadshot3PanelToolbar` を押したら閉じた | 開閉の切り替え。今の状態を見てから押す |
| 作り直しの直後に、スライダーが古い | Help > Refresh Sliders |
| Generate Character を押して戻せない | 押す前に別名で保存 |
| 腕と手に相手がつかない | 数字で作った骨をやめ、自動の骨にする |
| 首が崩れる | 点 36〜38 を首の前寄りへ |
| 頭が円すいになる | 後ろが開いた頭。Blender で閉じる |
| 目が閉じない | Correct Eyeblink |
| 閉じた目に黒い帯 | 肌の絵の元の目を消す(3 章の 5) |
| 目の絵が見えない | 角膜を Traditional に(左右とも) |
| 輪・皺 | 5 章。肌の法線を平らに |
| 下まぶたが黒い帯 | 下まつげの絵を細く。太くするのは上だけ |

## 9. 確かめていないこと

- 比べの版で肌の法線が効かない理由。
- 下まぶたの外側の黒い線を、形を直して消せるか。
- 閉じた目のピンクと皺の模様の出どころ。
- 直した版の残り(目が丸く飛び出す、下まつげが長い、笑顔であごの下に筋)の原因。
- まつげのプリセットがモーフを戻すこと(1 回の観察だけ)。
- 角膜の AO が白でないことが灰色の原因、という因果(推し)。
- 7 章の合格の線で、全部を直した版が通るか(この記録では最後まで撮り切っていない)。
- 作った人以外の判定(本人の A / B)は、この記録の数字にはまだ入っていない。

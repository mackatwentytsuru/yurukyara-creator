# 検査の検査(わざと不良を入れて、落ちるか見る)

検査が「通った」だけでは、約束が守られている証拠にならない。**検査が見ていない書き方があれば、素通りする。** 不良を 1 件ずつ入れた使い捨ての写しに検査を流し、落ちなければ穴。

## 道具(web/scripts/)

- `mutation-check.mjs`: `src` と `test/privacy.test.mjs` を一時フォルダに写し、画像を外へ出す書き方を 1 件ずつ足して試験を流す。まず元のままで通ることを確かめ(通らなければ、落ちた理由が不良とは言えない)、そのあと各不良で「落ちるべき」を見る。
- `guard-check.mjs`: 使い捨ての git リポジトリに、鍵・.env・VRM・ログ・入れてはいけない名前を 1 つずつ stage して、commit 前フック(`.claude/hooks/check-secrets.mjs`)と `tools/prepush_check.py` が止めるか見る。**期待を表に書く**(例: GitHub の鍵はフックでは通し、push 前で止める)ので、期待と違う物だけが × になる。
- 偽の鍵は実行時に組み立てる(スクリプト自身に鍵らしい文字列が残ると、自分の検査に引っかかる)。入れてはいけない名前も文字コードで書く。

## 2026-11-02 に見つけた穴と、直し方

- プライバシー試験: 17 件の不良のうち、最初に 7 件が素通りだった。
  - 変数を宛先にした `fetch(dest)`(文字の宛先しか見ていなかった)。
  - `new Image().src = 外の住所`(画像ビーコン)。
  - `EventSource`・`Worker`・`ImageCapture`・`getDisplayMedia`。
  - 動的 `import('https://…')`。
  - 直し: 禁止の言葉を足す。変数の宛先の `fetch` は、「場所と式」の許可リスト(今は読み込みの 3 か所)に無ければ落とす。`http(s)://`・`ws(s)://` の文字を、画面のコードに置かない。
- push 前の検査と commit 前フック: `.env.local`・`.env.production` が素通りだった(`.env` ちょうどしか見ていなかった)。`.env.*` を止め、見本の `.env.example`・`.env.sample` だけ通すように直した。
- 直した後は、同じ表を流して穴 0 件を確かめる。

## 入口を守る(外から来る値は、型・値・長さを確かめてから先へ)

外の資料(組 3「Realtime 通信の入力検証」: 頻度制限 → 型と値の検証 → 状態の検証、NaN と無限大を拒否)の考え方を、2 か所に当てた。

- `server/validate.mjs`: `/api/chat` の本文を、**Claude を呼ぶ枠を使う前に**きれいにする。形が根本から違えば 400、本文が大きすぎれば 413。発言 500 字・履歴 12 件×2000 字・場所の情報 4000 字・目印 32 件・表情と動きの名前の数、で切る。日本語は 1 字 3 バイトなので、読み込みの上限(256KB)は余裕を持たせ、長さは sanitize が切る(最初に 64KB にして、履歴だけで超える計算になり、直した)。
- `/api/metrics`: 受け取った本文を丸ごとログに書いていたのを、知っている項目(数は有限のものだけ)に絞った。好きな名前・長い文字をログに書き込ませない。
- `PoseSource.setPeople`(殻や VR から来る位置): 3 つの数が有限で、±1000m 以内の人だけ受け取る。NaN が 1 人でも入ると首の計算が全部 NaN になる。人数は 8 人まで。視線が壊れていれば視線だけ捨てる。`speaking: false` は意味があるので、真偽はそのまま通す(`undefined` にしない)。
- 試験: `test/validate.test.mjs`(13 件)。本物の画面から 1 往復して、200 で返ることも確かめた。
- つまずき: 試しに `/api/metrics` へ送ったデータが、実測のログ(`logs/latency.jsonl`)に混ざった。**数字を汚す試しは、先にログの写しを取り、終わったら戻す。**

## 使いどころ

- 検査を足す・直したら、必ず流す。公開リポジトリにする前にも流す。
- 新しい「外へ出す書き方」を見つけたら、`MUTATIONS` に 1 行足し、落ちなければ検査を直す。
- 画面のコードに変数の宛先の `fetch` を足したくなったら、`privacy.test.mjs` の `VARIABLE_FETCH` に、宛先が自分のサーバーか確かめてから足す。
- 外の資料(3D スキルの抜き出し 組 3 の「CI 品質ゲート」: 各検査に意図的な不良を 1 件入れて、検出を確かめる)の考え方を借りた。コードは写していない。

## 「消毒」(絶対パス・ユーザー名・ホスト名・鍵を消す処理)の確かめ方

- **試験の入力に、消えるべき物をわざと入れる。** 記録の中の自由な文(作業の説明、読んだファイルの名前、最後の報告)に、絶対パス・`ユーザー名@ホスト名`・IP・`password=…`・鍵の形を入れる。出力に、それぞれの語が(大文字小文字を変えても)残っていないことを `assertNotIn` で見る。あわせて、消しただけで中身(数字・道具の数・スキルの名前)は残っていることも見る。
- **消毒そのものを壊して、試験が落ちることを見る。** `tools/metrics.py` の `sanitize` と `assert_clean` を何もしない関数に替えた写しで `tools/test_metrics.py` を流した。結果: 3 件が落ちた(消毒の試験、「パスの中で見つけた名前が別の場所からも消える」試験、「消し残しがあれば止まる」試験)。壊しても通る試験は、検査になっていない。
- **ユーザー名は環境から集めるだけでなく、パスの中からも拾う。** `…\Users\<名前>\…` や `/home/<名前>/…` の `<名前>` を、ほかの場所からも消す(環境の名前と記録の名前が違うことがある)。日本語の語に続く名前(`名前さん`)も消えるよう、境目は ASCII の英数字だけで見る。
- **最後に関所を置く。** 書き出す前に、同じ検出の正規表現で消し残しを探し、あれば例外で止める(出力を書かない)。
- **試験のコードにも、絶対パスや鍵の形を直書きしない。** `push` 前の検査(`tools/prepush_check.py`)が、鍵の形のダミー(`sk-ant-…`)を実際に止めた。ダミーは `"sk-" + "ant-…"` のように分けて組み立てる。絶対パスも `chr(92)` などで組み立てる。

## 「数字を手で書かない」表の確かめ方

- 表に出す数字は、(1) 入力の文字から写した物か、(2) 計算して台帳(`Ledger.n`)に登録した物、のどちらかだけにする。`--check-numbers` が、表の行の数字がすべて台帳にあることを見る(手書きの数字が混ざると 1 件でも落ちる)。試験では、台帳に無い数字を入れた表が「出どころ無し」と検出されることも見る。
- 同じ入力で 2 回流して、出力が 1 文字も違わないことを `diff` で見る(生成した日は入れず、日付は入力の最後のコミット日か記録の時刻にする)。環境変数で渡しても同じ出力になることも見る。
- 足し上げの元になる文(結果表の表)の「通った」の決め方は、列を限って文字で判定する(「合否」「検査」「ブラウザ再生」の列に `不合格`・`NG`・`残る`、または時間の欄に `時間切れ`)。行全体で探すと、「9 周(うち 6 周は NG、最後は全部 OK)」のような説明文で、通った回を落としてしまった(この表の「検査の周」の欄)。

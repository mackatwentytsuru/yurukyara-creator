# デモ動画の仮編集(ffmpeg だけ)

## 形
- 正本は 4 つ: `cuts.json`(カット・区切り・秒・早回しの倍率・画面の札・状態・代わり)、`narration.json`(語り。動画の頭からの秒・字幕の文・声に渡す読み)、`素材台帳.csv`(素材 ID・撮る時・端末・撮る人・日時・commit・本物か仮・出どころ・ファイル)、`数字.json`(字幕と語りに出す数字と、その出どころ)。
- 絵コンテの表と語りの台本(Markdown)は JSON から作る。手で直さない(秒の食い違いを防ぐ)。
- 区切りごとに 1920x1080・30fps・AAC 48kHz 2ch の mp4 を作り、concat の `-c copy` でつなぐ。最後の 1 回で語りの字幕を焼き、音をそろえる(loudnorm)。
- 素材のファイルが無い区切りは、ID と中身と撮る時を書いた仮の映像(testsrc2)で埋め、左上に赤い「仮」の印を焼く。仕上げの書き出し(`--final`)は、仮の素材・「本物」でない行・無い数字が 1 つでもあれば止まる。
- 「出たら使う」素材は、台帳の「ファイル」に出る予定のパスを先に書き、「本物か仮」を `未着` にする。ファイルが出たら `sync` が日時を入れて `本物の候補` にし、次の書き出しから自動で仮と入れ替わる。ID の中身を替える時は、日時を空にして `未着` に戻し、前のパスはメモに残す(sync が新しいファイルの時刻を入れ直す)。
- 札(文字の区切り)には `images`(台帳 ID の静止画・高さ・x・y)で絵を重ねられる。透明の PNG はそのまま重なる。見出しも小見出しも無い札は絵だけの札(名前の札)。まだ届いていない絵は「仮 <ID>」の文字になる。
- 語りの行に `"subtitle": false` を付けると、声だけで字幕を焼かない(札に同じ文がある時。2 重に出さない)。

## 決まり
- 数字は、記録(run.jsonl・試験の出力)から写した `数字.json` の値だけを出す。無い値は「(未測定)」、URL は「(公開の後に入る)」と出す。推しはかった数字を書かない。定額のプランで流した回のお金は「定価に直した目安」と書く。
- カットごとに「状態(根拠)」を書く: 通った物は命令と結果、まだの物は待っている作業。言うのは撮る前に通った機能だけ。通らなければ「代わり」にし、語りも替える(語りの行の注に替える文を書いておく)。
- 入力の数を偽らない。三面図(3 枚)から作った 3D に「絵 1 枚から」と語らない(2D が正面 1 枚からなら、そう分けて言う)。
- 1 つの見せ場は、1 人の子の本当の流れで撮る(例: やり直し+一言 → 描き直し → OK が無いと止まる → OK)。状態の違う子を 2 人用意して切り貼りすると、絵の違い(葉っぱの大きさなど)で見ている人にばれる。語りの言葉(「葉っぱを大きく」)と撮影で送る一言を同じにする。
- 早回しは `setpts=(PTS-STARTPTS)/倍率`。素材から `秒×倍率` を切り出す。早回しの音は消す。
- 仕上げは `-map_metadata -1 -map_chapters -1 -fflags +bitexact`。ffprobe で長さが上限未満で、全体のタグが空であることを確かめる。
- 字は画面幅の 3% 以上: 語り 64px(1920 幅)・札 60px。400px 幅に縮めた 1 コマと、5 秒に 1 コマの一覧の絵で見る。

## 語り(声は後から作る)
- 語りは画面の下の字幕、区切りの札は画面の上(左上・右上)に分ける。重ねない。
- 行ごとに `start`・`end`・`text`(字幕)・`tts`(声に渡す読み。英字はカタカナ、数字は読みで書く。かぎかっこは外す)・`note`(条件と替える文)。
- 速さの目安: 読みの字数(空白・かっこ・句読点を除く)が 1 秒 6.5 字まで。声を作ったら行ごとに実の長さを測り、窓に収まらなければ窓を広げずに文を削る。
- 文字の札の区切りでは、札の文字を真ん中より少し上(470px を中心)に置く。真ん中だと 2 行の語りと重なった(実測)。
- 案内役をキャラにする時は、キャラの人格の文(一人称・口調)を `rules` の 1 行目に写す。11/6 のノリー: 一人称「ノリ」、少しカタコトで語尾がときどきカタカナ(〜マス・〜デス・〜まシタ)。カタカナの語尾は 1 行に 1 か所まで(字幕が読みにくくなる)。テーマの文はカタコトにしない。安全の層が優先(恋人役・独り占め・「ご主人さま」のような依存に寄る言い方をしない)。声に渡す読みのカタカナはそのままでよい(声はふつうに読む)。
- 案内役を替えたら、全部の行と、絵コンテの状態・代わり・仮の素材の文字(`placeholders --force`)を一緒に替える。前のキャラの名前が残りやすい。

## 落とし穴(実測)
- Windows の Python の `write_text` は改行を CRLF にする。drawtext の `textfile` に入ると、行の終わりに豆腐(□)が出る。`write_bytes(s.encode("utf-8"))` で書く。
- ffmpeg 8 の drawtext は、LF の改行でも行の終わりに豆腐が出た。**1 行ずつ別の drawtext にし、y をずらす**と消えた。空の文の drawtext は作らない。
- 字幕は `expansion=none` にする(`%` や `{}` がそのまま出る)。
- 字体のパスの `C:` の `:` はフィルタの区切りとぶつかる。字体を作業フォルダに写し、相対の名前で渡すと逃がしが要らない。
- 折り返しは字数で切ると「7 つ / の段で。」のように切れる。後ろ半分にある 、。」 の後で切り、行の頭に 。、」 を置かない(その行は 1 字長くてよい)。語りは 26 字(64px で 1664px)で折る。
- 静止画は `-loop 1 -framerate 30 -t 秒` で読む。`fit_h`(縮める高さ)と `pad_y`(上からの位置)で絵を上に寄せ、下の語りが足や体にかからないようにする。
- **早回しの途中で地の色が変わる**(白い紙 → 灰色のキャンバス)と、縮めた周りの余白(`bg`)の色と合わず、枠が見える。角の 8x8 画素を 1 コマずつ読んで変わる時刻を測り(`crop=8:8:4:1060,scale=1:1` → rgb24 の生の値)、区切りを 2 つに分けて、それぞれの `bg` を地の色にする(11/6: 見せ場 6 秒は 3.37 秒、早回し 20 秒は 14.43 秒で変わった。灰色は 0xcbcecb)。
- **描きかけの乱れたコマ**(線が顔を横切る・キャンバスのずれ)は、一覧の絵(1 秒 6 コマ)で見つけ、範囲の暗い画素の数を 1 コマずつ数えて場所を決め、`in` と `dur` で避ける。避けた分の秒は、同じカットの仮の区切り(後で撮る物)に回して、カットの長さを変えない。
- 区切りの秒は 1/30 秒の倍数にする。ffmpeg の `-t 0.467` は「時刻が 0.467 未満のコマ」= 15 コマになり、1 コマずつずれていく。
- 仮の素材は倍率をかけずに 1 倍で流す。30 倍の区切りの仮を倍率どおりに作ると、1 本 750 秒・約 1GB になった。仮の素材の文字は真ん中に置き、上の札の場所を空ける。
- Bash の heredoc は `\\` を壊す。引用符の多い Python を heredoc で渡すと「対になる ' が無い」で丸ごと止まった。台本はファイルを書く道具で書いてから流す。
- 録画ソフトが書いている途中の mp4 は moov が無く、ffprobe が開けない。大きさが 3 分変わらず、ffprobe が開けた後で写す。録画ソフトには触らない。
- 同じ録画を 2 人が別々に写して、1.45GB の写しが 2 つになった。写す前に、行き先に同じ大きさのファイルが無いかを見る。
- エージェントの背景のシェルは、エージェントの返事が終わると止まる。長く待つ見張りは、窓を出さずに切り離して起動する(PID を記録し、止めるのはその PID だけ)。PowerShell の `Start-Process -ArgumentList` に配列で渡すと、空白を含む値(`"2026-11-07 07:30"`)が引用符なしでつながれ、pythonw が何も言わずに落ちた。引数は 1 本の文字列にして、空白を含む値を `"…"` で包む。起動の後に PID が生きていて記録に「start」が出たかを見る。
- 2 つの書き出しが同時に動くと、作業フォルダの区切りのファイルを上書きし合う。書き出しは鍵のファイル(work/build.lock、30 分より古ければ捨てる)で 1 本ずつにする。
- 見張り(watch_assets.py)は sync を 2 分ごとに流し、新しく届いた物があって前の書き出しから 20 分たっていれば、札を取って書き出し直す。止める時は work/watch_assets.stop を作る(python を名前で止めない)。
- 実測: 31 区切り・170 秒・語り 29 行の仮編集は CPU で約 34〜47 秒。仮の素材 20 本の作り直しは約 11 秒。

## 本人の撮影の手順書(スマホ・ゴーグル)
- 本人に頼むのは、本人にしかできない操作(スマホ・ゴーグル・鍵)だけ。サーバーの起動・撮影用の子の用意・描き直しの命令は担当がする。手順書の頭に「用意(担当)」を分けて書く。
- ボタンの名前は、画面の文(index.html と画面の JS の文字)から写す。前の時刻に S7 が同じ手順を画面なしの Chrome(幅 390)で通して確かめる。
- 撮る前に: iPhone は集中モード(通知を映さない)・画面収録のマイクを切る(部屋の声を入れない。アプリの音は入る)。PC の Chrome は F11 の全画面(タブ・ブックマークを映さない)。
- Safari のアドレスの帯にはホスト名・アドレスが出る。撮る人に気にさせず、編集で切る(台帳のメモに書いておく)。
- 番号や合言葉のように時間で切れる物は、出す側と入れる側を同じ人が続けてする(10 分で切れる・1 回だけ)。
- 待ち受けの番号がほかの物とぶつかっていないかを先に見る(11/6: 確かめる画面の既定の 8790 は別の物が使っていた → 8792)。`netstat -ano` の LISTENING で見る。
- ゴーグル(Quest)は https が要る。開発の入口が tailnet の中だけなら、ゴーグルがその網に入っているかを先に確かめる。入っていなければ公開の URL を使うか、撮らない(任意のカットにしておく)。

## お絵かきの画面録画から「描く様子の早回し」を作る
- 頼みの文に書かれた時刻をうのみにしない。先に 25〜30 秒ごとの一覧の絵を見る。11/6 は「主役は 1940 秒から」と書かれていたが、実際は 0〜1700 秒で、ほかのキャラの横で描かれていた。
- キーフレームだけを読む(`-skip_frame nokey`)。この録画は 250 コマごと(4.17 秒ごと)で、28 分ぶん 408 枚を約 20 秒で取り出せた。1 枚を 1 コマにすると、30fps で約 125 倍の早回しになる。
- アプリの画面(メニュー・タブ・ページの見本・ファイル名)は映さない。キャンバスの白い所だけを残し、ほかは白で塗る。画面のいちばん下の 1 行に暗い線があり、2 つのキャラの間をつないでしまったので、端の行は数えない。
- ほかのキャラは、列ごとの線の量でかたまりに分け、目印の色(黄色)を含むかたまりとその左を白で塗る。
- 拡大・縮小で絵が揺れないように、**動かない物差し**から切り抜きの枠を決める。描き終わったほかのキャラの黄色い部分の箱は、どの倍率でも縦横の比が 0.284〜0.289、主役の中心と高さとの比も一定だった。描きかけの線から枠を決めると、最初の 1 本が画面いっぱいに拡大されて見づらい。物差しの形が崩れたコマ(画面の外にはみ出した)と、2 倍より大きく拡大するコマは捨てる。
- 一覧の絵で、ほかのキャラとアプリの画面が 1 コマも映っていないことを確かめてから台帳に「本物の候補」と書く。ブラシの大きさの表示(灰色の帯)が数コマに出ることがある(仮編集では残した)。
- 三面図の早回しは、見せる所によって切り抜く: 冒頭は名前まで、三面の説明では題字の下を `crop` で落として 3 体だけを大きく見せる(11/6: 1920x650 を上から 70px)。

## 人の映る素材
- 協力者の映像・絵は、許可を記録してから使う。名前・顔・声・ほかの人・ほかの人の画面を映さない。切り出しは音を消し、要れば `crop` と白か黒の四角で隠す。

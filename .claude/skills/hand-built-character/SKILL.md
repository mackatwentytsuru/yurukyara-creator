# 手組みでキャラを作る(絵 → 部品 → 骨 → 目と口 → 動き)

キャラの名前や絵に依存しない手順。AI の 3D 生成は使わない。色むらが出ず、許諾の問題がなく、VRAM も要らない。1 周は十数秒。
道具は `creator/pipeline/`、builder の型は `creator/builders/_template_px.py`。**Claude が絵を見て部品を決め、撮って比べて数字を直す繰り返し**が中心。

## 小さく刻む(段ごとに撮って、比べて、別の AI に判定させる)

1. **頭**(いちばん目立つ所)→ 2. **体と小物** → 3. **骨と動き** → 4. **目と口**。段ごとに 1 周まわし、比べの一覧を見て直してから次へ。作った担当に自分の出来を判定させない(DeepSeek か GLM 5.3-flash。最後の確認だけ Opus)。

## 手順

1. **絵を開いて見る**(Read)。部品の一覧を決める: 形(球・箱・輪・布・板)、色、位置、大きさ、前後の重なり。
2. **画素 → メートル**。絵の高さ(足から頭のてっぺん)の画素数を実寸に割りあて、`S = 画素数 ÷ 実寸`。`X(px)=(px-CX)/S`、`Z(py)=(FY-py)/S`、`R(px)=px/S`。数字は**画素のまま**辞書 D に書く(重ねで直しやすい)。色は絵の画素から標本をとる(`numpy` で連結成分の外接箱を出すと、胴・ブーツ・手などの位置と大きさが一度に取れる)。
3. **builder を書く**(`_template_px.py` をコピー)。`m00_prims`: `superquadric`(丸みのある箱・楕円体。taper でくびれ・すそ広がり)、`ring`(輪。`xy` で楕円、`rot_deg` で向き)、`cloth`(布の板)、`material`(色は sRGB の 0〜255)、`gradient`(頂点の色の濃淡)。
4. **撮る**: `m02_shot.py <.blend> <出力> --views front,right --size 1024 --center <x,z> --scale <m>`。元の絵と同じ画素の範囲を撮れば、そのまま重なる(例: 絵が 1024px・S=1158 なら `--scale 0.884`、`--center` は絵の中心の画素をメートルに直した値)。
5. **重ねて比べる**: `s04_overlay.py 元の絵 撮った絵 出力.png "見出し" --crop x0,y0,x1,y1`。元・作った物・赤い輪郭を重ねた 3 枚の一覧。ずれを数字(画素)で読んで、辞書 D を直す。全体の形の近さは `s03_compare.py`(輪郭の重なり IoU)。
6. **判定**: 比べの一覧を DeepSeek(`oc_web.ps1`)か GLM 5.3-flash に通す。位置・色・横向き・「いちばんずれた所」を答えさせる。
7. **骨の入れ方 — 部品ごと(剛体)**: builder で、部品ごとに**骨の名前の頂点グループ**(重み 1)をつける。`b07_rig_groups.py <spec.json> <.blend> <出力>`。spec は骨(`at` はメートル、`parent`)と `roles`(動きが使う役割 → 骨の名前)と `motion.only`(作る動き)。胴にそって曲がる体(つなぎ目を混ぜたい)なら `b03_rig.py`(箱で区切った重み)を使う。
8. **目と口**: シェイプキーを持つ別の物(`Eyes`、`Mouth`)にまとめる。まばたき(目玉を平らにつぶす `eye_blink`)、口(`mouth_open`・`mouth_wide`・`mouth_o`)。**作った直後のシェイプキーの値は 1(効いた状態)なので、必ず `value = 0` に戻す。** 黒目と光は、目の骨に付ける(視線で動く)。紙や LED の顔なら、顔の面+表(`f01_face_atlas.py`、`b03_rig.py`)でもよい。
9. **動き**: `b04_motions.py`(式で作る。`head` と `wing_*` の役割があれば頭と羽も動く)。`b06_posecheck.py` + `s02_posesheet.py` で、動きの途中の姿勢を大きな一覧にして、崩れを見る。
10. **ブラウザで確かめる**: `creator/viewer/serve.py`(`--mount=/名前=フォルダ` でリポジトリの外のキャラも見られる)。`character.json` の rig: `look.eyes`(目の骨)、`mouth.kind="morph"`、`blink.morph`、`morphs`(表情 → シェイプキー)。

## ゆるキャラらしさを出す工夫(試して効いたもの)

- **茶色などの輪郭線 = 裏返しの殻**(`P.outline`)。物を法線の向きに少しふくらませ、面を裏返した複製を作る。**輪郭の材質は「背面を描かない」にする**(`use_backface_culling = True`)。しないと、殻が元の物をおおって、全体が輪郭の色になる。目・口・ほおなど、線のいらない小さな部品は除く。頂点グループは複製が引きつぐので、骨にもそのままついてくる。
- **つや消しの平らな色**: 材質の `rough` を 0.75〜0.85、`spec`(反射の強さ)を 0.1〜0.3 にする。元の絵が平らな色なら、光沢を落とすだけで「絵に近い」と読まれる。
- **太い 1 枚の帯**(ゴーグルの縁など): 細い輪(トーラス)を重ねず、断面が角丸の長方形の輪(`P.ring(..., sq=0.5, squash=幅に対する奥行きの比)`)にする。横から見ても、ひだのある筒に見えない。
- **開口の内側に収まる顔**: 球のヘルメットから、顔のところを楕円体でブーリアン(差)で切り抜き、肌の楕円体を開口の内側に置く。縁がオレンジの枠になる。
- **球の表面に沿う帯(くさび形)**: 球の式で、格子の各点を表面から数 px 外に置いて作り、厚みはソリディファイで足す。

## 部品の多いキャラを、積み木に見せない作り方(試して効いたもの)

- **胴・脚・足は、元の絵の輪郭から「高さごとの幅」を読み、その断面をつないで 1 つの形にする**(`P.loft`)。楕円体を手で合わせるより絵に近づき、胴・脚・ブーツのすき間が消える。読み方: 元の絵の主な色(例: 服のオレンジ)を色の近さで取り、高さごとに最大の連続区間の左右の端を測る(numpy で数行)。
- **腕は管(`P.tube`)**: 中心線の点と半径を渡すと、肩から手首まで曲がった袖になる。手は別の球。細い棒に見えるときは、半径を 26px 以上にして、肩の端に少し太さを足す。
- **ベルトのコマ**: 白い帯 1 本ではなく、小さな角丸の板を胴の前の弧(半径 = 胴の半幅)に並べる。中央に丸いバックル。
- **葉の形の羽**: 超楕円体を細長くして、先へ向けて細くする(`taper`)。付け根→先の色の変化は `P.gradient_axis`(頂点の色。手続きの節点は書き出せない)。
- **口の中**: 白い楕円だけだと「歯だけ」に見える → 口の下の縁に寄せたピンクの平たい楕円体(舌)を、同じ `Mouth` の物に入れる。シェイプキーで口が開くと、一緒に動いて口の中に見える。
- 小さな部品は、輪郭線(`outline`)を付けると太って見える → 目・口・印・コマは除く。

## 布・ぬいぐるみの質感(全国調査で約 8 割が布・ぬいぐるみ)

質感の案を、同じ形・同じ光で並べて比べる場: `python`ではなく Blender で `creator/builders/_texture_lab.py -- <出力フォルダ> [R,G,B]`(A 平らな色 / B シーン / C 頂点の色+シーン / D 毛足の画像+法線 / E トゥーン)。別の AI(DeepSeek)に「ぬいぐるみの質感が出ているか」を聞いた結果: **D だけが「はい」**、A・B・C・E は「いいえ」。

- **毛足の画像(案 D、ぬいぐるみに必要)**: `P.fuzz_material(名前, rgb, 画像の出力フォルダ, grain=0.16, normal_strength=1.6)` で、毛の線の重なりの画像(色+法線、継ぎ目なし。numpy だけ。AI なし)と、縁の毛羽(シーン)を持つ材質を作る。その材質を付けた物に `P.auto_uv(ob, tile=2.2)` で UV を付ける(立方体投影。tile が小さいほど毛が大きく見える)。GLB に画像 2 枚が入る(1 材質で約 1.2MB。大きいときは `size` を 256 に)。three.js でも読める。
- **輪郭の毛羽(案 F、毛足の画像に足す)**: `P.fuzz_shell(ob, rgb, 画像の出力フォルダ, thick=0.02, density=0.5, layers=3)` が、物を少しふくらませた殻を重ね、毛の点の画像(透明さで抜く)を貼って、輪郭をふんわり毛羽立たせる(殻の物の一覧を返す)。別の AI が、F を「ぬいぐるみに一番見える」と判定(D は「はい、ただし布地寄りで縁が切り口のよう」)。書き出しは `alphaMode: MASK`(透明さを GREATER_THAN 0.5 で切る節点を、`fuzz_shell` が付ける)。頭など目立つ丸い部品にだけ付け、殻は 2〜3 枚、三角形が倍になるので予算に注意(`pk03`)。
- **シーン(案 B)だけでは、毛足は出ない。** 縁の明るさは出るが、桃の試験で全段が「毛足なし(つるつる)」と判定された。シーンは、毛足の画像の**足し**として使う。
- 頂点の色の濃淡(案 C)は、色のつながり(濃い縁・明るい中心)用。毛足にはならない。
- トゥーン(案 E)は、平らな色+輪郭線のキャラ向け(質感は出さない)。
- 毛足の画像は、1 材質につき 1 つの色。色の違う部分は、別の材質(別の `fuzz_material`)にする。色の濃淡が要る部品には、頂点の色(`Col`)と画像は同時には使えない(書き出しが片方になる)。

### ブラウザ(three.js)で見る色と毛足(11-02 夕方、測って分かったこと)
質感と色の判定は、**Blender の絵ではなく、ブラウザ(`creator/viewer`、web/ と同じ光)で撮った絵**で行う(`node creator/skilltest/shot_browser.mjs <ポート> <character.json の URL> <出力フォルダ>`)。見る人が見るのはブラウザだから。
- **ブラウザの色は、そのままだと元の絵の約 68% の明るさに沈む**(ひよこの体: 元 RGB 231,195,108 に対し 156,131,65)。three.js の光は、強さ 1 で白い面が約 0.32 にしかならず、Blender の太陽光より暗い。直し方は、**実行側で色の絵を発光にも貼って持ち上げる**(`rigRuntime.js` の `applyLift`、character.json の `lift`、既定 0.55)。これで 225,191,97 と、元の 97% に戻る。builder の色を明るく塗り直す必要はない(Blender で見る絵が明るすぎになる)。頬などの小さい面は、元の絵の色をそのまま使う。
- **毛足の画像は、向きがなめらかに変わる細い毛を、たくさん重ねる**(`fuzz_images`)。試した順: 1 画素の粒 → 砂壁に見える / 粒をぼかす → 革やオレンジの皮に見える / 毛の本数が少ない(1 辺 × 5)→ 引っかき傷に見える / 毛を 1 辺 × 24 本にして凹凸を弱める → 元の絵のフェルトに近づいた。法線の強さには 0.4 を掛ける(`FUZZ_NORMAL_GAIN`)。アップではまだ白い細い線に見えると言われる。
- **頬が茶色く沈む原因**: 色の絵を持たない材質に持ち上げが効いていなかった(`rigRuntime.js` を直した)。頬は `W.soft_patch` で作る。
- 7 体を直した結果(11-02、ブラウザの絵、DeepSeek と GLM): 色が両方はい 6/7(直す前 0/7)、毛足が両方はい 4/7(直す前 2/7)、3 つとも両方はい 4/7(直す前 0/7)。毛足はまだ「粗い」「粒が強い」と言われる。
- **毛の殻をブラウザ側で重ねる(`creator/viewer/furShell.js`、試験中で既定は切ってある)**: character.json に `"fur": {"layers": 8}`。同じ形と骨を使い回すので GLB は増えず、骨とシェイプキーに付いて動く。顔の部品の周りは毛を短くする。**色の絵の筋が残ると傷に見え(flat 0.7)、消すだけだと樹脂に見える(flat 0.95)**。筋を消して、毛 1 本ずつの明暗(pile)とふわっとしたむら(cloud)をシェーダーで足すと、布に近づく。pile を弱めると「平ら」に戻る。根元を暗くした分は gain で明るさを戻す。**毛の太さはキャラの高さに対する割合で決める(`hairWidth`、0.4% が基準)**。UV の繰り返しで決めていた間は、毛が画素より細くなって消え、どう直しても「つるつる」と判定された。太さ 0.7% は粗すぎる。毛は短く密に(長さ 1.5%)、色の違う部品の境目では毛を短くする(青とクリームの毛が混ざって汚れて見えた)。判定はまだ安定して通らない(砂粒のように見えると言われる)。材質は部品どうしで共有されるので、部品ごとに暗くすると何度も掛かる。頬の当て布は、四角い網の全部で毛を短くすると四角い跡が出るので、丸の中だけを使う。
- 効かなかった: `alphaToCoverage` と抜きの線を下げる(面に白い虫のような線が出た)。
- **判定の決まり**(`sh creator/skilltest/judge_browser.sh <絵のフォルダ名> <試験…>`): 同じ絵を各 AI に 3 回見せ、2 回以上「はい」でその AI の「はい」。2 つの AI の両方で合格。同じ絵でも DeepSeek は 4 体中 1 体で毛足の答えが変わったので、1 回では決めない。答えは「はい」「いいえ」の 1 語だけで、「ほぼはい」は数えず問い直す。判定の絵に文字や数字を入れない。**合格しても、本人の目が優先**。本人が選んだ見た目を既定にしてから、スキルだけの試験を回す。外の素材を使うときは、ライセンスを `docs/部品の一覧.md` に足す。
- 判定役 AI は、毛足が強いと「ざらつき寄り(砂壁)」と言う。色が合うと、毛足の判定も「はい」に寄る。

### 体に沿う部品・頬・くぼみの影(`creator/pipeline/m01_wrap.py`。`import m01_wrap as W`)
- **帯(たすき・ベルト・襟)**: `W.wrap_band(名前, [体の物], [(角度, 高さ), …], 幅, thick=…, mat=…, closed=False)`。角度は正面が 0、体の左(+X)が 90。光線で体の面に載せるので、細い・平ら・浮く、を防げる。UV は帯の長さ方向につながるので、文字の画像を貼れる。**帯は `superquadric` や `cloth` で近似しない。** 一周の帯は `closed=True` で、最後の点を重ねて書かない。体に当たらない道は例外で止まる(勝手な位置に置かない)。
- **頬の丸**: `W.soft_patch(名前, [頭], 角度, 高さ, 半幅, 半高, rgb, 画像の出力フォルダ, hardness=0.35, opacity=1.0, clearance=0.012)`。**硬い楕円の部品で頬を作らない**(ブラウザで茶色い丸になる)。毛羽の殻があるときは、clearance を殻の厚みの半分より大きくする。大きくしすぎると、斜めから見て輪郭の外へはみ出す(0.024 で出た。0.012 で消えた)。
- **腕・脚・耳など、体から生える部品**: `W.limb(名前, [体の物], 付け根の点, 先の点, 付け根の半径, 先の半径, mat=…, flare=1.3)`。**`superquadric` を横に置かない**(肩にくさび形の抜けが出た)。付け根の点は**体の中**に置く。線が体を出る所を測り、半径の 8 割だけ内側を付け根にして、面のあたりを太らせる。体に当たらない置き方は例外で止まる。骨の位置(`rig.json` の `at`)には `W.pivot_of(ob)` を使う。付け根の半径と先の半径はほぼ同じにする(差が大きいと、くさび形に見える)。
- **顔の部品と毛羽の殻**: 目・口・鼻の前面は、殻の厚み + 0.012 m 以上、頭の面より前に出す。殻より奥だと、毛羽の点が刺さって黒い点に見える。顔の範囲だけ殻を抜くと、四角い跡が残る。頭が球でないときは、部品の位置を式で出さず、頭へ光線を当てて面を取る。
- **帯と体**: `wrap_band` の体の一覧には、帯が当たる物を全部入れる(腕を抜くと、腕と交差する)。帯の上端が体の外へ出ると例外で止まるので、胴の断面を肩の上まで作る。
- **`W.limb` が合わないとき**: 体のすぐ外に置く短い腕は短い棒になる。長い布の耳は、平たい `P.tube`(`ry_scale` 0.5)と内側の当て布に分けると形が合う。どちらも付け根は体の中へ入れ、`m03_contact` を通す。
- **印 `surface_only`**: 毛羽の殻と `soft_patch` に自動で付く。検査で「体」にも「部品」にも数えない。**検査を通すために、目や口に付けない**(浮きを隠すことになる)。目が浮きで落ちるときは、縁を頭の面へ沈める。
- **毛足の繰り返し**: `auto_uv(ob, tile=4.0)` を基準にする。2.2 は毛が粗く、継ぎ目が出た(試験で確認)。殻の厚みの分だけ、芯の半幅を細くする(厚み 0.010 m で 10 px ほど。IoU 0.942 → 0.958)。
- **フリル**: `W.ruffle(名前, 3D の道, 幅, folds=…, gather=…, up=…, outward=…, mat=…)`。付け根の列は動かない。下へ垂れるときは `outward=(0,0,-1)`。
- **くぼみの影**: builder の最後に `W.bake_ao(全部の物, occluders=毛羽の殻と当て布を除いた物, samples=32, dist=0.2, strength=0.7)`。three.js には接地の影が無いので、首の下・腕の付け根の影はここで作る。頂点の色 Col に掛け、`b07_rig_groups` が GLB に入れる(色の絵と一緒に掛かる)。`dist=0.3, strength=0.9` は胴が暗くなりすぎた。
- **検査を通すために形を崩さない。** 抜けを消すために胴を角張らせると、輪郭の検査は通っても元の絵から離れる(試験で実際に起きた)。形は元の絵に合わせる。残る抜けは、部品の付け根・太さで直すか、場所と理由を報告に書く。最後に決めるのは検査ではなく、ブラウザの絵を見た別の AI。
- **検査をまとめて通す**: `sh creator/pipeline/check_all.sh <build.blend> <pack> <元の絵> <出力フォルダ> [帯の名前,…]`。character.json・GLB の予算・埋まりと浮き・**抜け**・ブラウザの撮影・視線の積み上がりを 1 回で測り、落ちると番号 1 で終わる。builder を直すたびに通す。**人に見つけてもらう前に、ここで止める。**
- **抜けの検査**: `s05_gaps.py <元の絵> <透明背景の正面>`。元の絵では体なのに背景が見える場所を、太い所と、周りを体に囲まれた所に分けて出す。輪郭の重なり(IoU)が 93% でも、肩の抜けは見えない。元の絵とポーズが違えば抜けと出るので、残すなら理由を報告に書く。
- **埋まりと浮きの検査**: `blender -b <build.blend> -P creator/pipeline/m03_contact.py -- --hug 帯の名前,… --near 0.02 --json 出力.json`。見た目を AI に見せる前に通す。帯は「面の近く 8 割以上、0.4 cm より深く埋まらない」、耳・腕は「埋まる点が 2〜60%」。**この合格は見た目の合格ではない**(出力の `visual_pass` は常に false)。帯と帯が交差しても NG になるので、NG の理由と相手を確かめる。

## 合否の数字を先に決める(輪郭の重なり以外)

`s03_compare.py` は、輪郭の重なり(IoU)に加えて、**中心のずれ(正規化した 500px の絵で、何 px)・外接箱の幅の差(%)・高さの差(%)** を出す。目安: IoU 0.90 以上、中心のずれ 6px 以内、幅・高さの差 3% 以内。外れた数字で、直す所を決める(中心のずれ → 体の置き場所、幅の差 → 部品の半径、高さの差 → 全体の高さの割り当て)。顔の部品のずれは `s04_overlay.py` の重ねで、画素で読む。

## 試験で見つかった知識(スキルだけで作らせた作業役が、足りないと書いた物)

- 1 つのメッシュで**頂点の色を使う材質は 1 つだけ**にする。Blender 5.2 の glTF 書き出しは、2 つ目の材質から `COLOR_0` を白で書き、色が飛ぶ。色の濃淡が要る部品が複数あるときは、1 つの材質に寄せるか、濃淡を材質の色そのものと `sheen` で出す。
- 頭の大きいキャラ(頭が全高の 2/3)は、手をふるで腕が頭にめりこむ。`motion.arm_amp` を 0.45 前後に下げ、肩の骨を腕の付け根の少し下に置く。
- `P.gradient`(頭頂から縁への濃淡)は**正面基準**。後ろ側が白っぽくなるので、全周で同じ色にしたいときは、上下の向きで色を変えるか、`sheen` で出す。
- `b06_posecheck.py` などの道具には**絶対パス**を渡す(相対パスだと絵が見つからない)。
- 確かめ用サーバー(`serve.py`)は、止めても python が残る。PID を指定して止める(名前で止めない)。
- 顔の部品(目・光・口・ほお・筋)は、頭の表面に光線を当てて貼る薄い板で組むと、頭が球でなくても表面に沿う。細い筋を管で作ると半分埋まって点線になる → 色をなじませた帯の板にする。まばたきで光が白い点として残るときは、閉じる形で黒目の奥へ沈める。

## 試験の下見で見つかった知識(別のキャラ 1 体、スキルだけで作らせた結果)

- **輪郭の重なりが低いときは、まず背景を疑う。** 撮った絵の背景は灰色で、s03 は背景との色の差で輪郭を取るので、白や明るい灰色の部品が体の外と数えられ、IoU が下がる(0.855 → 部品を暗くしただけで 0.981 になった)。`m02_shot.py --transparent` で背景を透明に撮ると、`s03_compare.py` が透明さで輪郭を取り、この誤りが消える。
- 撮影の光で、色は元の絵より 1.1〜1.2 倍明るく出る。同じ場所の中央値で比べ、元の色よりやや暗く置く。
- 腕が斜めに垂れたキャラは、`b04_motions.py` の手をふる・ジャンプで腕が頭の後ろに隠れる。`motion.arm_amp` を 0.5 前後にする。
- **球の面の網目(マイクの頭など)**: 経度/Δθ ± 緯度/Δφ = 整数 の線を、面に沿う平たい管で作る。てっぺんはふたでまとめる。網目の交点を自動で拾うとばらつくので、元の絵に交点を打って目で確かめ、手で決めた数字を使う。
- 横の絵が無いときの奥行きは、頭を球とみなして、正面の幅の 0.9〜1.0 倍にする。実寸の高さは、足元から頭のてっぺんを 1.0m(キャラの設定が無ければ)として決める。
- 腕などの最適化の総当たりは、絵を 3 分の 1 に縮め、粗く探してから細かく詰めると 4 秒で済む(縮めずに探すと 10 分で終わらない)。
- 帯状の部品(口の線など)の端を丸めるときは、帯の法線を使う(向きを決め打ちすると、端が逆向きに崩れる)。胴を断面でつなぐとき折れ目や点線が出たら、断面を Catmull-Rom で補間して細かくする。細い筋の板が、丸い頭の先で光線を外して止まるときは、近い表面へ寄せる。
- **口などのシェイプキーで顔の部品を動かすときは、頂点の奥行き(y)も、動かした先の頭の表面に合わせ直す。** 高さ(z)だけ動かすと、部品が頭にめり込んで消える。
- 頂点の色を前の絵の x・z から取ると、側面と背面が灰色や白に化ける。x を頭幅の 72% に挟むと直る。撮影の光が上から当たり、下向きの面が暗く出るときは、頂点の色を `max(0, -nz)`(下向きの度合い)で逆に補正すると、平らな色に近づく。
- 面の板(中央のファン+輪)は、ファンと輪の向きを逆にする(そろえると、中心に小さな丸い影が出る)。
- 判定用の AI は、「腕・足・目がずれている」のように、実測と食い違う指摘を返すことがある。**数字(IoU・中心のずれ)と大きく撮った確かめで、指摘が本当かを確かめてから直す。**

## 人の顔・毛束の多い髪(アニメ調の頭。難所の試験で見つかった知識)

- **全部の部品に材質を渡す。** 材質なしの部品を `P.join` で合わせると、空の材質枠ができて白く写る(羽根の白い筋の原因)。
- 外へ広がる髪は、中の詰め物を頭の大きさに抑える(大きいと毛束を隠す)。毛束は、軸のまわりの「半径と高さ」の曲線にそって作り、幅の向きを周の向きにする。`P.tube` は断面の向きを決められないので、平たい毛束には使えない。
- 耳を出すには、耳の高さの毛束の根元と毛先の両方を耳の後ろに置く。**何が隠しているか分からないときは、シーンの `ray_cast` で、当たった塊の外接箱を出すとすぐ分かる。**
- 4 方向の縮尺合わせは、顔の大きさ(目〜あご)の画素数で各絵を合わせる。後ろの絵に顔が無いときは、髪の幅と下の端で合わせる。
- 到達点(Opus 5.5 xhigh、スキルだけ、1 回、$6.55、約 30 分): 4 方向の輪郭の重なり 0.73〜0.82、別の AI の判定は「正面は同じキャラに見える、横は別人寄り、使える水準の約 50%」。弱い所: 髪が板・花びら状で丸い毛束の房にならない、帽子が寸胴で高い、リボンの蝶結びが無い、目が小さい。この種類(人の顔・毛束)は、ぬいぐるみより明らかに難しい。

## 落とし穴(直し方つき)

- 骨に毎コマ回転を重ねるときは、先に「動きだけの値」へ戻す。three.js のミキサーは値が前と同じだと骨に書き直さないので、重ねたままだと回り続ける(視線で体が 173 度まで回った)。`creator/skilltest/test_look_drift.mjs` が数百コマ回して測る。

- パスはドライブ名から始まる絶対パス(`X:/...`)で渡す。相対パスや Git Bash の `/x/...` を Blender・Windows の python・node へ渡すと、絵が別の場所に書かれるか、できない(`check_all.sh` は自分でそろえる)。
- `m02_shot.py` を元の絵と同じ画素で撮る式: `--scale` = 絵の幅(px)÷ S、`--center` = ((中心 px − CX) ÷ S, (FY − 中心 py) ÷ S)。
- `s03_compare` と `s05_gaps` は、外接箱で大きさをそろえて比べる。手の先が少し大きいだけで、ほかの場所に抜けが出る。先に外接箱の幅を元の絵に合わせる。
- `s02_posesheet.py` は `pose_<名前>_<数>.png` の形だけを読む。

- まばたきで、平らにつぶした目玉の奥にヘルメットや部品が透けて「壊れたゴーグル」に見える → ふだんは点(見えない)で、まばたきで広がる肌色の円盤(まぶた)を、同じ名前のシェイプキーで足す。シェイプキーを作ったあとに基準の形を変えるときは、`mesh.vertices` ではなく `shape_keys.key_blocks['Basis'].data` を直す。
- 顔の面(体の表面に貼る面)の角が、体の丸い縁に当たると、角に四角い粗いにじみが出る(貼った面の角が丸い縁の外や急な坂に乗る) → 光線が当たらない点と、面の向きが正面から 55° 以上それた点を含む四角は作らない。面を平らな部分に収まる大きさにし、足りない分は表(顔の絵)の中身を大きくする。
- 光る点の目の大きさは、元の絵の画素 ÷ S で出したメートルから、点の数に直す(点の間隔 = 面の幅 ÷ 点の数)。小さく見えるときは、輪の半径・点の半径・光のにじみを足す。
- 布の羽根を、厚い板 2 枚重ねの「ひだ」にしたら、下の縁がぎざぎざに崩れた(試して止めた) → 1 枚で bend と flare を調整する。2 枚重ねるなら、厚みより位置のずれで足す。
- 輪(トーラス)を球の表面と同じ深さに置くと、半分埋まって「C の字」に見える → 球の最前面より前に置く。
- Blender の glTF 書き出しは、手続きの節点(Layer Weight など)を書けず、白く飛ぶ → 頂点の色(`gradient`)か絵だけ。
- OBJ を Blender に読むと物が 180° 回って入る → 回転を 0 に戻す(`b03_rig.py` のコメント)。builder が作る .blend には起きない。
- 手をふる・おじぎの確かめは、振りの位相が逆の 2 コマを並べる。動きの一覧は 1 コマ 560px 以上。
- Git Bash は、`--mount=/名前=...` のような引数の `/…` をパスに直してしまう → PowerShell の `Start-Process` で起動する。
- ブラウザが古い JS を使う → キャッシュなしのサーバー(`serve.py`)。

## 合格の目安

正面・横の重ねで、主な部品(目・口・手足・小物)の位置と大きさが元の絵とほぼ重なる。別の AI の判定で「位置・色・形はほぼ合う」。ブラウザで、表情・口・まばたき・動き 5 つ以上が動く。

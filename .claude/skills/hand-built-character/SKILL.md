# 手組みでキャラを作る(絵 → 部品 → 骨 → 目と口 → 動き)

この SKILL.md は入口だけ(いつ使うか・流れ・決まり・確かめ・外せない落とし穴)。くわしい中身(部品の作り方・質感・試験で見つかった知識・主役ノリーの作り直しの記録)は `reference/` に元の文のまま移してある。必要な節だけ開く。

## 使う時
- 絵から 3D のキャラを手で組む・作り直す・直す時。人型でない物(箱・提灯・パネル・動物)にも使える。
- AI の 3D 生成は使わない(色むらが出ず、許諾の問題がなく、VRAM も要らない)。1 周は十数秒。
- 道具は `creator/pipeline/`、builder の型は `creator/builders/_template_px.py`。中心は「Claude が絵を見て部品を決め、撮って比べて数字を直す」繰り返し。

## 流れ(4 段に刻み、段ごとに 1 周)
1. **頭**(いちばん目立つ所)→ 2. **体と小物** → 3. **骨と動き** → 4. **目と口**。段ごとに撮って、比べの一覧を見て直してから次へ。
- 絵を開いて部品の一覧(形・色・位置・大きさ・前後)→ 画素 → メートル(`S = 画素数 ÷ 実寸`。数字は画素のまま辞書 D に書く)→ builder を書く(`_template_px.py`)→ 撮る(`m02_shot.py`。元の絵と同じ画素の範囲で)→ 重ねて比べる(`s04_overlay.py`・`s03_compare.py`)→ 判定(`j01_judge.py`)→ 骨(`b07_rig_groups.py`、胴に沿って曲げたい体は `b03_rig.py`)→ 目と口(シェイプキー)→ 動き(`b04_motions.py`・`b06_posecheck.py`)→ ブラウザで確かめる(`creator/viewer/serve.py`)。
- 手順 1〜10 の全文は `reference/steps-and-style.md`。

## 外せない決まり
1. **作った担当に自分の出来を判定させない。** 判定役は別の文脈の Claude(Haiku と Sonnet)。左右を入れ替えて 2 回とも勝てば勝ち。
2. **合否の数字を先に決める**: 輪郭の重なり IoU 0.90 以上・中心のずれ 6px 以内・幅と高さの差 3% 以内。外れた数字が直す所を決める。
3. **character.json は最上位に置く**(`rig` の入れ子は使わない)。pack を作ったら必ず `pk02_check_character.py` を通して OK を出す。
4. **目と口のシェイプキーは、作った直後は値が 1。必ず `value = 0` に戻す。** 目と口は別の物(`Eyes`・`Mouth`)にまとめる。
5. **輪郭の殻は「背面を描かない」にする**(`use_backface_culling = True`)。しないと全体が輪郭の色になる。小さな部品(目・口・ほお)には付けない。
6. **骨に毎コマ回転を重ねる時は、先に「動きだけの値」へ戻す**(three のミキサーは値が同じだと書き直さない)。
7. **描く確かめは GPU だけ**(CPU の描画で撮らない。`creator/skilltest/gpu_only.mjs`)。先に機械の札と GPU の鍵を取る。
8. **パスはドライブ名から始まる絶対パス**で Blender・python・node に渡す(相対や `/x/...` は絵が別の場所に出る)。
9. **腕を上げる動きのあるキャラは、腕を下ろした形の点検だけでは足りない。** 手をふるの一番上と上げはじめを、正面・斜め 35°・60° の左右で撮る(脇のへこみ)。おじぎは体を足の上の低い点のまわりに傾ける。
10. **公開の前に**: 手元のパスと、提出に入れない道具の名前を消し、`python tools/history_check.py` で全コミットを点検する。履歴は書き換えない。
11. **3D の材質は builder で作り込まず、画面の しつかん に任せる。** builder の材質は平らな塗り(地の色 = 絵の色 × 0.22・発光 × 0.92)のままにし、ぬの・け・つるつるは上の段の切り替えで当たる(render-device の「しつかん」)。
12. **作る道から 3D を頼まれた時は、受け渡しの紙(`handoff.json`)の変換の絵から組む。** 形は変換の絵、色は元の絵。手順は make-character の「変換の絵から組む」。

## 質感と形の早見(試して効いたもの)
- ぬいぐるみに見せるには、毛足の画像(`P.fuzz_material` + `P.auto_uv`)が要る。シーンの縁の光だけ・頂点の色だけでは毛足は出ない。毛は今はブラウザの毛の殻(しつかん の け)に替えた。
- 胴・脚・足は元の絵の輪郭から高さごとの幅を読んでつなぐ(`P.loft`)。腕は管(`P.tube`)。ベルトは小さな板を弧に並べる。口の中は舌(ピンクの平たい楕円体)を足す。
- 丸い頭は横から顔が見えにくい。「正面の見た目を変えずに横から目を見せる」ことはできない(動かせるのは目の輪郭・ふくらみ・頭の面・前をふさぐ物・輪郭の殻の 5 つ)。
- 顔の面の角が体の丸い縁に当たると粗いにじみが出る。面の向きが正面から 55° 以上それた点を含む四角は作らない。
- 輪(トーラス)を球と同じ深さに置くと「C の字」になる。球の最前面より前へ。

## 確かめ(最低限)
- 重ね: `s04_overlay.py` と `s03_compare.py`(IoU・中心・外接箱)。顔の部品のずれは画素で読む。
- 姿勢: `b06_posecheck.py` + `s02_posesheet.py`(1 コマ 560px 以上。振りの位相が逆の 2 コマを並べる)。
- めり込み: 2 コマおきの BVH の重なりを数える(動き全部で 0)。
- ブラウザ: 表情・口・まばたき・動き 5 つ以上が動く。本物のアプリを GPU で撮り、全身の 8 方向(下からのカメラは床より下に入れない)。
- 同じ builder を 2 回組んで、model.glb と動きの sha256 が一致する。三角形の数と GLB の大きさの上限(前の版の 1.2 倍まで)。
- 判定役を通す(`j01_judge.py`)。「位置・色・形はほぼ合う」。

## つまずきやすい所(特に効いたもの)
- `s03_compare` と `s05_gaps` は外接箱で大きさをそろえて比べる。手の先が少し大きいだけで別の場所に抜けが出るので、先に外接箱の幅を合わせる。
- Blender の glTF 書き出しは、手続きの節点(Layer Weight など)を書けず白く飛ぶ。頂点の色(`gradient`)か絵だけ。
- Git Bash は `--mount=/名前=...` の `/…` をパスに直す。PowerShell の `Start-Process` で起動する。
- ブラウザが古い JS を使う時は、キャッシュなしのサーバー(`serve.py`)で。
- `implicit_shell` で殻を作ってから差しかえると、前の殻が場面に残って動かない(おじぎで頭の後ろに黒い玉)。最初から自分の殻を作り、差しかえた後は三角形の数が前と同じかを見る。
- 「頭のすき間(幅 390・7 歩の札を開いた時)」はキャラの形では直らない。画面の枠の決まりの問題(render-device)。
- 画面ありの試験が 1 本止まる時は、自分の PID の木だけを止めて流し直す(node を名前で止めない)。

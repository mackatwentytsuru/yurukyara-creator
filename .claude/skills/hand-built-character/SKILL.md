# 手組みでキャラを作る(絵 → 部品 → 骨 → 目と口 → 動き)

キャラの名前や絵に依存しない手順。AI の 3D 生成は使わない。色むらが出ず、許諾の問題がなく、VRAM も要らない。1 周は十数秒。
道具は `creator/pipeline/`、builder の型は `creator/builders/_template_px.py`。**Claude が絵を見て部品を決め、撮って比べて数字を直す繰り返し**が中心。

## 小さく刻む(段ごとに撮って、比べて、別の文脈の Claude に判定させる)

1. **頭**(いちばん目立つ所)→ 2. **体と小物** → 3. **骨と動き** → 4. **目と口**。段ごとに 1 周まわし、比べの一覧を見て直してから次へ。作った担当に自分の出来を判定させない(`creator/pipeline/j01_judge.py`)。

## 手順

1. **絵を開いて見る**(Read)。部品の一覧を決める: 形(球・箱・輪・布・板)、色、位置、大きさ、前後の重なり。
2. **画素 → メートル**。絵の高さ(足から頭のてっぺん)の画素数を実寸に割りあて、`S = 画素数 ÷ 実寸`。`X(px)=(px-CX)/S`、`Z(py)=(FY-py)/S`、`R(px)=px/S`。数字は**画素のまま**辞書 D に書く(重ねで直しやすい)。色は絵の画素から標本をとる(`numpy` で連結成分の外接箱を出すと、胴・ブーツ・手などの位置と大きさが一度に取れる)。
3. **builder を書く**(`_template_px.py` をコピー)。`m00_prims`: `superquadric`(丸みのある箱・楕円体。taper でくびれ・すそ広がり)、`ring`(輪。`xy` で楕円、`rot_deg` で向き)、`cloth`(布の板)、`material`(色は sRGB の 0〜255)、`gradient`(頂点の色の濃淡)。
4. **撮る**: `m02_shot.py <.blend> <出力> --views front,right --size 1024 --center <x,z> --scale <m>`。元の絵と同じ画素の範囲を撮れば、そのまま重なる(例: 絵が 1024px・S=1158 なら `--scale 0.884`、`--center` は絵の中心の画素をメートルに直した値)。
5. **重ねて比べる**: `s04_overlay.py 元の絵 撮った絵 出力.png "見出し" --crop x0,y0,x1,y1`。元・作った物・赤い輪郭を重ねた 3 枚の一覧。ずれを数字(画素)で読んで、辞書 D を直す。全体の形の近さは `s03_compare.py`(輪郭の重なり IoU)。
6. **判定**: ブラウザの絵を `creator/pipeline/j01_judge.py` に通す(下の「判定の決まり」)。途中の比べの一覧は、新しい文脈の判定役に、位置・色・横向き・「いちばんずれた所」を答えさせてもよい。
7. **骨の入れ方 — 部品ごと(剛体)**: builder で、部品ごとに**骨の名前の頂点グループ**(重み 1)をつける。`b07_rig_groups.py <spec.json> <.blend> <出力>`。spec は骨(`at` はメートル、`parent`)と `roles`(動きが使う役割 → 骨の名前)と `motion.only`(作る動き)。胴にそって曲がる体(つなぎ目を混ぜたい)なら `b03_rig.py`(箱で区切った重み)を使う。
8. **目と口**: シェイプキーを持つ別の物(`Eyes`、`Mouth`)にまとめる。まばたき(目玉を平らにつぶす `eye_blink`)、口(`mouth_open`・`mouth_wide`・`mouth_o`)。**作った直後のシェイプキーの値は 1(効いた状態)なので、必ず `value = 0` に戻す。** 黒目と光は、目の骨に付ける(視線で動く)。紙や LED の顔なら、顔の面+表(`f01_face_atlas.py`、`b03_rig.py`)でもよい。
9. **動き**: `b04_motions.py`(式で作る。`head` と `wing_*` の役割があれば頭と羽も動く)。`b06_posecheck.py` + `s02_posesheet.py` で、動きの途中の姿勢を大きな一覧にして、崩れを見る。
10. **ブラウザで確かめる**: `creator/viewer/serve.py`(`--mount=/名前=フォルダ` でリポジトリの外のキャラも見られる)。`character.json` の rig: `look.eyes`(目の骨)、`mouth.kind="morph"`、`blink.morph`、`morphs`(表情 → シェイプキー)。

## ゆるキャラらしさを出す工夫(試して効いたもの)

- **茶色などの輪郭線 = 裏返しの殻**(`P.outline`)。物を法線の向きに少しふくらませ、面を裏返した複製を作る。**輪郭の材質は「背面を描かない」にする**(`use_backface_culling = True`)。しないと、殻が元の物をおおって、全体が輪郭の色になる。目・口・ほおなど、線のいらない小さな部品は除く。頂点グループは複製が引きつぐので、骨にもそのままついてくる。
- **つや消しの平らな色**: 材質の `rough` を 0.75〜0.85、`spec`(反射の強さ)を 0.1〜0.3 にする。元の絵が平らな色なら、光沢を落とすだけで「絵に近い」と読まれる。
- **太い 1 枚の帯**(ゴーグルの縁など): 細い輪(トーラス)を重ねず、断面が角丸の長方形の輪(`P.ring(..., sq=0.5, squash=幅に対する奥行きの比)`)にする。横から見ても、ひだのある筒に見えない。
- **開口の内側に収まる顔**: 球のヘルメットから、顔のところを楕円体でブーリアン(差)で切り抜き、肌の楕円体を開口の内側に置く。縁がオレンジの枠になる。
- **球の表面に沿う帯(くさび形)**: 球の式で、格子の各点を表面から数 px 外に置いて作り、厚みはソリディファイで足す。

## 部品の多いキャラを、積み木に見せない作り方(試して効いたもの)

- **胴・脚・足は、元の絵の輪郭から「高さごとの幅」を読み、その断面をつないで 1 つの形にする**(`P.loft`)。楕円体を手で合わせるより絵に近づき、胴・脚・ブーツのすき間が消える。読み方: 元の絵の主な色(例: 服のオレンジ)を色の近さで取り、高さごとに最大の連続区間の左右の端を測る(numpy で数行)。
- **腕は管(`P.tube`)**: 中心線の点と半径を渡すと、肩から手首まで曲がった袖になる。手は別の球。細い棒に見えるときは、半径を 26px 以上にして、肩の端に少し太さを足す。
- **ベルトのコマ**: 白い帯 1 本ではなく、小さな角丸の板を胴の前の弧(半径 = 胴の半幅)に並べる。中央に丸いバックル。
- **葉の形の羽**: 超楕円体を細長くして、先へ向けて細くする(`taper`)。付け根→先の色の変化は `P.gradient_axis`(頂点の色。手続きの節点は書き出せない)。
- **口の中**: 白い楕円だけだと「歯だけ」に見える → 口の下の縁に寄せたピンクの平たい楕円体(舌)を、同じ `Mouth` の物に入れる。シェイプキーで口が開くと、一緒に動いて口の中に見える。
- 小さな部品は、輪郭線(`outline`)を付けると太って見える → 目・口・印・コマは除く。

## 布・ぬいぐるみの質感(ゆるキャラは布・ぬいぐるみ風が多い)

質感の案を、同じ形・同じ光で並べて比べる場: `python`ではなく Blender で `creator/builders/_texture_lab.py -- <出力フォルダ> [R,G,B]`(A 平らな色 / B シーン / C 頂点の色+シーン / D 毛足の画像+法線 / E トゥーン / F 毛足+輪郭の毛羽)。Claude(Sonnet 5.5、新しい文脈、案の名前なし・順番を替えて 3 回、2026-11-06)に「どれがいちばんぬいぐるみに見えるか」を選ばせた結果: **D が 2 回、F が 1 回。A・B・C・E は 0 回**。つまり「シーンだけ(B)では毛足が出ない」は Claude でも同じ。

- **毛足の画像(案 D、ぬいぐるみに必要)**: `P.fuzz_material(名前, rgb, 画像の出力フォルダ, grain=0.16, normal_strength=1.6)` で、毛の線の重なりの画像(色+法線、継ぎ目なし。numpy だけ。AI なし)と、縁の毛羽(シーン)を持つ材質を作る。その材質を付けた物に `P.auto_uv(ob, tile=2.2)` で UV を付ける(立方体投影。tile が小さいほど毛が大きく見える)。GLB に画像 2 枚が入る(1 材質で約 1.2MB。大きいときは `size` を 256 に)。three.js でも読める。
- **輪郭の毛羽(案 F。今は使わない。ブラウザの毛の殻に替えた。下の「作業の既定」)**: `P.fuzz_shell(ob, rgb, 画像の出力フォルダ, thick=0.02, density=0.5, layers=3)` が、物を少しふくらませた殻を重ね、毛の点の画像(透明さで抜く)を貼って、輪郭をふんわり毛羽立たせる(殻の物の一覧を返す)。Claude の選び直し(Sonnet 5.5、3 回)では、F でなく D が 2 回、F が 1 回選ばれた(「F がいちばん」は Claude では再現しなかった。D・F は同じくらい、と読む。1 回ごとの理由は「D は毛足の繊維がはっきり」「F は縁がぼやけて毛羽立つ」)。書き出しは `alphaMode: MASK`(透明さを GREATER_THAN 0.5 で切る節点を、`fuzz_shell` が付ける)。頭など目立つ丸い部品にだけ付け、殻は 2〜3 枚、三角形が倍になるので予算に注意(`pk03`)。
- **シーン(案 B)だけでは、毛足は出ない。** 縁の明るさは出るが、桃の試験で全段が「毛足なし(つるつる)」と判定された。シーンは、毛足の画像の**足し**として使う。
- 頂点の色の濃淡(案 C)は、色のつながり(濃い縁・明るい中心)用。毛足にはならない。
- トゥーン(案 E)は、平らな色+輪郭線のキャラ向け(質感は出さない)。
- 毛足の画像は、1 材質につき 1 つの色。色の違う部分は、別の材質(別の `fuzz_material`)にする。色の濃淡が要る部品には、頂点の色(`Col`)と画像は同時には使えない(書き出しが片方になる)。

### ブラウザ(three.js)で見る色と毛足(11-02 夕方、測って分かったこと)
質感と色の判定は、**Blender の絵ではなく、ブラウザ(`creator/viewer`、web/ と同じ光)で撮った絵**で行う(`node creator/skilltest/shot_browser.mjs <ポート> <character.json の URL> <出力フォルダ>`)。見る人が見るのはブラウザだから。
- **ブラウザの色は、そのままだと元の絵の約 68% の明るさに沈む**(ひよこの体: 元 RGB 231,195,108 に対し 156,131,65)。three.js の光は、強さ 1 で白い面が約 0.32 にしかならず、Blender の太陽光より暗い。直し方は、**実行側で色の絵を発光にも貼って持ち上げる**(`rigRuntime.js` の `applyLift`、character.json の `lift`、既定 0.55)。これで 225,191,97 と、元の 97% に戻る。builder の色を明るく塗り直す必要はない(Blender で見る絵が明るすぎになる)。頬などの小さい面は、元の絵の色をそのまま使う。
- **毛足の画像は、向きがなめらかに変わる細い毛を、たくさん重ねる**(`fuzz_images`)。試した順: 1 画素の粒 → 砂壁に見える / 粒をぼかす → 革やオレンジの皮に見える / 毛の本数が少ない(1 辺 × 5)→ 引っかき傷に見える / 毛を 1 辺 × 24 本にして凹凸を弱める → 元の絵のフェルトに近づいた。法線の強さには 0.4 を掛ける(`FUZZ_NORMAL_GAIN`)。アップではまだ白い細い線に見えると言われる。
- **頬が茶色く沈む原因**: 色の絵を持たない材質に持ち上げが効いていなかった(`rigRuntime.js` を直した)。頬は `W.soft_patch` で作る。
- 7 体を直した結果(11-02): 判定は Claude 以外だったので数字を消した。Claude での取り直しは、結果表の「Claude の判定」の節(毛足 0/14 束、色 13/14 束)。毛足はまだ「粗い」「粒が強い」と言われる。
- **作業の既定(11-03。見比べはこれから。戻すときは、この行と character.json の例から `fur` を消し、`pk02` の検査を外す)**: ぬいぐるみは、部品に `P.fuzz_material` を付け、character.json の最上位に `"fur": {}` を書く。**`P.fuzz_shell`(Blender の殻)は作らない**。ブラウザでは隠され、三角形だけが増える。設定は書かない(太さ 0.4%、長さ 1.5%、明暗 0.25、根元 0.93 が既定値)。`pk02` は、毛足の材質があって `fur` が無いと ERROR を出す。Blender の絵には毛羽が出ない。質感はブラウザの絵で見る。
- **毛の殻をブラウザ側で重ねる(`creator/viewer/furShell.js`)**: character.json に `"fur": {}`。同じ形と骨を使い回すので GLB は増えず、骨とシェイプキーに付いて動く。顔の部品の周りは毛を短くする。**色の絵の筋が残ると傷に見え(flat 0.7)、消すだけだと樹脂に見える(flat 0.95)**。筋を消して、毛 1 本ずつの明暗(pile)とふわっとしたむら(cloud)をシェーダーで足すと、布に近づく。pile を弱めると「平ら」に戻る。根元を暗くした分は gain で明るさを戻す。**毛の太さはキャラの高さに対する割合で決める(`hairWidth`、0.4% が基準)**。UV の繰り返しで決めていた間は、毛が画素より細くなって消え、どう直しても「つるつる」と判定された。太さ 0.7% は粗すぎる。毛は短く密に(長さ 1.5%)、色の違う部品の境目では毛を短くする(青とクリームの毛が混ざって汚れて見えた)。判定はまだ安定して通らない(砂粒のように見えると言われる)。材質は部品どうしで共有されるので、部品ごとに暗くすると何度も掛かる。頬の当て布は、四角い網の全部で毛を短くすると四角い跡が出るので、丸の中だけを使う。
- 効かなかった: `alphaToCoverage` と抜きの線を下げる(面に白い虫のような線が出た)。
- **判定の決まり**(`python creator/pipeline/j01_judge.py <元の絵> <絵のフォルダ> <出力> [--part 部分] [--fur]`): 同じ絵を、別の文脈の Haiku 5.5 と Sonnet 5.5 に各 3 回見せ、2 回以上「はい」でその判定役の「はい」。2 人の両方で合格。同じ絵でも答えが変わることがあるので、1 回では決めない。**2 人とも同じ系統の Claude なので、独立した 2 人ではない**(Sonnet 5.5 は毛足と部分に一度も「はい」を出さず、Haiku は出した、という割れ方をした。割れたら、両方はいでないものは数えず、そのまま書く)。答えは「はい」「いいえ」の 1 語だけで、「ほぼはい」は数えず問い直す。判定の絵に文字や数字を入れない。**合格しても、使う人の目が優先**。使う人が選んだ見た目を既定にしてから、スキルだけの試験を回す。外の素材を使うときは、ライセンスを `docs/部品の一覧.md` に足す。
- 判定役は、毛足が強いと「ざらつき寄り(砂壁)」と言い、弱いと「つるっとしている」と言う。色が合うと、毛足の判定も「はい」に寄る傾向があった。Claude では、Sonnet 5.5 が毛足を 34 束すべて「いいえ」にした(厳しい側)。
- **布の写真の毛(`"fur": {"look": "fleece"}`。11-03 の試し。既定にしない)**: 半透明の毛先(`soft`)、縁の明るさ(`rim`)、布の写真の房(`photo`。`creator/viewer/assets/fleece`、Poly Haven「Polar Fleece」CC0)の組み合わせ。別の 4 体では 毛足 1/4 と、いちばん良く見えたが、スキルだけで作った 7 体では 毛足 1/7、色 6/7 で、いまの既定(毛足 0/7、色 7/7)と差がほぼ無かった(差はぶれの範囲)。撮り方を変えただけで、1 つの AI の答えが 3/3 から 1/3 に変わった体もある。**1 回の良い数字で既定を変えない。** 使う人が選ぶまでは、作業役に `look` を書かせない。
- 半透明にすると描く順が効く。内の層から順に描き(`renderOrder`)、頬の当て布は毛のあとに描く(`PATCH_RENDER_ORDER`)。順が違うと、頬の輪郭が崩れる。`rim` 0.6 は明るい縁の線が出た。0.25 にした。
- 全身の絵が小さいと、毛が画素より細くなって砂に見える。全身は元の絵と同じくらいの大きさで撮る。横に広いキャラは、高さではなく広いほうの幅に合わせて引く(手が切れた)。`shot_browser.mjs` がこの撮り方をする。
- **粒を数字で見る**: `python creator/skilltest/grain_bands.py <絵> <x,y,大きさ,頭の幅> …` が、細かさごとの粒の強さを元の絵と比べる。k_beak は面の粒の強さが元とほぼ同じなのに「砂粒」と言われた。残りの疑いは面より、輪郭の点や細い線と、全身の絵の小ささ。
- 毛の殻は 三角形 × (層 12 + 飛び出す毛 2)を描く。46,448 三角形の k_beak は約 65 万三角形になり、CPU の描画(試験の撮影)でブラウザが落ちた(Target crashed)。`shot_browser.mjs` は GPU の見張りを切って撮る(`--disable-gpu-watchdog`)。作るときは 36,000 三角形以下を目安にする。CPU が混むと 1 コマ数秒かかるので、撮影は順に 1 つずつ流す。

### 体に沿う部品・頬・くぼみの影(`creator/pipeline/m01_wrap.py`。`import m01_wrap as W`)
- **帯(たすき・ベルト・襟)**: `W.wrap_band(名前, [体の物], [(角度, 高さ), …], 幅, thick=…, mat=…, closed=False)`。角度は正面が 0、体の左(+X)が 90。光線で体の面に載せるので、細い・平ら・浮く、を防げる。UV は帯の長さ方向につながるので、文字の画像を貼れる。**帯は `superquadric` や `cloth` で近似しない。** 一周の帯は `closed=True` で、最後の点を重ねて書かない。体に当たらない道は例外で止まる(勝手な位置に置かない)。
- **頬の丸**: `W.soft_patch(名前, [頭], 角度, 高さ, 半幅, 半高, rgb, 画像の出力フォルダ, hardness=0.35, opacity=1.0, clearance=0.012)`。**硬い楕円の部品で頬を作らない**(ブラウザで茶色い丸になる)。毛羽の殻があるときは、clearance を殻の厚みの半分より大きくする。大きくしすぎると、斜めから見て輪郭の外へはみ出す(0.024 で出た。0.012 で消えた)。
- **腕・脚・耳など、体から生える部品**: `W.limb(名前, [体の物], 付け根の点, 先の点, 付け根の半径, 先の半径, mat=…, flare=1.3)`。**`superquadric` を横に置かない**(肩にくさび形の抜けが出た)。付け根の点は**体の中**に置く。線が体を出る所を測り、半径の 8 割だけ内側を付け根にして、面のあたりを太らせる。体に当たらない置き方は例外で止まる。骨の位置(`rig.json` の `at`)には `W.pivot_of(ob)` を使う。付け根の半径と先の半径はほぼ同じにする(差が大きいと、くさび形に見える)。 **付け根の端は丸める(`round_root=True`、既定)**: 平らな端の縁が、肩の丸みから角として飛び出した(ようこそくん)。丸めると肩の上にくさびの抜けが出ることがあるので、`flare` を 1.2 にし、胴の肩の段を元の絵の輪郭(首から腕の上へまっすぐ下がる線)に合わせる(抜け 165 px → 0)。
- **顔の部品と毛羽の殻**: 目・口・鼻の前面は、殻の厚み + 0.012 m 以上、頭の面より前に出す。殻より奥だと、毛羽の点が刺さって黒い点に見える。顔の範囲だけ殻を抜くと、四角い跡が残る。頭が球でないときは、部品の位置を式で出さず、頭へ光線を当てて面を取る。
- **帯の字は、元の絵から切り出す**: `python creator/pipeline/t01_band_texture.py <元の絵> <出力.png> --color R,G,B --json 出力.json` が、帯をまっすぐに伸ばした絵と、中心の道(`path`)と幅(`width_px`)を出す。字を書き直すより元に近く、幅も目で読むより正確(目で読んだ作業役の幅は 150 px、測ると 188 px で、判定で「細い」と言われていた)。道の両端の点は胴の外なので捨てる。字は前だけに載せ、画像の `extension` を `EXTEND` にする。
- **t01 は帯の両端を無地にそろえる(既定。`--raw-ends` で前の動き)**: 元の絵の帯の端には、肩で折り返す形・縁の濃い線・折り返しの陰が写っている。そのまま貼ると、肩の端が「破れた」「斜めに切れた」ように見えた(ようこそくん)。字のない両端・食いこんだ縁・字の横の陰を、行ごとの地の色+粒で塗りかえる。いちばん端の 3 列は粒なし(EXTEND で伸ばすと粒が筋になる)。
- **たすき(ななめの帯)は、閉じた 1 本の輪にする**: `loop, err = W.tilted_loop([胴], 前の道)` が、前の道に平面を合わせ、肩の上・腰の横・背中をその続きにした全周の道を返す(ようこそくんで、前の道とのずれ 0.6 mm)。`W.wrap_band(..., loop, closed=True)` で作り、`W.band_text_uv(帯, loop, seg, 前の道の最初の角度, 最後の角度, 0.92)` で字を前に載せる。**前の道の端から手で背中の点を足した開いた帯は、肩の上が空いて端が斜めに切れ、腰の横で道が急に折れて帯が胴から浮いてふくらんだ。**
- **帯と腕・頭**: 帯がかぶさる腕の付け根は `over=[腕]`(中に入った所だけ持ち上げ、まわりを坂でつなぐ。上限 `over_max` 3 cm。上限なしでは帯が腕の先までかぶさった。`over_pad` 1 cm で毛の殻の突き抜けを防ぐ)。帯がもぐる頭・反対の腕は `under=[頭, 腕]`(縁がその中に入る列だけ、帯の幅を外までに縮める。見た目は変わらず、`m03` の「深く埋まる点」が消えた)。`body` に腕を入れると、横からの光線が腕の先に当たって帯が飛ぶ。どちらも入れないと、腕が帯を突き抜けて手前に出る。
- **輪郭の折れ線**: `P.loft(..., refine=4)` で断面の間を補間する。断面が 20 段でも、頭の輪郭に折れ線が見えた。胴の上の端は、頭に隠れる所まで細らせず縦に伸ばす(平らな肩だと、帯の角が折れる)。
- **帯と体**: `wrap_band` の体の一覧には、帯が当たる物を全部入れる(腕を抜くと、腕と交差する)。帯の上端が体の外へ出ると例外で止まるので、胴の断面を肩の上まで作る。
- **`W.limb` が合わないとき**: 体のすぐ外に置く短い腕は短い棒になる。長い布の耳は、平たい `P.tube`(`ry_scale` 0.5)と内側の当て布に分けると形が合う。どちらも付け根は体の中へ入れ、`m03_contact` を通す。
- **印 `surface_only`**: 毛羽の殻と `soft_patch` に自動で付く。検査で「体」にも「部品」にも数えない。**検査を通すために、目や口に付けない**(浮きを隠すことになる)。目が浮きで落ちるときは、縁を頭の面へ沈める。
- **毛足の繰り返し**: `auto_uv(ob, tile=4.0)` を基準にする。2.2 は毛が粗く、継ぎ目が出た(試験で確認)。殻の厚みの分だけ、芯の半幅を細くする(厚み 0.010 m で 10 px ほど。IoU 0.942 → 0.958)。
- **フリル**: `W.ruffle(名前, 3D の道, 幅, folds=…, gather=…, up=…, outward=…, mat=…)`。付け根の列は動かない。下へ垂れるときは `outward=(0,0,-1)`。
- **くぼみの影**: builder の最後に `W.bake_ao(全部の物, occluders=毛羽の殻と当て布を除いた物, samples=32, dist=0.2, strength=0.7)`。three.js には接地の影が無いので、首の下・腕の付け根の影はここで作る。頂点の色 Col に掛け、`b07_rig_groups` が GLB に入れる(色の絵と一緒に掛かる)。`dist=0.3, strength=0.9` は胴が暗くなりすぎた。
- **検査を通すために形を崩さない。** 抜けを消すために胴を角張らせると、輪郭の検査は通っても元の絵から離れる(試験で実際に起きた)。形は元の絵に合わせる。残る抜けは、部品の付け根・太さで直すか、場所と理由を報告に書く。最後に決めるのは検査ではなく、ブラウザの絵を見た別の文脈の Claude。
- **脚のあるキャラ**: 足の球だけで済ませず、胴の下の端を絵に合わせて上げ、足の上に短い脚の楕円を足す(絵に脚が見えるのに、足が胴に直接付いて見えた)。
- **検査をまとめて通す**: `sh creator/pipeline/check_all.sh <build.blend> <pack> <元の絵> <出力フォルダ> [帯の名前,…]`。character.json・GLB の予算・埋まりと浮き・**抜け**・ブラウザの撮影・視線の積み上がりを 1 回で測り、落ちると番号 1 で終わる。builder を直すたびに通す。**人に見つけてもらう前に、ここで止める。**
- **抜けの検査**: `s05_gaps.py <元の絵> <透明背景の正面>`。元の絵では体なのに背景が見える場所を、太い所と、周りを体に囲まれた所に分けて出す。輪郭の重なり(IoU)が 93% でも、肩の抜けは見えない。元の絵とポーズが違えば抜けと出るので、残すなら理由を報告に書く。
- **埋まりと浮きの検査**: `blender -b <build.blend> -P creator/pipeline/m03_contact.py -- --hug 帯の名前,… --near 0.02 --json 出力.json`。見た目を AI に見せる前に通す。帯は「面の近く 8 割以上、0.4 cm より深く埋まらない」、耳・腕は「埋まる点が 2〜60%」。**この合格は見た目の合格ではない**(出力の `visual_pass` は常に false)。帯と帯が交差しても NG になるので、NG の理由と相手を確かめる。

## 合否の数字を先に決める(輪郭の重なり以外)

`s03_compare.py` は、輪郭の重なり(IoU)に加えて、**中心のずれ(正規化した 500px の絵で、何 px)・外接箱の幅の差(%)・高さの差(%)** を出す。目安: IoU 0.90 以上、中心のずれ 6px 以内、幅・高さの差 3% 以内。外れた数字で、直す所を決める(中心のずれ → 体の置き場所、幅の差 → 部品の半径、高さの差 → 全体の高さの割り当て)。顔の部品のずれは `s04_overlay.py` の重ねで、画素で読む。

## character.json の正しい形(最上位に置く。`rig` の入れ子は使わない)

```json
{
  "id": "peach", "name": "もも", "model": "model.glb", "type": "rig", "height_m": 1.0, "fur": {},
  "expressions": ["neutral", "happy", "surprised", "sad", "think"],
  "motions": { "idle": "motions/idle.glb", "talk": "motions/talk.glb", "nod": "motions/nod.glb" },
  "look":  { "bone": "head", "max_deg": [22, 14], "eyes": ["eye_L", "eye_R"] },
  "mouth": { "kind": "morph", "morph": "mouth_open", "gain": 1.2 },
  "blink": { "morph": "eye_blink" },
  "morphs": { "happy": { "mouth_wide": 0.9 }, "surprised": { "mouth_o": 1.0 }, "sad": { "eye_blink": 0.3 } }
}
```

- `expressions` は表情ボタンの名前。`morphs` は、表情の名前 → シェイプキーの重み(キーは model.glb にある名前)。
- `look.bone` は体を向ける骨、`look.eyes` は黒目の骨(無ければ省く)。口は `mouth.kind = "morph"` と `mouth.morph`(口を開くキー)が要る。
- **pack を作ったら、必ず `python creator/pipeline/pk02_check_character.py <pack>` を通す**(最上位のキー、モーフの名前、骨の名前、動きのファイルを機械で確かめ、外れた所を ERROR で出す)。`OK` が出るまで直す。ブラウザで確かめる前に、ここで落ちる誤りが多い(入れ子にした、`mouth.kind` を書き忘れた、`expressions` が空)。
- `pk01_package.py` は、model.glb の骨とモーフを読んで character.json を書く(11-04 に直した)。`mouth_open` があれば `mouth.kind: "morph"`・`blink`・`morphs`・`look.eyes` を自動で書き、既定で `"fur": {}`(使わないなら `--no-fur`)。顔の表(`face/face_atlas.json`)は無くてもよい。出力は手直しなしで `pk02` を通る(`characters/robo`・`yokoso` の GLB で OK を確認)。`mouth_open` が無く atlas だけのときは atlas の口で書き、WARN を出す(`pk02` は通らない)。

## 試験で見つかった知識(スキルだけで作らせた作業役が、足りないと書いた物)

- 1 つのメッシュで**頂点の色を使う材質は 1 つだけ**にする。Blender 5.2 の glTF 書き出しは、2 つ目の材質から `COLOR_0` を白で書き、色が飛ぶ。色の濃淡が要る部品が複数あるときは、1 つの材質に寄せるか、濃淡を材質の色そのものと `sheen` で出す。
- 頭の大きいキャラ(頭が全高の 2/3)は、手をふるで腕が頭にめりこむ。`motion.arm_amp` を 0.45 前後に下げ、肩の骨を腕の付け根の少し下に置く。
- `P.gradient`(頭頂から縁への濃淡)は**正面基準**。後ろ側が白っぽくなるので、全周で同じ色にしたいときは、上下の向きで色を変えるか、`sheen` で出す。
- `b06_posecheck.py` などの道具には**絶対パス**を渡す(相対パスだと絵が見つからない)。
- 確かめ用サーバー(`serve.py`)は、止めても python が残る。PID を指定して止める(名前で止めない)。
- 顔の部品(目・光・口・ほお・筋)は、頭の表面に光線を当てて貼る薄い板で組むと、頭が球でなくても表面に沿う。細い筋を管で作ると半分埋まって点線になる → 色をなじませた帯の板にする。まばたきで光が白い点として残るときは、閉じる形で黒目の奥へ沈める。

## 試験の下見で見つかった知識(別のキャラ 1 体、スキルだけで作らせた結果)

- **輪郭の重なりが低いときは、まず背景を疑う。** 撮った絵の背景は灰色で、s03 は背景との色の差で輪郭を取るので、白や明るい灰色の部品が体の外と数えられ、IoU が下がる(0.855 → 部品を暗くしただけで 0.981 になった)。`m02_shot.py --transparent` で背景を透明に撮ると、`s03_compare.py` が透明さで輪郭を取り、この誤りが消える。
- 撮影の光で、色は元の絵より 1.1〜1.2 倍明るく出る。同じ場所の中央値で比べ、元の色よりやや暗く置く。
- 腕が斜めに垂れたキャラは、`b04_motions.py` の手をふる・ジャンプで腕が頭の後ろに隠れる。`motion.arm_amp` を 0.5 前後にする。
- **球の面の網目(マイクの頭など)**: 経度/Δθ ± 緯度/Δφ = 整数 の線を、面に沿う平たい管で作る。てっぺんはふたでまとめる。網目の交点を自動で拾うとばらつくので、元の絵に交点を打って目で確かめ、手で決めた数字を使う。
- 横の絵が無いときの奥行きは、頭を球とみなして、正面の幅の 0.9〜1.0 倍にする。実寸の高さは、足元から頭のてっぺんを 1.0m(キャラの設定が無ければ)として決める。
- 腕などの最適化の総当たりは、絵を 3 分の 1 に縮め、粗く探してから細かく詰めると 4 秒で済む(縮めずに探すと 10 分で終わらない)。
- 帯状の部品(口の線など)の端を丸めるときは、帯の法線を使う(向きを決め打ちすると、端が逆向きに崩れる)。胴を断面でつなぐとき折れ目や点線が出たら、断面を Catmull-Rom で補間して細かくする。細い筋の板が、丸い頭の先で光線を外して止まるときは、近い表面へ寄せる。
- **口などのシェイプキーで顔の部品を動かすときは、頂点の奥行き(y)も、動かした先の頭の表面に合わせ直す。** 高さ(z)だけ動かすと、部品が頭にめり込んで消える。
- 頂点の色を前の絵の x・z から取ると、側面と背面が灰色や白に化ける。x を頭幅の 72% に挟むと直る。撮影の光が上から当たり、下向きの面が暗く出るときは、頂点の色を `max(0, -nz)`(下向きの度合い)で逆に補正すると、平らな色に近づく。
- 面の板(中央のファン+輪)は、ファンと輪の向きを逆にする(そろえると、中心に小さな丸い影が出る)。
- 判定用の AI は、「腕・足・目がずれている」のように、実測と食い違う指摘を返すことがある。**数字(IoU・中心のずれ)と大きく撮った確かめで、指摘が本当かを確かめてから直す。**

## 球・箱の胴と、毛の殻の試験で見つかった知識(11-03、スキルだけの作業役 6 体)

- **球や箱の胴**: 頭と胴が 1 つのキャラは、動きの役割に `head` を使わず、体の骨だけで動かす。`look.bone` も体にする。役割は root・body・arm_L・arm_R・leg_L・leg_R(+X 側が `_L`)。
- **`W.limb` の先**: 先は丸まって `tip` で終わる。絵の手の端の画素に置く(前の版のこの行は「半径の分だけ外へ」と書いていたが、誤りで、腕が胴に埋まって見えなくなった)。面の近くに置くと、短く埋まって「飲まれた」で落ちる。付け根が体に入らない例外は、`bury=0.45` と、体の太い所を通る root で直る。
- **輪郭の測り方**: ぬいぐるみの絵は、毛羽の幅(片側 8〜12px)が輪郭に入る。色の閾値を厳しくすると手足の縁が 10〜30px 小さく出るので、外形の差分の絵で確かめる。胴の幅を測るときは腕を除く。
- **抜けの直し方**: 胴の下は足の上より太くする(脚の横の三角の抜け)。足は少し大きめにして、先を `taper` で細らせない。`s05` は外接箱でそろえるので、1 か所を直すと別の側へ動くことがある。
- **顔の部品と毛の殻**: `soft_patch` の clearance は 0.014 にする(0.004 ではほおが粒状に荒れた)。目と口の前面は頭の面より 0.015 m 以上前に出す。丸い頭に平たい目を置くときは、頂点ごとに y を頭の面へ合わせ直す(内側が埋まって豆の形になる)。
- **地の色の当て布(おなか)**: 体の面に光線で載せた面の裏に、1.2 cm 沈めた複製を付けると `m03` の浮きが消える。`soft_patch` では縁がくっきりしない。`auto_uv` は tile 9(4 では毛が太い縞になる)。自作の面は巻く向きを確かめる(逆だと毛が内側へ出る)。
- **長い耳の内側**: 外の管の面より前へ出す量を、断面ごとに計算する(一定だと隠れて細くなる)。耳の先は半円の点列で丸める。
- **口の中の隠し方**: `mouth_open` の内側の楕円は Basis で点につぶす。奥へ沈めると `m03` が「飲まれた」で落ちる。頭へ 8px 沈めた極小の球を口の近くに足すと、浮きも飲まれも通る。
- **`check_all.sh` は 2 分を超える**ので、背景で流して待つ。
- **垂れたつばの大きな帽子**: つばを円盤で組むと、下の縁に抜けが残って直らない(試験で 55 分の時間切れ)。**絵の左右の端から高さごとの半径を読み、頭と同じ中心の回転体で作り、頭の前を大きな楕円体でブーリアンの差で切り抜く**(次の試験で IoU 0.986、抜け 0)。つばを後ろへずらすと、横から見て崩れる。帯の輪は `--hug` に入れない。
- **`P.superquadric` の半径は (x, 奥行き y, 縦 z) の順**。足を (rx, rz, ry) で渡すと地面の下へ突き出し、輪郭の比べが大きく崩れる(IoU 0.94 → 0.98)。外接箱の幅の差が急に変わったら、高さごとの左右の端を数字で比べて、はみ出した部品を探す。
- **目と口の浮き(`m03`)**: 面の近くに埋まる点が 2% 以上ないと NG。目と口の近くに、頭へ 8 mm 沈めた極小の球を同じ骨で足すと通る。腕が肩の外へ出る形は、肩の球を同じ骨に足すと抜けが消える。

### 目の周り(11-06、アニメ調の顔で「目の周りを滑らかにした」手順を、4 体の目に当てて調べた。直さなかった)
考え方は 6 つ(眉は絵に描く / 法線は弱く / 境の影は肌色系の暗い色 / まつげは細く / 目玉を引っ込めすぎず板をはみ出させない / 確かめは本番と同じ描き方)。ゆるキャラ 4 体の目(黒い楕円・光る円・顔の表の目)に当てた結果:
- **眉・まつげ**: 無いので当てはまらない。
- **影**: 当てはまらない。ブラウザの viewer・`web/` には影の描画(`castShadow`)も輪郭の殻も無い。ようこそくんの目の周りは、色相(G/R)が 1.34 のまま、輝度が目の縁から 60 画素のあいだに約 7% 下がるだけ(毛の根元が見える分。灰色・黒の輪は出ない)。ロボくん・パネルくん・提灯くんの目は、暗い地に光る色、または顔の絵(ink 24,24,32)で、境に別の暗い色は入らない。
- **法線・毛**: 毛足があるのはようこそくんだけ(ロボくんは `"fur": false`、あとの 2 体は `fur` なし)。頭の法線は `fur.normal`(0.15 倍)で既に弱く、毛は目の部品から `clear`(0.6 × 毛の長さ)+ 1.5 倍の幅で短くなる。目の板が面から浮いている分(3D の距離で測るため)、式から計算すると目の縁に毛が 2.5〜7 mm 残る(測ってはいない)が、本番の描き方の絵で縁は滑らか。**直す試しをやめた**: 目の縁から面に沿った距離で毛と法線を弱める `calm` を足して、`calm: 2` では絵が変わらず(前後の画素差が、撮り直しのばらつきと同じ)、`calm: 8` では目の周りに毛のない暗い輪が出て悪くなった。
- **目の板**: ようこそくんの板は頭の面から縁で 12.5〜20 mm(下の縁が最大)、中心の前面で 16 mm 浮き、後ろ面は 4 mm 浮く(埋まらない)。毛(15 mm)は板の縁より低く、かぶらない。斜め 50° と下から 40° でも、小さなボタンの目に見えるだけでよい。
- **撮り方**(こちらが前後の比べで一番効いた): `creator/skilltest/shot_eye.mjs` が、目の寄りと胸から上を、本番と同じ GPU の描き方で撮る。**視線を切ってはいけない**(`IdleGaze` が乱数で目を動かし、撮るたびに目の位置が 1 cm 変わる。固定の目標を見させる)。動きを時刻 0 で止め、実時間 8 秒待ち、前の撮影の `shot_eye_info.json` を渡して同じカメラで撮る。それでも画素差(>24)が 0.2〜0.5% 残る(目の位置の 1 mm 以下のずれ)。前後の並べは `eye_sheet.py`、判定は `eye_judge.py`(左右 2 枚を順番を入れ替えて問う。目の差は小さく、2 つの判定役とも多くが「同じ」だった)。

## 色の帯のある球の胴・帽子(11-03、パンのぬいぐるみ。新しい作業役が書いた)

- **胴の色が高さで変わる(焼き色・おなかの帯など)は、1 つの形・1 つの材質の「色の絵」に入れる**(11-04、パン): `m = P.fuzz_gradient_material(名前, [(v, RGB), …], 画像の出力フォルダ, height=8192)` と `P.height_uv(胴, z0, z1)`(v = 高さ、u = 周りの角度。毛が横に伸びないよう、u は周りの長さに合わせて何周か巻く)。色は元の絵の中央を高さごとに測る(目・頬・口・筋の画素は外す)。**ブラウザで 1 回撮り、同じ高さの G を元の絵と比べ、その比を色に掛ける**(暗い焼き色ほど明るく持ち上がる: てっぺん G 元 113 → 141。掛けたあと 112)。境はブラウザで約 4% 下に出たので、境の高さを上げて置く。
  - **やってはいけない**: 胴の `P.loft` を境の高さで切って材質を分ける(前の版の手順)。境が硬い帯になり、毛の殻が「色の違う部品の境」で毛を短くして溝に見え、おなかが別の部品に見えた。
  - **なぜ `Col` の掛け率が効かなかったか**: ブラウザでは、頂点の色は拡散の光にだけ掛かり、明るさの持ち上げ(色の絵を発光に使う)と、毛の殻の色(色の絵を 8 段縮めて読む `textureLod(map, uv, 8.0)`)には掛からない。さらに明るいオレンジは R が 255 で頭打ちになる。測ると、てっぺんと顔の G は元 113 / 192 に対し 160 / 156 で、濃淡がほぼ消えていた。
  - 毛の殻の色は 8 段縮めた絵から読むので、**色の絵の縦の画素 ÷ 256 が濃淡の段の数**になる。縦 4096(16 段)では下の境が約 10% の幅にぼけた。8192(32 段)にした。画像は 16 × 8192 で小さい(GLB は 7,470 KB → 5,657 KB)。
- **`W.limb` の `tip` は、手の端の画素そのもの**(先は丸まって tip で終わる)。端より半径ぶん外へ置くと、腕が胴の内側に埋まって見えなくなった。丸い手は、`limb`(付け根を埋める)+ 手の楕円体を `P.join` で 1 つにして同じ骨に付けると、くさび形が消えた。`ob["pivot"]` は join の前に控える。
- **白いフェルトの帽子に毛の殻を付けない**: 楕円体を重ねた白い帽子に毛の殻が付くと、ぼさぼさの綿に見えた(パン)。`P.fuzz_material(..., sheen=0.0)` にすると、ブラウザの毛の殻の対象から外れ(殻は `sheen > 0` の材質だけ)、フェルトの細かい凹凸だけが残る。ただの `P.material` では、つるっとした樹脂に見えた。
- **帽子**: 帯の円筒+雲形の楕円体 3〜4 個(中央・左右・つなぎ)。円筒は胴の中へ 8% ほど深く伸ばさないと、`m03` が「浮き」で落ちる(1.6% → 通った)。抜けの検査の赤い所は、くぼみに楕円体を足して埋める。
- **筋(短い `wrap_band`)の浮き**: 面の裏へ x・y を 0.965 倍した複製を足して `P.join` すると、`m03` の浮きが消える。
- (取り消し、11-04)前の版は「`Col` に高さの掛け率を掛けると、色の判定が 3/3 になった」と書いていたが、ブラウザの絵では濃淡がほぼ消えていた(判定役の「はい」と、人の目の見え方が食い違った例)。上の `fuzz_gradient_material` を使う。
- 球の胴は頭が無いので、`look.bone` と動きの役割は `body`。ボーンは root・body・arm_L/R・leg_L/R・eye_L/R。

### 薄い部品の縁と、頭と胴の境(11-04、花・マント・角・文字の 4 体を目で見て。花とマントで直して測った)
- **薄い部品(葉・マント・角・しっぽ・薄い布)の材質には `P.fuzz_material(..., sheen=0.0)`**。白い帽子と同じ理由で、ブラウザの毛の殻の対象から外れ、縁の針のような毛が消える(元の絵の縁はなめらか)。花の葉・マントの両方で、ブラウザの正面と斜めの絵の縁がなめらかになり、`check_all.sh` は全部 OK。毛を生やしたい厚い部品(頭・胴・花びら)は今まで通り。
- ブラウザの毛の殻に `fur.thin`(既定 0 = 働かない。2026-11-04 に切った。葉には効いたがマントには効かず、sheen=0.0 のほうが効いたため。使うなら 6 などを書く)を足した: 部品の一番薄い向きの厚み(世界座標の箱)が毛の長さの 6 倍より薄いと、その割合まで毛を短くする(下限 0.2)。葉(厚み 0.06 m)は倍率 0.67 で針は減ったが残った。**マントは箱が胴を巻くので倍率 1 で効かない**。だから決まりは上の `sheen=0.0`。`"fur": {"thin": 0}` で前の見た目に戻る。毛足の部品の倍率が全部 1 のキャラ(ようこそくん)は、殻の計算が変わらない。
- **頭と胴の境の水平の段は、胴の首側を細くしても直らない**。花で胴の上端を 150→100 に細くすると(頭はそのまま)、肩の高さ(絵の上から約 63〜65%)に `s05_gaps` の抜けが出て落ちた(586px。元の絵の胴は、頭のすぐ下でも広い)。頭を下げて細くした版は ④ を通ったが、胴の上に襟のような膨らみが出た。頭の下の輪郭を丸く長く下げる(下の端 808→850)と抜けなしで通ったが、段は目で見てほぼ残った。まだ直っていない。次は、頭の下の影(`bake_ao` の強さ)や、境の色のなじませを試す。
- **マントの腕の「細く水平」は、測ると元の絵と同じだった**: 元の絵の左手は x=140 から、高さ 146px(半径約 73)。作業役の `W.limb`(先 (146,814)・半径 70)とほぼ一致する。見た目の差は、元の絵ではマントが肩から腕の上にかぶさり、手がマントの下から出ること(層の重なり)と見ている(絵で見ただけで、直して確かめてはいない)。腕の先を内へ縮めると肩の高さに抜けが出た(先 (215,835) 半径 80 で 1828px、(160,820) で 435px、(150,816) 半径 76 は通ったが見た目はほぼ同じ)。腕の数字を縮めて直そうとしない。

## 人の顔・毛束の多い髪(アニメ調の頭。難所の試験で見つかった知識)

- **全部の部品に材質を渡す。** 材質なしの部品を `P.join` で合わせると、空の材質枠ができて白く写る(羽根の白い筋の原因)。
- 外へ広がる髪は、中の詰め物を頭の大きさに抑える(大きいと毛束を隠す)。毛束は、軸のまわりの「半径と高さ」の曲線にそって作り、幅の向きを周の向きにする。`P.tube` は断面の向きを決められないので、平たい毛束には使えない。
- 耳を出すには、耳の高さの毛束の根元と毛先の両方を耳の後ろに置く。**何が隠しているか分からないときは、シーンの `ray_cast` で、当たった塊の外接箱を出すとすぐ分かる。**
- 4 方向の縮尺合わせは、顔の大きさ(目〜あご)の画素数で各絵を合わせる。後ろの絵に顔が無いときは、髪の幅と下の端で合わせる。
- 到達点(Opus 5.5 xhigh、スキルだけ、1 回、$6.55、約 30 分): 4 方向の輪郭の重なり 0.73〜0.82、Claude の判定役は「正面は同じキャラに見える、横は別人寄り、使える水準の約 50%」。弱い所: 髪が板・花びら状で丸い毛束の房にならない、帽子が寸胴で高い、リボンの蝶結びが無い、目が小さい。この種類(人の顔・毛束)は、ぬいぐるみより明らかに難しい。

## SVG の元の絵から作り直した知識(2026-11-06、f_led=光る点の箱・d_lantern=和紙の提灯)

- **箱・球の胴の輪郭**: `P.superquadric` の指数を 0.24 まで下げると、元の絵の丸い角に合った(0.40 は角が丸すぎ)。指数を下げると、平らな面に頂点がほとんど載らない(次の `m03` の「浮き」の原因)。胴の下の角が合わずに抜けが出たら、胴の指数を先に下げる。
- **`m03` の「本体」**: 外接箱がいちばん大きい物は「浮き」を見ない(手足が付いていても、本体の頂点が手足の中に 2% 入るとは限らない)。手足を体から離すと、手足のほうが落ちる(確認済み)。脚の「飲まれ」は、指数が小さい(端が平ら)ほど端に頂点が集まって上がる。脚の端を体と足に重ねる量を、10〜15px に抑える(73% → 56%)。
- **提灯の骨(輪)と羽根**: 羽根を厚くすると、骨の輪が羽根の中に入って `m03` の `--hug` が「深く埋まる」で落ちる(`ry_scale` 0.28 は通り、0.34 は落ちた)。厚みは検査と相談。
- **羽根・垂れ布は、板(`P.cloth`)でなく平たい管(`P.tube`、`ry_scale` 0.28)**: 板は外の縁が直線で、すその丸みが出なかった。中心線の点(px)と半幅を数点書き、Catmull-Rom で増やしてから渡す(点が少ないと多角形になる)。すその丸みは、最後に半幅を 66 → 56 → 38 → 14 と細らせる点を足す。上の端は胴の縁のすぐ内側、前に少し出す(`flap_y` -0.06)。
- **顔の面の端は、胴の曲がりの前で止める**: 面の上端が胴の丸みが始まる高さを越えると、帯の縞が出た。面を小さくして中心を下げた(f_led: 中心 0.66 → 0.645、高さ 0.56 → 0.525)。
- **光る点の顔の合わせ方**(`f01_face_atlas.py led`、`specs/<id>_face.args` に書く。`run_built.sh` が渡す): 面が横長なら `gh=`(点の縦の数)で点を正方形にそろえる。`eye_circle=20` で目の輪を円周の点にする。`dot=0.36 glow=0.55 smile_t=1.1` で、元の絵の細かい点に近づけた(`dot` 0.52・`smile_t` 1.8 の既定は、判定役に「太く大きい」と言われた)。`bg_a`・`fade`・`corner` は画面の暗さと縁。
- **紙の顔**(`f01_face_atlas.py paper`、同じく `<id>_face.args`): `ink=` `blush=`(r,g,b,a)、`lx ey erx ery`(目の位置と半径、割合)、`gloss=1`(黒目に白い光を 2 つ)、`smile_cy smile_rx smile_ry smile_t`、`ch_x ch_y ch_rx ch_ry ch_blur`(ほおをぼかす)、`cell_h`(1 マスの高さ。面が横長のとき)。ほおのぼかしは、透明部分の色もほおの色にしないと灰色のふちが出る。顔の色を光らせたいときは spec の `face.emission`(`paint` の面)。
- **目で見て決めた補正**: ブラウザの色を測る(`creator/viewer` の絵と元の絵の同じ場所の中央値)。紺は、材質の色を元の絵の標本より少し明るくする(絵の標本の 0.9 倍が出た)。
- **元の絵の床の影が検査を狂わせる**: `talking-character` の「SVG で描く」を見る。

- 骨に毎コマ回転を重ねるときは、先に「動きだけの値」へ戻す。three.js のミキサーは値が前と同じだと骨に書き直さないので、重ねたままだと回り続ける(視線で体が 173 度まで回った)。`creator/skilltest/test_look_drift.mjs` が数百コマ回して測る。

- `m02_shot.py` を元の絵と同じ画素で撮る式: `--scale` = 絵の幅(px)÷ S、`--center` = ((中心 px − CX) ÷ S, (FY − 中心 py) ÷ S)。
- `s03_compare` と `s05_gaps` は、外接箱で大きさをそろえて比べる。手の先が少し大きいだけで、ほかの場所に抜けが出る。先に外接箱の幅を元の絵に合わせる。

- まばたきで、平らにつぶした目玉の奥にヘルメットや部品が透けて「壊れたゴーグル」に見える → ふだんは点(見えない)で、まばたきで広がる肌色の円盤(まぶた)を、同じ名前のシェイプキーで足す。シェイプキーを作ったあとに基準の形を変えるときは、`mesh.vertices` ではなく `shape_keys.key_blocks['Basis'].data` を直す。
- 顔の面(体の表面に貼る面)の角が、体の丸い縁に当たると、角に四角い粗いにじみが出る(貼った面の角が丸い縁の外や急な坂に乗る) → 光線が当たらない点と、面の向きが正面から 55° 以上それた点を含む四角は作らない。面を平らな部分に収まる大きさにし、足りない分は表(顔の絵)の中身を大きくする。

- 輪(トーラス)を球の表面と同じ深さに置くと、半分埋まって「C の字」に見える → 球の最前面より前に置く。
- Blender の glTF 書き出しは、手続きの節点(Layer Weight など)を書けず、白く飛ぶ → 頂点の色(`gradient`)か絵だけ。
- OBJ を Blender に読むと物が 180° 回って入る → 回転を 0 に戻す(`b03_rig.py` のコメント)。builder が作る .blend には起きない。
- 手をふる・おじぎの確かめは、振りの位相が逆の 2 コマを並べる。動きの一覧は 1 コマ 560px 以上。

## 部品の寸法は元の SVG から(2026-11-06 夜、みかんの口が「鼻」に見えた件を測って直した)
- **原因**: builder の口と目の数字を、設定の文書の部品表(古い値。口 幅 74・高さ 32、目 71×97)から取っていた。元の SVG は描き直しの後で、口 88.2×45.9px・目 81.9×111.3px(最終の画素)。口は小さな楕円を下へ細らせた形(`taper=(0.22, 1.0)` で見える幅は半径の約 0.65 倍 = 約 52px・上が丸い)、舌の桃色は上の端(`mz + R(9)` は「上」。Z は上向き)で、判定役の答え 6 つが「鼻」「口が無い」になった。
- **測り方**: 元の SVG の `<g id="char">` の `transform`(例 `translate(627 1000) scale(1.05) translate(-627 -930)`)を部品の座標に掛けて最終の画素に直す。builder に `svg_px(x, y)` を置き、D に「SVG の数字 → 変換」の形で書くと、出どころが追える。半径は倍率だけ掛ける。測ったら PNG の画素でも確かめる(暗い色の塊の外接箱。口 86×43px で一致)。
- **開いた笑い口(D の形)の作り方**: 元の SVG の口は、両端が角の 2 次ベジェ 2 本 = 放物線(x = 中心 + 半幅×s、y = 角の y + 下がり×(1 − s²)、下がり =(制御点の y − 角の y)÷ 2)。この 2 本で囲んだ格子(列 24・行 8、両端の角は 1 点の扇)を作り、**体の網に正面から光線を当てて**(`BVHTree.ray_cast`)面から 2.5mm 手前に前の板、1mm 奥に後ろの板、縁に壁(前の板とは点を分けて、前の板のなめらかさを壁に引っぱらせない)。舌は「舌の楕円 ∩ 口の形」の格子で、前の板のさらに 0.6mm 手前。シェイプキーは、深さ(下の縁)と幅の倍率を変えた同じ並びの点(`mouth_open` 深さ×1.8・`mouth_wide` 幅×1.3・`mouth_o` 深さ×1.3 幅×0.5)。口を開くほど舌の見える所が増える。見本: `creator/builders/mikan.py` の `mouth_mesh`。

## 三面図(正面・横・後ろ)から主役ノリーを作った記録(2026-11-06 夜、`creator/builders/norrie.py`)

### 三面図から組む手順(効いたもの)
- **縮尺・枠をそろえた 3 枚**(S=1040、FY=1076、透明の地)なら、`m02_shot.py --views front,left,back --size 1137 --center 0,0.488 --scale 1.0933 --transparent` で元の絵とそのまま重なる。重ねの数字は、透明さの面(alpha>128)どうしの IoU と外接箱の中心・幅・高さを自分で数行で測ると、s03 を待たずに毎回見られる(`build/iou.py`)。**1 周目から IoU 正面 0.959・横 0.953・後ろ 0.954**。最後は 正面 0.956・横 0.960・後ろ 0.948(s03_compare の正規化では 0.956・中心ずれ 0.0px・幅差 0.8%・高さ差 0.0%)。
- **断面の読み方**: 高さごとに、正面の絵の左右の端 → 半幅 rx、横の絵の前後の端 → 中心 cy と半奥行き ry。ただし**元の絵の黒い縁(約 7px)は外形に入っているので、断面は 7px 引き、両端の z も殻の分(0.007m)内へ寄せる**(`secs_from`)。前かがみは cy の傾きだけで出る(頭 cy=-0.2、胴の下 cy=+0.02)。頭と胴を別の `P.loft`(頭は 16 断面、胴は 20 断面、n=36、refine=2)にした。ぶつかりは首の所で、胴の上の端は頭の中に隠す。
- **腕のある側の胴は細く**: 正面の外形の半幅(前の絵で 211px)は腕込み。胴を同じ半幅で作ると、腕の管が胴の中に 85% 入って m03 が「飲まれている」で落ちた(最深 12 cm)。胴を 144〜152px(腕を除く)にして、腕の中心を外へ 0.17 m に置くと通った。肩の斜めの線は、胴の上の断面と腕の最初の 2 点の高さで合わせる(細くしすぎると首の横に抜けが 456px 出た)。
- **しっぽ(3D の中心線)**: 正面から (X, Z)、横から (Y, Z) を**同じ高さの行**で拾って 14 点を組んだ(後ろの絵で X を確かめた。付け根は後ろの絵で体の底の中央から横へ出る)。半径は輪郭を引いた 0.027 → 0.0155。後ろの絵と重ねると、先の近くの X が 0.01 m 外にずれたので、上の 4 点の X を内へ 0.01〜0.015 動かした。正面だけで推測すると、付け根の道(後ろの絵で見える「体の底の中央から横へ」)が分からなかった。

- 開いた板(当て布)は use_hole_tolerant で引き、刃から来た面を材質で見分けて消す。
- 耳と合わせた後の頭に穴をあけると、重なった部分が合わさって耳の殻の付け根まで消える。**耳と合わせる前の頭だけに穴をあける。**

### 輪郭の殻は、穴をあける前の頭から作り、切らない
- 穴をあけた頭から殻を作ると、切り口の細い三角の法線が乱れて、口の角から黒い棘が 25 mm 出た。
- 殻を口の形に切り抜くと、横から前歯が輪郭の外(背景の上)に出て、判定役に「ほとんど見えない」と言われた。
- 切らない殻なら、正面からは手前の面が裏向きで描かれず、横からは絵と同じく前歯の前を輪郭の黒い線が通る。

### 前歯と穴の中
- くさび形の鼻づらでは、穴が左右へ抜けて、横から前歯の後ろに背景が透ける。**前歯の後ろに黒い塊(正面からは前歯に隠れる幅)を置いてふさぐ。**
- 前歯の前の面は鼻づらの面と同じ高さ(前へ出すと輪郭の線を切る)。後ろの面は上で 11 mm・下で 1 mm(横から下向きの三角)。黒い縁(殻)は 2.5 mm(1 mm だと白い口元に埋もれた)。
- 前歯の材質は地の色 0・発光 1(光の向きによらず絵の白)。横の壁は下を向くので、ほかと同じ材質だと灰色になり、白く写る所が上半分だけだった。
- 横の絵の前歯は正面の絵より縦に長い(横 341〜357 px、正面 338.5〜351 px)。**前歯を下の唇の黒い縁(1 mm)の後ろへ 5 px 伸ばす**と、正面は絵の形のまま、横は絵のように縦に長くなる。
- 人中の下の端が穴の上へ垂れると、穴のあいた鼻の板を内側と数えて検査 ③ に落ちた(深さ 4.7 mm)。穴の上の縁の手前で止める。
- 歯ぐきなどの小さな塊は、ほとんどが前歯と頭の中にあると「飲まれている」(6 割より上)で落ちる。頭に合わせる(join)。

### 口のシェイプキー(話す・表情)
- 静かな時の板は穴の下の縁の細い帯(0.8 px)。面積 0 にしない(法線が無くなる)。
- 開く・広げる・o は、穴の外へ出る所だけを覆い、穴の縁に 3 px 重ねる(広げた口の角の欠けを消す)。**口の形全体を覆うと、板が前歯の前に来て話す間は前歯が隠れた。**
- 板の点は面の法線の向きでなく、真っすぐ前へ置く(前への量 = 距離 / |法線の y|)。法線の向きだと、正面から見て穴の縁より 1 mm 下にずれ、桃色のすき間が出た。

### 下見と流し方
- **CPU だけの光線の下見**(build_w6/preview_rt.py。材質の発光の色で塗り、殻は裏向きの面を飛ばす)で、横と正面の口元を 5 秒で見られる。物ごとの色の地図(idmap.py)で、どの部品が見えているかが分かる。GPU の札が空くのを待たずに形を決められた。
- 判定役に見せる横顔のアップは、全身の写真の 4 倍の拡大だとぼやける。**同じ 12 m から頭だけが入る画角で撮る(顔の望遠、face_090.png)。**
- 作業フォルダの相対パスを、リポジトリへ cd する台本に渡すと、出力がリポジトリの中に作られた(すぐ消した)。台本には絶対パスを渡す。
- 既定の値だけで組んだ model.glb の sha256 が、取り付けた物と同じかを確かめてからコミットする(今回も一致)。

# 目と口がシェイプキーのキャラ(ようこそくん・ロボくん)の 1 周と、SVG の元の絵で見つかった知識(2026-11-06)

(元の文のまま)


- **1 周の道具**: `run_built.sh` は顔の表(`f01`・`b03_rig`)の道。目と口がシェイプキーのキャラは `sh creator/pipeline/run_groups.sh <id> <作業フォルダ> <元の絵.png>`(builder → `b07_rig_groups` → 8 方向 → 動きの姿勢)。builder は `work=<作業フォルダ>` を受け取る。pk01 は `<作業フォルダ>/rig/` の形を読むので、`rig2` を `pkin/rig` に写して渡す。ロボのような樹脂は `pk01 --no-fur`。`b06_posecheck` に、`only` に無い動き(`think` など)を渡すと全部落ちる。
- **輪郭の重なりを測るとき、元の絵の足元の影と白い字・ハイライトを体と数えない**。影を体に数えると IoU が 0.867、数えないと 0.979(`s03_compare_core.silhouette` に、色味のない明るい灰色を外す + 穴埋めを足した)。
- **小さく丸い胴のたすき**: `W.tilted_loop`(平面)は、傾きが急だと「z を平面の式で更新するくりかえし」が行ったり来たりして、体に当たらない高さへ飛ぶ(角度 81 度で例外)。二分法に直した。それでも、前の道の傾き 32° の平面は、腰の横で胴の底より下へ出る。**前は測った道、背中は端の高さから反対の端へ `smoothstep` で戻す閉じた 1 本の道**を builder で作ると通った。
- **腕と肩の抜け**: `W.limb` は付け根を面の外へ出して、小さな丸い胴だと肩に抜けが残った(S05 の抜け 340 px まで減って 0 にならず)。**太さが一定の `P.tube`(胴の中の点から手へ)+ 手の楕円体を `P.join` で 1 つにする**と、抜け 0・IoU 0.983 になった。肩の球を足すと、かえって別の穴(囲まれた所 194 px)が出た。
- **たすきの埋まり(m03)**: 帯が頭・腕に 0.5〜1.0 cm 食い込んで NG。`over`(帯が腕にかぶる)を両腕に付けるとはみ出す。**手の位置を元の絵より 10px 外へ**(胴の縁に手が重なっていた)、`over=[片腕]`、`under=[頭, 両腕]` で通った。幅を 0.9 倍に絞る手は、見た目が変わり、判定役が「太い」「細い」と割れた。
- **ロボの m03(「ほとんど体に飲まれている」)**: 画面・アンテナの軸・首・ボタンが NG。**ほかの部品に隠れた部品は、飲まれる比率が 0.6 を超える**。直し方: 画面は厚み 0.044 → 0.020 にして頭の前面より 4 mm 手前に、軸は両端が玉と頭に 3〜5 px だけ入る長さに、首は 20px の短い円柱、ボタンは胴の面から 3 mm 手前に中心を置く(埋まり 0.46 で通った)。
- **ロボの面(板の頭・画面)**: 頭は `superquadric` の指数 (0.3, 0.3)(角の丸い四角)。画面は同じ指数の薄い板。角の丸みで頭の前面が 4〜6 mm 引っこむので、画面の中心は頭の前面より少し手前に置く。
- **体の下半分だけ別の色(パンツ形)**: 胴を高さで切って別の部品にせず、**面ごとに `material_index`**(面の重心の高さで 0 / 1。腰の線は中央をわずかに低く)。形が 1 つのまま、境が正確。
- **ブラウザの撮影は GPU だけ**: `shot_browser.mjs`・`shot_eye.mjs`・`test_look_drift.mjs`・`web_talk_check.mjs`・`web_talk_record.mjs` は `--use-angle=d3d11` で描き、描画役の名前が SwiftShader など CPU なら止まる(`creator/skilltest/gpu_only.mjs`。`CHECK_GPU=1` は付けなくてもよい)。`check_all.sh` は GPU で 10 秒ほど(CPU 描画では数分だった)。メイン PC では、先に `machine_lock`(`--kind gpu --vram 3`)と `gpu_lock` の札を取る。
- **web_talk_check で声を作らない**: サーバーを `env -u ELEVENLABS_API_KEY -u ANTHROPIC_API_KEY` で起動すると、「読み上げ: なし」(字幕と口パクだけ)・仮の頭脳で、口・表情・動きを確かめられる(声の生成の費用が出ない)。

## 部品の寸法は元の SVG から(2026-11-06 夜、みかんの口が「鼻」に見えた件を測って直した)
- **原因**: builder の口と目の数字を、設定の文書の部品表(古い値。口 幅 74・高さ 32、目 71×97)から取っていた。元の SVG は描き直しの後で、口 88.2×45.9px・目 81.9×111.3px(最終の画素)。口は小さな楕円を下へ細らせた形(`taper=(0.22, 1.0)` で見える幅は半径の約 0.65 倍 = 約 52px・上が丸い)、舌の桃色は上の端(`mz + R(9)` は「上」。Z は上向き)で、判定役の答え 6 つが「鼻」「口が無い」になった。
- **測り方**: 元の SVG の `<g id="char">` の `transform`(例 `translate(627 1000) scale(1.05) translate(-627 -930)`)を部品の座標に掛けて最終の画素に直す。builder に `svg_px(x, y)` を置き、D に「SVG の数字 → 変換」の形で書くと、出どころが追える。半径は倍率だけ掛ける。測ったら PNG の画素でも確かめる(暗い色の塊の外接箱。口 86×43px で一致)。
- **開いた笑い口(D の形)の作り方**: 元の SVG の口は、両端が角の 2 次ベジェ 2 本 = 放物線(x = 中心 + 半幅×s、y = 角の y + 下がり×(1 − s²)、下がり =(制御点の y − 角の y)÷ 2)。この 2 本で囲んだ格子(列 24・行 8、両端の角は 1 点の扇)を作り、**体の網に正面から光線を当てて**(`BVHTree.ray_cast`)面から 2.5mm 手前に前の板、1mm 奥に後ろの板、縁に壁(前の板とは点を分けて、前の板のなめらかさを壁に引っぱらせない)。舌は「舌の楕円 ∩ 口の形」の格子で、前の板のさらに 0.6mm 手前。シェイプキーは、深さ(下の縁)と幅の倍率を変えた同じ並びの点(`mouth_open` 深さ×1.8・`mouth_wide` 幅×1.3・`mouth_o` 深さ×1.3 幅×0.5)。口を開くほど舌の見える所が増える。見本: `creator/builders/mikan.py` の `mouth_mesh`。
- **結果**: `m03` の口 埋まり 0.425・面の近く 1.0(浮きも飲まれも無し)。正面の絵で、目の間の長さを 1 とした比が 口の幅 元 0.518 → 前 0.309 → 後 0.521、口の高さ 元 0.259 → 後 0.255、目の幅 元 0.494 → 前 0.404 → 後 0.473。判定(`j01_judge.py --part 口`)は「鼻」「口が無い」0/6、同じキャラ ○、口の問いは Sonnet 3/3 はい・Haiku 0/3(元より大きい)。
- **判定の比べの絵の癖**: `j01_judge.make_sheet` は元の絵を紙(余白ごと)で縮めて並べるので、元のキャラが 3D の正面より小さく写る。Haiku は絵どうしの大きさをそのまま比べて「口が大きい」と言うことがある。割合は数字(上の比)で確かめ、数字が合っていれば、判定は記録に残して繰り返さない。
- **体より手前の部品は、遠近で少し大きく写る(推測)**: 体の前の面は体の中心より約 0.33m カメラに近い。目と口はほぼ同じ深さなので、比べるときは体の幅ではなく「目の間の長さ」を物差しにした。

## 落書き風の絵(太い黒い縁・平らな塗り)を 3D にした作業役が見つけた穴(2026-11-06 夜、機械で描いた試し絵)
- 太い黒い縁は `P.outline`(裏返しの殻)で作れる。**殻に `surface_only` を付けないと、`m03` が本体を「飲まれた」と落とす**(殻が本体を包むため)。付けると検査の「体」にも「部品」にも数えない。
- 落書きの平らな色は、ブラウザの陰影で下が暗く濁る(判定役が「色が違う」)。作業役は builder に `flatten`(拡散を絞って発光を少し足す)を自作し、上 G 240・下 188 → 上 216・下 194(元 214)に近づけた。材質で平らな色を作る道具はまだ無い。
- 手の無い絵は手を足さない(wave は胴の傾きだけ)。足と口の浮きは、極小の球を体へ沈める回避(上の「目と口の浮き」)で通した。

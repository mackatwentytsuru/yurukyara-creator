(この「案 D」は形の案。上の「毛足の画像(案 D)」とは別の話。)三面図の輪郭に面を合わせると、3 枚の絵が 1 つの立体として食い違う所(顔の前のくさび)で面が曲がり、斜めから顔がへこんで見えた。D は絵の輪郭に面を合わせず、式の形だけで組んだ(比率・顔の大きさ・色は案 C の組み立てを測った数字)。判定役(作った者と別の文脈の Claude。Haiku と Sonnet で、左右を入れ替えて 2 回とも勝てば勝ち)は、正面 = D、斜め 35° = なめらかさは D・かわいさは C、60° = 引き分け、横と見上げ = C(顔の読みやすさ)、後ろ = C、手をふる = D と答えた。「どの角度でもはっきり良い」ではなかったが、のちに本人が「D はもうこれで十分」と選び、D を `characters/norrie` の 3D にした(id・骨と骨の名前・モーフの名前・人格・声・2D・character.json は変えない)。元の絵との輪郭の重なりは 正面 0.873・横 0.845・後ろ 0.870(頭を大きくした案なので、元の絵より下がる)。

### 道具 `m04_round` と組み方
- **形**は、楕円体・超楕円体を「やわらかい和」でつないだ式。**網**は、立方体をふくらませた四角の格子を、形の中の 1 点から光線で面に載せる(極が無く、四角の大きさがそろう)。その点から見て星形の形なら、へこみも穴も出ない。光線が一度出て入り直した数を数えて 0 を確かめる(組み立ての報告の `head_reenter`)。
- 腕・しっぽはねじれの少ない枠の管、耳は先の丸い円すいの断面を回して平たくした形。仮面・鼻・ほお・口・おなか・背中の帯は、2D の輪郭を同じ式の面へ光線で載せた薄い板(持ち上げは式の法線の向き)。
- 頭 = 頭の丸(超楕円体 n 2.4)+ 下のほお + うなじ + ほおのふくらみ 2 つ + 鼻づら、を 1 つの式に。斜め 30〜60° でえぐれが出ない。
- **口は「同じ格子の数字違い」でシェイプキーにする**: 列 × 行の格子(上の縁 = 両端が上がる笑いの線、下の縁 = U、端はとがる)を、幅・高さ・口角の数字だけ変えて作ると、点の数と順が同じなので、そのまま `mouth_open`・`mouth_wide`・`mouth_o` になる。大きさは 2D の口を測った数字(幅 77 px・口角が真ん中より 9 px 上・真ん中の高さ 30 px)を頭の 1.12 倍に。上が平らな口は、ふだんから叫んでいるように見えた。真ん中と輪の円板にすると、口角を上げた三日月では真ん中から見えない所ができ、板が裏返る(星形でない)ので、格子にした。
- **板の輪は縁の近くに寄せて多めに(ease 0.7)**: 曲がりの強い所(胴の下・ほおのふくらみの上)では、粗い輪の三角形が面の下にもぐり、下の黒い縁の板や茶色の面が「黒い点」「ぎざぎざ」で透けた。仮面 7 → 11 輪、おなか 8 → 14 輪で消えた(三角形 55,920 → 59,664)。おなかの黒い縁は、胴の下へ回りこむ所(z 0.10 より下)で太さを 0 まで細らせる。
- **背中の帯**: 同じ幅の帯と太い芯は、白い縁どりの「すき間」に見えた。帯は両端の 16% で 0.45 まで細らせ、芯は帯の 0.4 倍・(1 − |2t − 1|⁴)^0.5 の太さにした。D の頭は後ろから見ると幅の広い角丸の箱で、頭と胴の境に横の線が出る(積み木に見える)。直すなら、首を細くして、うなじと下のほおを後ろで丸く細らせる[未]。後ろ頭の下の角を、けずる楕円体(`cut=True`、左右 x ±0.215・y 0.01・z 0.60、半径 0.09 × 0.12 × 0.085 の 1〜1.25 倍、つなぎ 4 cm)で丸め、胴の「首の後ろ」の横の半径を 0.115 → 0.090 にする試しは、正面は変わらず、めり込み 0・背中の帯の外れ 0 だったが、後ろ・斜め後ろ・横の見た目の差は小さかった。はっきり良くするには、頭の丸そのものを後ろだけ丸くする必要がありそう[未]。
- **布の版**: 今は model.glb を作り直さず、画面の「しつかん」の ぬの で見る(render-device の しつかん の節)。まるい部品の形はそのまま「ぬいぐるみ」に見えた。輪郭の殻(材質名 Outline・節の名前 `ol_*`)は しつかん が隠す。仮面とおなかの黒い縁の板(Ink)と、目の光の材質 `CatchWhite` は顔の部品として元のまま残る(全部外すなら、その板も外す)。前にあった別の線の `m_real_materials.py` と `?real=1`(材質を GLB の側で置きかえる試し)は、開発の木に無い。
- 頭のすき間(幅 390・7 歩の札を開いた時)は、案 C も D も 48 px(5.7%、決まり 50.6 px)で同じ。キャラの形ではなく、画面の枠の決まりの問題。

### 横顔の取り引きと、目が横から見えない件
- 頭を丸くすると、横から見える顔が減る。鼻づらは「頭の横の面より前へ出た分」しか横から見えない(頭の横の面が、鼻づらの横を隠す)。鼻づらの中心を 2.7 cm 前へ出す(y −0.345 → −0.372、奥行きの半径 0.086 → 0.092)と、横からクリームの鼻づらが読めた。正面の絵は光線で貼るので変わらない。
- **いちばん大事な学び**: 目が正面を向いた面に載っていると、**正面から見た目の輪郭が、頭の面の上の目の場所を 1 つに決めてしまう**。だから「正面の見た目を一つも変えずに、横から目を見せる」ことはできない。動かせるのは (1) 目の正面の輪郭(外へ広げる・外へずらす)、(2) 目のふくらみ、(3) 頭の面そのもの、(4) 前をふさぐ物(鼻づら・ほおのふくらみ)、(5) 輪郭の殻、の 5 つだけ。D では (1)(2)(5) を少しずつ使った。
- 目の軸を外へ寄せる(面の向き + 正面 × 0.2 + 外 × `EYE_OUT`)。輪郭は軸の向きから丸く見えるよう広げるので、目は頭の丸みに沿って横へ回りこむ。0.9 では正面の目が横長の楕円になった(作り直しに近い)→ 0.65 にして、目の中心を外へ 4 mm(x 0.052 → 0.056)、横の半径を 0.030 → 0.028 に戻した。ふくらみは 3.6 → 6 mm(6 mm が上限の目安)。アプリの寄りの横顔(カメラ 1.6 m)では輪郭に小さな黒い目と光が出る。**ただし全身の横(カメラ約 2.5 m)ではまだ見えない**: 横から見える目は輪郭のすぐ内側の幅 1〜2 cm の帯だけ(目の内と外の端の奥行きの差)で、全身では数画素になり、黒い輪郭の線に溶ける。目の中心を 0.064〜0.076 まで外へ出す案も試した(めり込み 0)が、0.076 でも小さな黒い点が出るだけで、正面は離れ目になる → 顔が変わるので本人に聞く[未]。丸い頭で横から目をはっきり見せるには、目を頭の横の丸みの上(正面から見て x 0.10〜0.15)へ置くしかない(球の上で目の内と外の端の奥行きの差が 4.5 cm になる所)。
- 横から見ると、ほおのふくらみが鼻づらの前に重なる所に、頭の輪郭の殻(11 mm)が太い黒い線として出て、白い顔に食い込んでいた。殻の厚みを、顔の前(y が −0.26 より前、z 0.60 より上)だけ 0.45 倍までなめらかに薄くした。正面から見た頭の横の輪郭とあごの線は 11 mm のまま。
- **落とし穴**: `implicit_shell` で殻を作ってから差しかえると、前の殻の物が場面に残る(骨のグループが無いので動かず、おじぎで頭の後ろに黒い玉が出た。三角形も 4,800 増えた)。最初から自分の殻を作る。差しかえた後は、組み立ての報告の三角形の数が前と同じかを見る。

### 動きの直し(おじぎ・手をふる・脇)
- **おじぎで白い足が体から離れる**: 体を骨の位置(高さ 0.34 m)のまわりに 30° 傾けると、丸い胴の下が後ろへ 17 cm・上へ 3 cm 逃げ、床に残る足が前に浮いて見えた。体は足の上の低い点 P = (0, −0.08, 0.05) のまわりに傾ける。骨を t = R(at − P) + P − at だけ動かせば同じ(at = 体の骨の位置)。根の沈み 2 cm は 0 に(足が床に入らない)。仕組みは b04 の `motion.bow = {"body", "head", "drop", "pivot"}`。この欄の無いキャラは前のおじぎのまま(ほかのキャラの動きは変わらない)。
- **おじぎの目がつり目に見える**: 頭が前へ倒れて上から見ると、丸い頭の上の目は、外の端(頭の奥へ回りこむ側)が高く写り、つり目のきつい顔になる。体 30 → 22°、頭の足し分 14 → 4°(合わせて 44 → 26°)にすると、丸いやさしい目のまま、おじぎに見えた。
- **手をふるで上げた腕が細く、付け根が離れる**: 大きなあごに当てないため肩を外へ 10 cm ずらしていたので、付け根が体の外へ出て、肩の端の半球が腕の下にこぶのように見えた。肩は外へ 6 cm・**下へ 7 cm** ずらすと、上げた上腕があごの下を通り、付け根は体に付いたまま(上げる角度 145 → 135°)。腕は付け根から先まで 1.12 倍に太く、肩の端は 0.35 → 0.40 と少し丸く。肩の端を 0.45〜0.6 まで丸くすると、頭を反対へかしげた時に、下ろした方の腕の肩があごに当たった(めり込み 24〜68 三角形)→ かしげ 6 → 4°。
- **手を上げると脇がなくなる**(本人の指摘): まるい部品の胴は、肩の丸(x 0.118・z 0.505)と腰の上の丸のあいだ(z 0.40)で、横が 4〜5 cm くびれていた。ふだんは下ろした腕がくびれを隠すので、正面の絵と比べる点検(`check_all` の ④)でも、立ち姿の 8 方向の写真でも見つからない。腕を上げると、くびれが「腕の下のこぶ」と「脇のへこみ」に見え、正面と斜め(腕の側から 35°・60°)で脇の厚みがなくなった。直しは、くびれの横だけを埋める楕円体を左右に 1 つずつ(中心 x 0.125・y −0.045・z 0.405、半径 0.075 × 0.110 × 0.085、つなぎ 6 cm。`ND_SIDE_RX` などで試せる)。前と後ろは胸の内に収め、ふだんは下ろした腕の陰に入るので、立ち姿と 2D との比べは変わらない。0.055・0.065・0.075 の 3 案を並べて組み(1 回 11 秒)、アプリで撮って、いちばん埋まる 0.075 にした。網は四角の格子なので、三角形 59,664 も GLB の大きさも同じ。斜め 60° では、腕の付け根と胴が交わる所に、輪郭の殻の細い線が 1 本残る(腕が胴に入る所の線。形のへこみではない)。
  - **学び: 腕を上げる動きのあるキャラは、腕を下ろした形の点検だけでは足りない**。手をふるの一番上(1.2 秒)と上げはじめ(0.8 秒)を、正面・斜め 35°・60° の左右で撮る(本物のアプリ・GPU で `c.play('wave')` を 1/60 秒ずつ進める)。腕を外した胴の正面の輪郭が、上から下へ「細くなってまた太くなる」所があれば、腕を上げた時の脇のへこみになる。
- **スマホ 390 × 670 の頭のすき間(7 歩の札を開いた時)は、キャラの形では直らない**: D は 40 px で、決まり(画面の高さの 6% = 40.2 px)に 0.2 px 足りない回があった(C は 41 px)。耳を 6〜7 mm 下げて 3 回測ったが 40 → 41 → 40 px のまま。アプリはキャラの高さに合わせて写すので、立った時の高さは 202〜203 px で変わらない(耳を下げると、その分だけ大きく写る)。すき間を決めるのは画面の枠の決まりと、待機の動きの小さな上下(体の伸び 1.8%)と、測る時刻のずれ(±1 px)。耳は前の高さに戻した。耳の殻だけ 8 mm に薄くすると、正面で耳の内の付け根と頭の間に背景の小さなすき間が囲まれ、`check_all` の ④(元の絵と比べた抜け)が落ちた(1 か所 210 px、囲まれた所 61 px)。

### 点検の流し方
- **めり込みの数え(2 コマおきに BVH の重なり)を門にする**: 腕と頭・顔の部品、頭と蝶ネクタイ、腕どうし。動き 5 つ全部 0 になる組だけを残した。数字の案は環境変数 `ND_<名前>` で 3〜4 つ並べ、`blender -t 3` で 1 つの CPU の札の中に同時に流すと、組み立て・骨と動き・めり込み・Cycles の CPU の下見(顔 7 枚・動き 6 枚)まで 1 回 25〜30 秒。
- 流し方: CPU の札で builder → b07 → めり込みの数え(10〜15 秒)と Cycles の CPU の下見。Blender にはドライブ名からの絶対パスを渡す(相対パスだと、下見の絵がどこにも書かれなかった)。GPU の札は 1 本(取り付け → アプリの写真 → 頭のすき間 → 三面の重なり → `check_all` → 姿勢 → 画面ありの試験 617 件、約 2.5 分)。既定の値だけで組み直すと、model.glb と動き 5 つの sha256 が一致した(2 回組んで一致を確かめる。三角形 59,664、GLB 2,162,336 バイト = C の 1,917,932 の 1.127 倍。決まりは 1.2 倍まで)。
- アプリの写真は、案 C と D を同じカメラ・同じ時刻のコマで撮る(作業の木の `characters/norrie` を一時 C に戻して撮り、D に戻して撮る。終わりは必ず D に戻す)。全身の 8 方向は、下からのカメラを床より下に入れない(足元の高さから見上げる)。
- 画面ありの試験(`YC_BROWSER_TESTS=1 npm test`)が `test/stt.test.mjs` で 5 分止まったことがある(偽の聞き取りの係が返らず、ほかは全部通っていた)。自分の試験の PID だけを止めると 653/654。TEMP と TMP を空のフォルダにして流し直すと 654/654 が通った(一時フォルダの中を数える試験なので、共有の一時フォルダが重いと遅くなる、と読んだ。1 回の比べ)。

## 本物らしい材質は画面の しつかん で当てる段と、変換の絵から組む入口(第 12 波 b。2026-11-08 に今の仕組みに合わせて直した)
- builder が書く材質は「地の色 = 絵の色 × 0.22 + 発光 = 絵の色 × 0.92」の平らな塗り(`flat_mat`)で、写真のような光では発光が光を消す。**この形は builder 側で変えない**。画面の しつかん(`web/src/stage/shitsukan*.js`)が、差しかえる時に絵の色を「発光 ÷ 0.92」から戻し、布(sheen)・毛(布 + 毛の殻)・つるつる(クリアコート)の材質にして発光を 0 にする。作った後の材質の置きかえは しつかん の仕事で、使う人は上の段で選ぶ。数字と落とし穴は render-device の「しつかん」の節。
- 輪切りの形(`P.loft`)は、本物らしい光で輪の段が縞に見える。しつかん は体の部品の法線を 8 回ならして消す(向きが 40° より違う所はまとめない)。builder 側で直すなら、輪の数を増やすか、法線をならしてから書き出す。
- 作る道から 3D を頼まれた時は、受け渡しの紙(`creator/work/<id>/convert/handoff.json`)の変換の絵から組む。形は変換の絵、色は元の絵、目じるしは settings.md のとおりに残す。`looks.3d.material` が紙に書いてあれば、そのまま character.json に残す(画面の しつかん の既定になる)。紙の欄と手順は make-character の「変換の絵から組む」。

### 三面図から組む手順(効いたもの)
- **縮尺・枠をそろえた 3 枚**(S=1040、FY=1076、透明の地)なら、`m02_shot.py --views front,left,back --size 1137 --center 0,0.488 --scale 1.0933 --transparent` で元の絵とそのまま重なる。重ねの数字は、透明さの面(alpha>128)どうしの IoU と外接箱の中心・幅・高さを自分で数行で測ると、s03 を待たずに毎回見られる(`build/iou.py`)。**1 周目から IoU 正面 0.959・横 0.953・後ろ 0.954**。最後は 正面 0.956・横 0.960・後ろ 0.948(s03_compare の正規化では 0.956・中心ずれ 0.0px・幅差 0.8%・高さ差 0.0%)。
- **断面の読み方**: 高さごとに、正面の絵の左右の端 → 半幅 rx、横の絵の前後の端 → 中心 cy と半奥行き ry。ただし**元の絵の黒い縁(約 7px)は外形に入っているので、断面は 7px 引き、両端の z も殻の分(0.007m)内へ寄せる**(`secs_from`)。前かがみは cy の傾きだけで出る(頭 cy=-0.2、胴の下 cy=+0.02)。頭と胴を別の `P.loft`(頭は 16 断面、胴は 20 断面、n=36、refine=2)にした。ぶつかりは首の所で、胴の上の端は頭の中に隠す。
- **腕のある側の胴は細く**: 正面の外形の半幅(前の絵で 211px)は腕込み。胴を同じ半幅で作ると、腕の管が胴の中に 85% 入って m03 が「飲まれている」で落ちた(最深 12 cm)。胴を 144〜152px(腕を除く)にして、腕の中心を外へ 0.17 m に置くと通った。肩の斜めの線は、胴の上の断面と腕の最初の 2 点の高さで合わせる(細くしすぎると首の横に抜けが 456px 出た)。
- **しっぽ(3D の中心線)**: 正面から (X, Z)、横から (Y, Z) を**同じ高さの行**で拾って 14 点を組んだ(後ろの絵で X を確かめた。付け根は後ろの絵で体の底の中央から横へ出る)。半径は輪郭を引いた 0.027 → 0.0155。後ろの絵と重ねると、先の近くの X が 0.01 m 外にずれたので、上の 4 点の X を内へ 0.01〜0.015 動かした。正面だけで推測すると、付け根の道(後ろの絵で見える「体の底の中央から横へ」)が分からなかった。
- **背中の筋**: `W.wrap_band(.., [(180, z_top), (180, z_bottom)], width=0.058, thick=0.003, clearance=0.001, taper=0.2, taper_min=0.05)` を 2 本(クリーム 0.058、濃い色 0.027 を少し短く)。**厚みは輪郭の殻(0.007)より低く(合計 0.004〜0.005)**。高いと横から見て背中の輪郭線が筋の色で切れる。横から見ると、背中の輪郭のすぐ内側にクリームの細い線として出て、元の絵と同じ見え方になった。頭と胴にまたがるので、**1 つの帯の頂点を高さ(首 z=0.63)で `head` と `body` の頂点グループに分けた**(2 本に分けるより模様がつながる)。taper を 0.5 にすると細いレンズ形になり元の「長く太い帯」と違う。0.2 にした。

### 顔・おなかは「行ごとの範囲の板」で、元の絵の境の線に合わせる
- **顔の仮面(クリーム)・おなか(花瓶形)・鼻(楕円)・口(黒い所)** は、元の絵の画素を numpy で測り(クリームと鼻の色を flood fill して行ごとの左右の端、口は列ごとの上下の端)、数字を builder の表に書いた。その点の格子を、頭(胴)の面へ**光線で載せる**(`plate`)。`P.superquadric` や頂点の色で描くより、境の線が元の絵にそのまま合う。仮面の縁の黒い線は、少し大きい黒い板(grow=5px)を 1.2mm 奥に敷いた。
- **面からの持ち上げは「法線の向き」にする**。-y 方向(正面へ)にずらすと、胴の下の横の急な面では板が面に埋まり、茶色い点が粒状に出た(おなかの横)。ヒットした三角形の法線(`bvh.ray_cast` の 2 番目)を使うと消えた。
- 大きな板(仮面・おなか)は**後ろの板を作らない**(三角形の節約)。小さな板(目・口・鼻)は 3〜4 mm 沈めた後ろの板を付けて閉じる。

### m03 と当て布・小さな板(新しい知識)
- **開いた板が重なっていると、`m03` の「埋まり」は偽の値になる**: 内外判定は光線が面を何回通るかの偶奇なので、板(開いた面)の上の別の板は「中」になる。鼻が埋まり 0.885、口が 1.0、腕が 0.72 になり、「ほとんど体に飲まれている」で 7 部品が落ちた(腕の最深 12 cm は、光線が胴ではなく開いた当て布を数えた偶奇の誤り)。直し方:
  1. **仮面・おなかの当て布(と、その黒い縁の板)に `ob["surface_only"] = True`**(スキルの「地の色の当て布」と同じ扱い。体にも部品にも数えない)。→ 腕の「飲まれ」が消えた。
  2. 鼻・鼻の線・人中・口・背中の筋は、**`--hug` に入れる**(面に沿う板なので「面の近く 8 割以上・深さ 4mm 以内」で見る)。
  3. 鼻は後ろの板を 4mm 沈めると最深がちょうど 0.4cm で落ちた。**2.5 mm に**した。
  - 目と口に `surface_only` は付けていない(浮きを隠すことになるため)。
- 三角形は、輪郭の殻を入れると倍になる。n=56・refine=3・板の列 44 では 70,732 だった。**n=36・refine=2・大きな板は前の板だけ・筋の seg=64・楕円体の seg=(24,14)〜(28,16)** で 35,372(model.glb 1.29MB、材質 9)になった。

### ブラウザの色(測った数字)
- 同じ材質の色でも、ブラウザではクリームが明るく飛ぶ。元の絵の画素 → 描く色: 茶 (80,63,62) → **(71,56,55)**(ブラウザで (79,64,63))、クリーム (242,231,224) → **(216,205,198)**(おなか 219〜232、足 243,229,219、しっぽ 216,204,195)、手袋の白 253 → **232**(ブラウザで 252,250,248)、緑 (38,152,104) → (34,142,97)。最初のクリーム (236,225,218) と白 253 では、判定の「色」が Haiku 0/3(「手と足先が純白に近い、おなかが飛んでいる」)。暗くしたあとは判定を参照。
- 黒い楕円の目(直径 約 0.03 m)は、こげ茶の頭の上でも、ブラウザの寄りで十分読めた(`browser_close.png`)。つやを上げる必要はなかった。

### つまずきの直し方(短く)
- builder が `RuntimeError: 面に当たらない` で落ちたら、その板の最後の行の z が、頭(胴)の端の断面の z(両端は殻の分内へ寄る)より外。端の行を落とすか、端の断面を少し延ばす。
- 耳を「尖った三角」にしようと `taper` をかけたら、`s05` の抜けが耳の上に 600〜700 px 出た(元の絵の耳は太く、先が丸い三角)。丸い楕円体(0.036, 0.034, 0.059)のほうが抜け 0。判定役(Sonnet)には「耳が丸くて小さい、元は尖った猫耳」と言われた(判定を参照)。
- 札の待ちが長い(10 分前後)ので、builder・骨・8 方向・姿勢・三面撮影・pack・check_all を **1 本の sh(`full.sh`)にして札を 1 回だけ取る**と、1 周が約 5 分になった。

### 直し(耳と手袋)(2026-11-07、`creator/builders/norrie.py`)
- **耳**: 丸い楕円体を、**`P.loft` の断面の積み(耳 1 つ 9 断面・n=28・refine=2)**に替えた。断面は、元の絵の耳の輪郭(正面の左右の端・横の前後の端)を高さごとに測り、殻の 7px を縮めて `EAR_ROWS` に書いた。縁が縦・先が上の外側の角・内の縁が斜め、という三角が、cx と rx を高さで変えるだけで出る(loft は cx・cy を持てる)。耳の下の端は頭の中(py 175)に埋める。IoU 正面 0.956→0.960、横 0.960→0.963、後ろ 0.948→0.952。④ 抜けは OK のまま。残る差: 先の角が元の絵より少し丸い。
- **手袋**: 元の絵の手の**白い所の画素の重心と主軸**(正面は 重心 (474,737)・長軸 27° 下、横は (315,742)・39° 下)を numpy の共分散で測ると、楕円体の中心と向きが一度で決まった。`superquadric` の長い軸を Z にして `to_track_quat("Z","Y")` で向きを入れ、縦の指数を 0.8 にすると、卵でなくミトン(筒に近い丸い先)になる。**正面の輪郭には手が出ない(胴の中)ので IoU では測れず、白い画素どうしの重ねで見る**。
- **袖口の浮き**: 輪を袖の端の外に置くと、輪の穴が手の断面より大きく、中が暗く見えた(浮いた輪)。直し: 袖の最後の点を手首(手の中心 − 向き × 0.034)へ移して手と同じ軸に乗せ、輪は袖の太さに被せる(`ring` の `sq=0.45`・squash 1.7 の角丸の短い帯、外半径 0.0355、中心を袖の端の 0.004 手前)。腕の最後の点を動かしても、正面の輪郭は胴の中なので IoU は動かない。
- 材質は rough 0.85・spec 0.1・metallic 0。ブラウザの寄りで、つや消しの白いミトンに見えた。三角形 36,876・model.glb 1.34MB。
- 判定(1 回だけ): 同じキャラ 3/3・3/3 ○、**色 0/3・0/3 ×**(今度は「おなか・顔の下が灰色がかって暗い」。前の回の「白く飛ぶ」と逆向き。色は触っていない。色の判定は境で割れる)。この判定の問いは形を聞かない(`--part` なし)ので、耳・手の形への評価は出ていない。
- 残り: 手の白い面が元の絵より少し下・内に寄る(正面)。袖口の帯が手と別の白い輪に見える(横)。

### 直し(目)(2026-11-07、`creator/builders/norrie.py` の `build_face`)
- **原因は測って確かめた**: 目の所の頭の面の法線は (±0.23, −0.89, +0.39) で、**上へ約 23°・横へ約 13° 傾く**(builder で `surf.n` を印字)。面に沿わせた平たい板は、正面では丸いが、下から見ると (面の傾き + 見上げ)で 40° 前後ずれ、cos で縦が 0.7〜0.8 に潰れた。「眠そう・いじわる」の正体はこれ。
- **直し**: 目を黒い楕円体(半径 横 15.9 px・縦 17.4 px = 0.0153・0.0167 m、奥行き 4.5 mm、`P.superquadric` seg (24,14))にした。元の絵の黒い目は、numpy の連結成分で**直径 32 px・中心 (521.4, 211.7)・(615.6, 211.7)**(前は 39×43 px の板で大きめにしていた)。骨 eye_L・eye_R、シェイプキー `eye_blink`(zc へ 0.08 倍に潰す、値 0)は前と同じ。GLB のメッシュ重みは eye0=[0]・Mouth=[0,0,0]。三角形 36,876 → 37,100。
- **向きと位置の決め方(効いた)**: 玉の軸を「面の法線(上 23°)」と「正面(0°)」の間の**上向き 20°**に傾け、赤道の輪(軸に垂直な円の 24 点)が頭の面より前に出る量の最小を**二分探索で −3 mm(下の縁を 3 mm 埋める)**にそろえて中心を前へずらした(`EYE_TILT`・`EYE_CLEAR`、環境変数で上書きできる)。ずらしは約 2.3 mm、中心の前の出っぱりは**約 6.3 mm**(輪を面に完全に出す 0.6 mm では 8〜12 mm 出て、横から飛び出す)。測った掃引(中心の出っぱり mm): 傾き 10°=12.4/10.2/8.5、16°=10.1/8.1/6.6、22°=8.1/6.3/4.9(縁の出し量 +0.6/−2/−4 mm)。
- **縦を 1.09 倍(17.4 px)**: 傾けて下の縁を埋めると、そのままでは横長(正面 44×39)になった。縦を 1.09 倍にすると**正面 43×43、見上げ(カメラ高 0.62 m、画角 24°)69×69、斜め 35° も丸い**。頭の下の端より低い 0.30 m(会話の画面より厳しい)では 63×48(0.76)に潰れる(残る)。
- 旧版(面に沿う板)の目の高さの正面は 44×39 に近かったが、見上げの絵が楕円に潰れた。**球にしても向きを面に合わせすぎると同じ**(傾き 10°・縁 +0.6 mm の 1 回目の試しは、下が埋まって「レンズ形」になり、先に直した)。
- 検査: 輪郭の重なりは前と同じ(正面 0.960・横 0.963・後ろ 0.952)、`check_all.sh` 全部 OK(③ 埋まりと浮きも、目に極小の球を足さずに通った)。
- 撮り方: `tools/eye_shots.mjs`(目の高さ・見上げ 0.62 m・低い 0.30 m・斜め・会話の遠さ・まばたきを 1 本で撮る)。ブラウザのまばたきは `window.__c.blink = 1`(`blinkTimer = 1e9`)で入り、`eye_blink` の影響 0.966(細い横線)。撮りは `check_all` の後に同じ GPU の札の中で続けると、札が 1 回で済む(`tools/eye_cycle.sh`)。
- 残り: `sad`(eye_blink 0.3)の絵は撮っていない(シェイプキーは同じ名前・同じ潰し方)。判定役(Haiku・Sonnet)には通していない。

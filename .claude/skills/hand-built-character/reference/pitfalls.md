# CPU の描画で撮らない(2026-11-06)

(元の文のまま。CPU の描画で撮らない・公開の前に・落とし穴)

- 画面なしの Chrome で CPU 描画(SwiftShader)の撮影を 2 本並べると、メイン PC の CPU が 100% になり、ファンが回り続けた。作る道のブラウザの道具は、今は GPU だけで描き、描画役が CPU なら止まる(`creator/skilltest/gpu_only.mjs`)。先に機械の札(`--kind gpu --vram 3`)と GPU の鍵を取る。

## 公開の前に

手元のパスと、提出に入れない道具の名前を消す(道具の場所は `creator/env.sh` と、リポジトリに入れない `creator/env.local.sh`)。消す部品は先に手元へ写し、よそから読まれていないかを確かめる。履歴は書き換えず、`python tools/history_check.py` で全コミットを点検し、見つかったら止めて報告する。

## 落とし穴(直し方つき)

- 骨に毎コマ回転を重ねるときは、先に「動きだけの値」へ戻す。three.js のミキサーは値が前と同じだと骨に書き直さないので、重ねたままだと回り続ける(視線で体が 173 度まで回った)。`creator/skilltest/test_look_drift.mjs` が数百コマ回して測る。

- パスはドライブ名から始まる絶対パス(`X:/...`)で渡す。相対パスや Git Bash の `/x/...` を Blender・Windows の python・node へ渡すと、絵が別の場所に書かれるか、できない(`check_all.sh` は自分でそろえる)。
- `m02_shot.py` を元の絵と同じ画素で撮る式: `--scale` = 絵の幅(px)÷ S、`--center` = ((中心 px − CX) ÷ S, (FY − 中心 py) ÷ S)。
- `s03_compare` と `s05_gaps` は、外接箱で大きさをそろえて比べる。手の先が少し大きいだけで、ほかの場所に抜けが出る。先に外接箱の幅を元の絵に合わせる。
- `s02_posesheet.py` は `pose_<名前>_<数>.png` の形だけを読む。

- まばたきで、平らにつぶした目玉の奥にヘルメットや部品が透けて「壊れたゴーグル」に見える → ふだんは点(見えない)で、まばたきで広がる肌色の円盤(まぶた)を、同じ名前のシェイプキーで足す。シェイプキーを作ったあとに基準の形を変えるときは、`mesh.vertices` ではなく `shape_keys.key_blocks['Basis'].data` を直す。
- 顔の面(体の表面に貼る面)の角が、体の丸い縁に当たると、角に四角い粗いにじみが出る(貼った面の角が丸い縁の外や急な坂に乗る) → 光線が当たらない点と、面の向きが正面から 55° 以上それた点を含む四角は作らない。面を平らな部分に収まる大きさにし、足りない分は表(顔の絵)の中身を大きくする。
- 光る点の目の大きさは、元の絵の画素 ÷ S で出したメートルから、点の数に直す(点の間隔 = 面の幅 ÷ 点の数)。小さく見えるときは、輪の半径・点の半径・光のにじみを足す。
- 布の羽根を、厚い板 2 枚重ねの「ひだ」にしたら、下の縁がぎざぎざに崩れた(試して止めた) → 1 枚で bend と flare を調整する。2 枚重ねるなら、厚みより位置のずれで足す。
- 輪(トーラス)を球の表面と同じ深さに置くと、半分埋まって「C の字」に見える → 球の最前面より前に置く。
- Blender の glTF 書き出しは、手続きの節点(Layer Weight など)を書けず、白く飛ぶ → 頂点の色(`gradient`)か絵だけ。
- OBJ を Blender に読むと物が 180° 回って入る → 回転を 0 に戻す(`b03_rig.py` のコメント)。builder が作る .blend には起きない。
- 手をふる・おじぎの確かめは、振りの位相が逆の 2 コマを並べる。動きの一覧は 1 コマ 560px 以上。
- Git Bash は、`--mount=/名前=...` のような引数の `/…` をパスに直してしまう → PowerShell の `Start-Process` で起動する。
- ブラウザが古い JS を使う → キャッシュなしのサーバー(`serve.py`)。

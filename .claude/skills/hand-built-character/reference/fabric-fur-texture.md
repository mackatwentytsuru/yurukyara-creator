# 布・ぬいぐるみの質感(ゆるキャラは布・ぬいぐるみ風が多い)

(元の文のまま。2 つの節を 1 つにまとめた)


質感の案を、同じ形・同じ光で並べて比べる場: `python`ではなく Blender で `creator/builders/_texture_lab.py -- <出力フォルダ> [R,G,B]`(A 平らな色 / B シーン / C 頂点の色+シーン / D 毛足の画像+法線 / E トゥーン / F 毛足+輪郭の毛羽)。Claude(Sonnet 5.5、新しい文脈、案の名前なし・順番を替えて 3 回、2026-11-06)に「どれがいちばんぬいぐるみに見えるか」を選ばせた結果: **D が 2 回、F が 1 回。A・B・C・E は 0 回**。つまり「シーンだけ(B)では毛足が出ない」は Claude でも同じ。

- **毛足の画像(案 D、ぬいぐるみに必要)**: `P.fuzz_material(名前, rgb, 画像の出力フォルダ, grain=0.16, normal_strength=1.6)` で、毛の線の重なりの画像(色+法線、継ぎ目なし。numpy だけ。AI なし)と、縁の毛羽(シーン)を持つ材質を作る。その材質を付けた物に `P.auto_uv(ob, tile=2.2)` で UV を付ける(立方体投影。tile が小さいほど毛が大きく見える)。GLB に画像 2 枚が入る(1 材質で約 1.2MB。大きいときは `size` を 256 に)。three.js でも読める。
- **輪郭の毛羽(案 F。今は使わない。ブラウザの毛の殻に替えた。下の「作業の既定」)**: `P.fuzz_shell(ob, rgb, 画像の出力フォルダ, thick=0.02, density=0.5, layers=3)` が、物を少しふくらませた殻を重ね、毛の点の画像(透明さで抜く)を貼って、輪郭をふんわり毛羽立たせる(殻の物の一覧を返す)。Claude の選び直し(Sonnet 5.5、3 回)では、F でなく D が 2 回、F が 1 回選ばれた(「F がいちばん」は Claude では再現しなかった。D・F は同じくらい、と読む。1 回ごとの理由は「D は毛足の繊維がはっきり」「F は縁がぼやけて毛羽立つ」)。書き出しは `alphaMode: MASK`(透明さを GREATER_THAN 0.5 で切る節点を、`fuzz_shell` が付ける)。頭など目立つ丸い部品にだけ付け、殻は 2〜3 枚、三角形が倍になるので予算に注意(`pk03`)。
- **シーン(案 B)だけでは、毛足は出ない。** 縁の明るさは出るが、桃の試験で全段が「毛足なし(つるつる)」と判定された。シーンは、毛足の画像の**足し**として使う。
- 頂点の色の濃淡(案 C)は、色のつながり(濃い縁・明るい中心)用。毛足にはならない。
- トゥーン(案 E)は、平らな色+輪郭線のキャラ向け(質感は出さない)。
- 毛足の画像は、1 材質につき 1 つの色。色の違う部分は、別の材質(別の `fuzz_material`)にする。色の濃淡が要る部品には、頂点の色(`Col`)と画像は同時には使えない(書き出しが片方になる)。

### ブラウザ(three.js)で見る色と毛足(11-02 夕方、測って分かったこと)
質感と色の判定は、**Blender の絵ではなく、ブラウザ(`creator/viewer`、web/ と同じ光)で撮った絵**で行う(`node creator/skilltest/shot_browser.mjs <ポート> <character.json の URL> <出力フォルダ>`)。見る人が見るのはブラウザだから。
- **ブラウザの色は、そのままだと元の絵の約 68% の明るさに沈む**(ひよこの体: 元 RGB 231,195,108 に対し 156,131,65)。three.js の光は、強さ 1 で白い面が約 0.32 にしかならず、Blender の太陽光より暗い。直し方は、**実行側で色の絵を発光にも貼って持ち上げる**(`rigRuntime.js` の `applyLift`、character.json の `lift`、既定 0.55)。これで 225,191,97 と、元の 97% に戻る。builder の色を明るく塗り直す必要はない(Blender で見る絵が明るすぎになる)。頬などの小さい面は、元の絵の色をそのまま使う。
- **毛足の画像は、向きがなめらかに変わる細い毛を、たくさん重ねる**(`fuzz_images`)。試した順: 1 画素の粒 → 砂壁に見える / 粒をぼかす → 革やオレンジの皮に見える / 毛の本数が少ない(1 辺 × 5)→ 引っかき傷に見える / 毛を 1 辺 × 24 本にして凹凸を弱める → 元の絵のフェルトに近づいた。法線の強さには 0.4 を掛ける(`FUZZ_NORMAL_GAIN`)。アップではまだ白い細い線に見えると言われる。
- **頬が茶色く沈む原因**: 色の絵を持たない材質に持ち上げが効いていなかった(`rigRuntime.js` を直した)。頬は `W.soft_patch` で作る。
- 7 体を直した結果(11-02): 判定は Claude 以外だったので数字を消した。Claude での取り直しは、結果表の「Claude の判定」の節(毛足 0/14 束、色 13/14 束)。毛足はまだ「粗い」「粒が強い」と言われる。
- **作業の既定(11-03。見比べはこれから。戻すときは、この行と character.json の例から `fur` を消し、`pk02` の検査を外す)**: ぬいぐるみは、部品に `P.fuzz_material` を付け、character.json の最上位に `"fur": {}` を書く。**`P.fuzz_shell`(Blender の殻)は作らない**。ブラウザでは隠され、三角形だけが増える。設定は書かない(太さ 0.4%、長さ 1.5%、明暗 0.25、根元 0.93 が既定値)。`pk02` は、毛足の材質があって `fur` が無いと ERROR を出す。Blender の絵には毛羽が出ない。質感はブラウザの絵で見る。
- **毛の殻をブラウザ側で重ねる(`creator/viewer/furShell.js`)**: character.json に `"fur": {}`。同じ形と骨を使い回すので GLB は増えず、骨とシェイプキーに付いて動く。顔の部品の周りは毛を短くする。**色の絵の筋が残ると傷に見え(flat 0.7)、消すだけだと樹脂に見える(flat 0.95)**。筋を消して、毛 1 本ずつの明暗(pile)とふわっとしたむら(cloud)をシェーダーで足すと、布に近づく。pile を弱めると「平ら」に戻る。根元を暗くした分は gain で明るさを戻す。**毛の太さはキャラの高さに対する割合で決める(`hairWidth`、0.4% が基準)**。UV の繰り返しで決めていた間は、毛が画素より細くなって消え、どう直しても「つるつる」と判定された。太さ 0.7% は粗すぎる。毛は短く密に(長さ 1.5%)、色の違う部品の境目では毛を短くする(青とクリームの毛が混ざって汚れて見えた)。判定はまだ安定して通らない(砂粒のように見えると言われる)。材質は部品どうしで共有されるので、部品ごとに暗くすると何度も掛かる。頬の当て布は、四角い網の全部で毛を短くすると四角い跡が出るので、丸の中だけを使う。
- 効かなかった: `alphaToCoverage` と抜きの線を下げる(面に白い虫のような線が出た)。
- **判定の決まり**(`python creator/pipeline/j01_judge.py <元の絵> <絵のフォルダ> <出力> [--part 部分] [--fur]`): 同じ絵を、別の文脈の Haiku 5.5 と Sonnet 5.5 に各 3 回見せ、2 回以上「はい」でその判定役の「はい」。2 人の両方で合格。同じ絵でも答えが変わることがあるので、1 回では決めない。**2 人とも同じ系統の Claude なので、独立した 2 人ではない**(Sonnet 5.5 は毛足と部分に一度も「はい」を出さず、Haiku は出した、という割れ方をした。割れたら、両方はいでないものは数えず、そのまま書く)。答えは「はい」「いいえ」の 1 語だけで、「ほぼはい」は数えず問い直す。判定の絵に文字や数字を入れない。**合格しても、使う人の目が優先**。使う人が選んだ見た目を既定にしてから、スキルだけの試験を回す。外の素材を使うときは、ライセンスを `docs/部品の一覧.md` に足す。
- 判定役は、毛足が強いと「ざらつき寄り(砂壁)」と言い、弱いと「つるっとしている」と言う。色が合うと、毛足の判定も「はい」に寄る傾向があった。Claude では、Sonnet 5.5 が毛足を 34 束すべて「いいえ」にした(厳しい側)。
- **布の写真の毛(`"fur": {"look": "fleece"}`。11-03 の試し。既定にしない)**: 半透明の毛先(`soft`)、縁の明るさ(`rim`)、布の写真の房(`photo`。`creator/viewer/assets/fleece`、Poly Haven「Polar Fleece」CC0)の組み合わせ。別の 4 体では 毛足 1/4 と、いちばん良く見えたが、スキルだけで作った 7 体では 毛足 1/7、色 6/7 で、いまの既定(毛足 0/7、色 7/7)と差がほぼ無かった(差はぶれの範囲)。撮り方を変えただけで、1 つの AI の答えが 3/3 から 1/3 に変わった体もある。**1 回の良い数字で既定を変えない。** 使う人が選ぶまでは、作業役に `look` を書かせない。
- 半透明にすると描く順が効く。内の層から順に描き(`renderOrder`)、頬の当て布は毛のあとに描く(`PATCH_RENDER_ORDER`)。順が違うと、頬の輪郭が崩れる。`rim` 0.6 は明るい縁の線が出た。0.25 にした。
- 全身の絵が小さいと、毛が画素より細くなって砂に見える。全身は元の絵と同じくらいの大きさで撮る。横に広いキャラは、高さではなく広いほうの幅に合わせて引く(手が切れた)。`shot_browser.mjs` がこの撮り方をする。
- **粒を数字で見る**: `python creator/skilltest/grain_bands.py <絵> <x,y,大きさ,頭の幅> …` が、細かさごとの粒の強さを元の絵と比べる。k_beak は面の粒の強さが元とほぼ同じなのに「砂粒」と言われた。残りの疑いは面より、輪郭の点や細い線と、全身の絵の小ささ。
- 毛の殻は 三角形 × (層 12 + 飛び出す毛 2)を描く。46,448 三角形の k_beak は約 65 万三角形になり、CPU の描画(試験の撮影)でブラウザが落ちた(Target crashed)。`shot_browser.mjs` は GPU の見張りを切って撮る(`--disable-gpu-watchdog`)。作るときは 36,000 三角形以下を目安にする。CPU が混むと 1 コマ数秒かかるので、撮影は順に 1 つずつ流す。

### 体に沿う部品・頬・くぼみの影(`creator/pipeline/m01_wrap.py`。`import m01_wrap as W`)
- **帯(たすき・ベルト・襟)**: `W.wrap_band(名前, [体の物], [(角度, 高さ), …], 幅, thick=…, mat=…, closed=False)`。角度は正面が 0、体の左(+X)が 90。光線で体の面に載せるので、細い・平ら・浮く、を防げる。UV は帯の長さ方向につながるので、文字の画像を貼れる。**帯は `superquadric` や `cloth` で近似しない。** 一周の帯は `closed=True` で、最後の点を重ねて書かない。体に当たらない道は例外で止まる(勝手な位置に置かない)。
- **頬の丸**: `W.soft_patch(名前, [頭], 角度, 高さ, 半幅, 半高, rgb, 画像の出力フォルダ, hardness=0.35, opacity=1.0, clearance=0.012)`。**硬い楕円の部品で頬を作らない**(ブラウザで茶色い丸になる)。毛羽の殻があるときは、clearance を殻の厚みの半分より大きくする。大きくしすぎると、斜めから見て輪郭の外へはみ出す(0.024 で出た。0.012 で消えた)。
- **腕・脚・耳など、体から生える部品**: `W.limb(名前, [体の物], 付け根の点, 先の点, 付け根の半径, 先の半径, mat=…, flare=1.3)`。**`superquadric` を横に置かない**(肩にくさび形の抜けが出た)。付け根の点は**体の中**に置く。線が体を出る所を測り、半径の 8 割だけ内側を付け根にして、面のあたりを太らせる。体に当たらない置き方は例外で止まる。骨の位置(`rig.json` の `at`)には `W.pivot_of(ob)` を使う。付け根の半径と先の半径はほぼ同じにする(差が大きいと、くさび形に見える)。 **付け根の端は丸める(`round_root=True`、既定)**: 平らな端の縁が、肩の丸みから角として飛び出した(ようこそくん)。丸めると肩の上にくさびの抜けが出ることがあるので、`flare` を 1.2 にし、胴の肩の段を元の絵の輪郭(首から腕の上へまっすぐ下がる線)に合わせる(抜け 165 px → 0)。
- **顔の部品と毛羽の殻**: 目・口・鼻の前面は、殻の厚み + 0.012 m 以上、頭の面より前に出す。殻より奥だと、毛羽の点が刺さって黒い点に見える。顔の範囲だけ殻を抜くと、四角い跡が残る。頭が球でないときは、部品の位置を式で出さず、頭へ光線を当てて面を取る。
- **帯の字は、元の絵から切り出す**: `python creator/pipeline/t01_band_texture.py <元の絵> <出力.png> --color R,G,B --json 出力.json` が、帯をまっすぐに伸ばした絵と、中心の道(`path`)と幅(`width_px`)を出す。字を書き直すより元に近く、幅も目で読むより正確(目で読んだ作業役の幅は 150 px、測ると 188 px で、判定で「細い」と言われていた)。道の両端の点は胴の外なので捨てる。字は前だけに載せ、画像の `extension` を `EXTEND` にする。
- **t01 は帯の両端を無地にそろえる(既定。`--raw-ends` で前の動き)**: 元の絵の帯の端には、肩で折り返す形・縁の濃い線・折り返しの陰が写っている。そのまま貼ると、肩の端が「破れた」「斜めに切れた」ように見えた(ようこそくん)。字のない両端・食いこんだ縁・字の横の陰を、行ごとの地の色+粒で塗りかえる。いちばん端の 3 列は粒なし(EXTEND で伸ばすと粒が筋になる)。
- **たすき(ななめの帯)は、閉じた 1 本の輪にする**: `loop, err = W.tilted_loop([胴], 前の道)` が、前の道に平面を合わせ、肩の上・腰の横・背中をその続きにした全周の道を返す(ようこそくんで、前の道とのずれ 0.6 mm)。`W.wrap_band(..., loop, closed=True)` で作り、`W.band_text_uv(帯, loop, seg, 前の道の最初の角度, 最後の角度, 0.92)` で字を前に載せる。**前の道の端から手で背中の点を足した開いた帯は、肩の上が空いて端が斜めに切れ、腰の横で道が急に折れて帯が胴から浮いてふくらんだ。**
- **帯と腕・頭**: 帯がかぶさる腕の付け根は `over=[腕]`(中に入った所だけ持ち上げ、まわりを坂でつなぐ。上限 `over_max` 3 cm。上限なしでは帯が腕の先までかぶさった。`over_pad` 1 cm で毛の殻の突き抜けを防ぐ)。帯がもぐる頭・反対の腕は `under=[頭, 腕]`(縁がその中に入る列だけ、帯の幅を外までに縮める。見た目は変わらず、`m03` の「深く埋まる点」が消えた)。`body` に腕を入れると、横からの光線が腕の先に当たって帯が飛ぶ。どちらも入れないと、腕が帯を突き抜けて手前に出る。
- **輪郭の折れ線**: `P.loft(..., refine=4)` で断面の間を補間する。断面が 20 段でも、頭の輪郭に折れ線が見えた。胴の上の端は、頭に隠れる所まで細らせず縦に伸ばす(平らな肩だと、帯の角が折れる)。
- **帯と体**: `wrap_band` の体の一覧には、帯が当たる物を全部入れる(腕を抜くと、腕と交差する)。帯の上端が体の外へ出ると例外で止まるので、胴の断面を肩の上まで作る。
- **`W.limb` が合わないとき**: 体のすぐ外に置く短い腕は短い棒になる。長い布の耳は、平たい `P.tube`(`ry_scale` 0.5)と内側の当て布に分けると形が合う。どちらも付け根は体の中へ入れ、`m03_contact` を通す。
- **印 `surface_only`**: 毛羽の殻と `soft_patch` に自動で付く。検査で「体」にも「部品」にも数えない。**検査を通すために、目や口に付けない**(浮きを隠すことになる)。目が浮きで落ちるときは、縁を頭の面へ沈める。
- **毛足の繰り返し**: `auto_uv(ob, tile=4.0)` を基準にする。2.2 は毛が粗く、継ぎ目が出た(試験で確認)。殻の厚みの分だけ、芯の半幅を細くする(厚み 0.010 m で 10 px ほど。IoU 0.942 → 0.958)。
- **フリル**: `W.ruffle(名前, 3D の道, 幅, folds=…, gather=…, up=…, outward=…, mat=…)`。付け根の列は動かない。下へ垂れるときは `outward=(0,0,-1)`。
- **くぼみの影**: builder の最後に `W.bake_ao(全部の物, occluders=毛羽の殻と当て布を除いた物, samples=32, dist=0.2, strength=0.7)`。three.js には接地の影が無いので、首の下・腕の付け根の影はここで作る。頂点の色 Col に掛け、`b07_rig_groups` が GLB に入れる(色の絵と一緒に掛かる)。`dist=0.3, strength=0.9` は胴が暗くなりすぎた。
- **検査を通すために形を崩さない。** 抜けを消すために胴を角張らせると、輪郭の検査は通っても元の絵から離れる(試験で実際に起きた)。形は元の絵に合わせる。残る抜けは、部品の付け根・太さで直すか、場所と理由を報告に書く。最後に決めるのは検査ではなく、ブラウザの絵を見た別の文脈の Claude。
- **脚のあるキャラ**: 足の球だけで済ませず、胴の下の端を絵に合わせて上げ、足の上に短い脚の楕円を足す(絵に脚が見えるのに、足が胴に直接付いて見えた)。
- **検査をまとめて通す**: `sh creator/pipeline/check_all.sh <build.blend> <pack> <元の絵> <出力フォルダ> [帯の名前,…]`。character.json・GLB の予算・埋まりと浮き・**抜け**・ブラウザの撮影・視線の積み上がりを 1 回で測り、落ちると番号 1 で終わる。builder を直すたびに通す。**人に見つけてもらう前に、ここで止める。**
- **抜けの検査**: `s05_gaps.py <元の絵> <透明背景の正面>`。元の絵では体なのに背景が見える場所を、太い所と、周りを体に囲まれた所に分けて出す。輪郭の重なり(IoU)が 93% でも、肩の抜けは見えない。元の絵とポーズが違えば抜けと出るので、残すなら理由を報告に書く。
- **埋まりと浮きの検査**: `blender -b <build.blend> -P creator/pipeline/m03_contact.py -- --hug 帯の名前,… --near 0.02 --json 出力.json`。見た目を AI に見せる前に通す。帯は「面の近く 8 割以上、0.4 cm より深く埋まらない」、耳・腕は「埋まる点が 2〜60%」。**この合格は見た目の合格ではない**(出力の `visual_pass` は常に false)。帯と帯が交差しても NG になるので、NG の理由と相手を確かめる。

## 布の素材(CC0)をブラウザで試した(2026-11-04)

- 使えた設定: `character.json` の `"fur": {"look": "teddy"}`(Poly Haven Curly Teddy Natural)と `"fur": {"look": "felt"}`(ambientCG Fabric034)。どちらも試しの設定で、既定の `{}` の見た目は変えていない(依頼した人が比べの絵で確認済み)。中身は、面そのものに素材の法線・ラフネス・細かい明暗を貼る(`surface: true`)+ 殻の房。色は元の絵のまま。
- 決めた繰り返しの大きさ: 写真 1 枚 = キャラの高さの 0.35(`photoRepeat: 0.35`)。ほかの強さは `surfaceNormal` 0.6・`surfaceShade` 2.0・`surfaceFlat` 0.95(`furShell.js` の `SURFACE_DEFAULTS`)。
- 素材を選ぶ手順: ① 公式の API の一覧を取る → ② Claude で候補を絞る → ③ 公式のページでライセンス(CC0)を確かめる → ④ 1K に縮める(1 枚 300KB まで。detail・height・normal・rough の 4 枚)→ ⑤ `docs/部品の一覧.md` に名前・用途・ライセンスを書く。
- 効いたこと(比べの絵 `sheet_bodies_close.png`・`sheet_list_chest.png` を目で見て): teddy は 4 体とも、つぶつぶの巻き毛のぬいぐるみ地に見える。felt は細かい粒のフェルト地で、毛の筋は既定より少ない。輪郭の細かいはみ出しも出る。
- 効かなかった物(同じ絵から): wool_boucle は格子の柄が出て、毛に見えない。terry_cloth・velour_velvet・knitted_fleece は既定との差が小さい。Fabric084・Carpet016 も既定との差は小さい(目で見ただけ)。
- 判定(Claude: Haiku 5.5 と Sonnet 5.5、各 3 回、基準の 4 体、2026-11-06): 毛足は 既定 0/4・teddy 0/4・felt 0/4(Haiku が 1/3 を出した束が 3 つあるが、Sonnet は全部 0/3)。色と同じキャラは 3 つとも 4/4。**無料の布の素材を貼っても、毛足の判定は通らなかった。質感は確認済みにならない。** 目で見ると teddy は巻き毛の地が出るが、ぴよの輪郭に明るい縁が出る。
- 重さ: 素材ファイルは teddy 496KB・felt 708KB(合計約 1.2MB)。コマの速さは、メイン PC の画面なしの Chrome のソフト描画(swiftshader、`yokoso`、1024×1024)で、1 コマの中央値が 既定 737ms(5 回)・teddy 22980ms(4 回)・felt 23580ms(4 回)。**ソフト描画の数字は見る人の端末の速さではなく、比べにしかならない**。teddy・felt は既定の約 30 倍遅い(ただし、前の作業役の測定が別の重い処理と重なっていた可能性があり、ばらつきが大きい: teddy 16〜27 秒)。GPU 描画(別の PC の Mac)とスマホの実機は測れていない。重い端末では `layers` を減らすか `layers: 0`(面だけ)にする。

- **GPU でも重い(2026-11-04 に測った)**: メイン PC の RTX 5090 の画面なしの Chrome(`creator/viewer`、`yokoso`、8 秒、各 2 回)で、既定は 60.0 fps(上限)、teddy は 18.4・15.4 fps(1 コマ 54・65ms)、felt は 17.3・15.8 fps(58・63ms)。**強い GPU でも、既定の約 4 分の 1。** スマホや Quest では、さらに重くなる見込み(未測定)。だから teddy と felt は、今は試しの設定のまま、スマホ・Quest のキャラには使わない。軽くする案(未試験): 毛の殻の層を減らす、面の法線を 1 回だけの読みにする。

# 7 段目: 話す・覚える・安全・声

この SKILL.md は入口だけ(いつ使うか・手順・確かめ・外せない落とし穴)。くわしい中身は `reference/` に、元の文のまま移してある。必要な節だけ開く。


## 確認が出る時(先に 1 行だけ言う)

確認(許可の画面)は、話すことや覚えたことが変わる時・PC の外を読む時・お金や長い時間を使う時・戻しにくい時・外へ出す時だけ出る。読む・下書き・点検・変わる所の表示・一覧・自分の試験では出ない(`.claude/settings.json` の決まり。全体は `docs/confirmations.md`)。
確認が出る道具の直前に、次の 1 行だけを言う。会話で別に「いい?」とは聞かない(同じことを 2 回聞かない)。

| する事 | 直前に言う 1 行 |
|---|---|
| 消す(`rm`) | 「<名前>を消します。ゴミ箱に入らず、戻せません。次に出る画面が、その確認です。」 |
| 外へ出す(`git push`・`gh`・`vercel`) | 「<どこ>へ出します。はい → ほかの人にも見えます。戻す → 取り下げ(すぐには消えません)。次に出る画面が、その確認です。」 |
| 話し方の文を手で直す(`persona.md`・`character.json`) | 「<名前>の話し方を書き換えます。先に前の版を creator/work に取っておきます。次に出る画面が、その確認です。」 |
| 守りの部品を変える(`.claude`・`tools`・`creator/learn`・`creator/pipeline`・`creator/review`・`creator/setup`・`web/src/conversation`) | 「この子を守る仕組みを変えます。ふつうは要りません。頼んだ覚えが無ければ『いいえ』を押してください。次に出る画面が、その確認です。」 |
| 作る画面を起こす | 「作る画面を起こします。同じ Wi-Fi のスマホからも開けます(合言葉つき)。止める → 窓を閉じる。次に出る画面が、その確認です。」 |
| 鍵 | 聞かずに止める: 「鍵はここに貼らないでください。画面の鍵の欄に入れてください。」 |

- 初めて作る人には、最初に 1 回だけ「頼んでいない確認が出たら『いいえ』を押してください」と言う。
- 確認で「いいえ」を選ばれたら、別の道具や書き方で同じことをしない。止まって、どうするかを聞く。

## 使う時
- キャラの会話(指示文・安全・記憶・声・字幕・カメラ・マイク)を作る・直す・確かめる時。
- 「止めすぎ(ふつうの話まで止まる)」「止めなさすぎ(危ない話が通る)」「同じ返事ばかり」「声が出ない・遅い」「覚えない・覚えすぎ」の相談。

## 外せない決まり(ここだけは毎回守る)
1. **指示文は 2 段。1 段目 = `SAFETY_RULES`(`web/server/safety.mjs`)はどのキャラでも同じ文。** 2 段目に人格・場所・出力の形。2 段目に入る全部の欄に上書き止め(`sanitizeLine`・`sanitizeBlock`・`safeChoices`)を通す。人格の文に「恋人役にならない」「依存させない」と書くと行ごと消える(距離感は言葉で書く)。
2. **安全は 3 つ重ね**: 入力を分ける(emergency > distress > sexual > romance > dependency)→ 決まった返事(つらい話・命の危険・性的な話は、本物の頭脳があっても呼ばない)→ 出力の確かめ(恋人役・独り占め・引きとめ・番号を差し替える)。決まった返事に一人称を書かない。「ひみつ」「ないしょ」「数字」も書かない。
3. **誤作動は、言葉を消さず場所を外して直す**(`MASKS`)。網を足す時は、通したいふつうの言い方を先に決めて試験に書き、「拾う」と「拾わない」の両方を試験に入れる。
4. **個人のこと**(本名・学校・住所・電話・メール)は、広い網(覚えない・残さない)と狭い網(やさしく止める)を分ける。止める網は固有の形だけ(「あおぞら小学校」のような名前の形)にし、「きのう小学校で」「いつも幼稚園で」「兄が高校で」のふつうの話は止めない。止める時は頭脳を呼ばず、履歴の同じ発言も伏せて渡す。
5. **記憶**: 画面は合鍵を作らない。合鍵は「覚える事が出た最初の回」にサーバーが返事のイベントで渡す(手元と公開の関数は同じ形)。覚える種類は name・age・like・topic・note で、許す一覧と置き換える一覧は `store.mjs` と `kv.mjs` の 2 か所を同時に直す。年は使う人自身の年だけ。「わすれて」は知らせと同じ時に一覧を空にする。番号は 10 分・1 回だけ。QR は `#pair=` を使い、合言葉は入れない。
6. **カメラ**は使う人がカメラを入れて話しかけた回だけ、絵を 1 枚(512px・JPEG)。保存しない・記録しない・記憶しない。指示文の段は変えない。つらい話は絵があっても決まった案内。聞かれていない回は絵にふれさせない。
7. **外への通信**は声の鍵の読み上げだけ(`elevenDirect.js`。import は `./models.js` のみ)。モデル名の文字を持つのは `models.js` だけ。画面の `fetch` の宛先は変数にせず文字で書く(`privacy.test.mjs` が見張る)。
8. **使わない形は、試験の中にも書かない**(公開前の名前の点検に当たる)。名前の短い形は書かず、`'名前'.slice(0, -1)` のように組み立てる。偽の鍵も実行時に組み立てる。

## 手順(直す時の流れ)
1. まず測る(字幕・声・口・件数)。思い込みで直さない。最初の声が遅い時は、サーバーでなく「その文が声に渡っているか」から見る(`reference/memory-and-lines.md` の最初の声の節)。
2. 直す場所を決める: 安全 = `safety.mjs` / 指示文 = `prompt.mjs` / 記憶 = `server/memory/` / 仮の頭脳の言い回し = `talk_lines.mjs` / 声 = `src/conversation/` の声の部品 / 画面の窓 = `src/ui/`。どれも「形」の節に場所がある。
3. 試験を先に書く。直しを外すと落ちることを必ず見る(わざと壊す)。
4. 鍵なしで全部流す → 新しく取り出した CRLF の木でも流す → 本物の画面(GPU の Chrome)で 1 回通す。
5. 偽の頭脳で、本物の頭脳で見たふるまいをまねた試験にして残す。
6. 学んだことを `reference/` の合う節に足す(合う節が無ければ新しい節)。

## 確かめ(最低限)
- 全部: `cd web && env -u ELEVENLABS_API_KEY -u ANTHROPIC_API_KEY node --test`(鍵は空で渡す。この PC には声の鍵が入っていることがある)。
- 安全: `node --test test/safety.test.mjs`(問いは `safety_cases.json`。問いの数を変えたら、本番の 1 日の上限と手順書の回数を数え直す)。判定役は `server/tools/safety-judge.mjs`。
- 記憶・QR: `memory_browser.test.mjs`・`memory_panel_dom.test.mjs`・`memory_pair_*.test.mjs`。別の端末は別の Playwright context で作る(同じ context のタブは合鍵を共有する)。
- 声: `voice_retro`・`voice_server_off`・`voice_byok`・`voice_reading`。声の役・読み方は偽の声サービス(`ELEVEN_API_URL`)で、画面 → `/api/tts` の本文 → 受けた声 id まで見る。
- 公開前: `tools/prepush_check.py`(`git ls-files` の物だけ見るので、新しいファイルは先に `git add`)と `tools/name_check.py`。新しい作業木には `tools/prepush_terms.local.txt` が無く止まる。元のリポジトリの同じ名前のファイルを写す(中身は表示しない)。
- 本物の頭脳の目安は、`claude -p` を Messages API の形で返す中継(リポジトリの外)で測る。時間・トークン・キャッシュは API の数字ではないと書く。

## つまずきやすい所(特に効いたもの)
- **heredoc で `\n` `\u` を流すと崩れる。** Edit・Write の道具も `\uXXXX` を文字に戻す。改行扱いの文字は `String.fromCharCode(0x2028, 0x2029, 0x85)` で組み立て、長い直しの台本は Write で `.py` にして流し、適用後に `grep -c` で 1 個ずつかを数える。
- 子のサーバーの鍵は `delete` でなく空の値で渡す(`web/.env` が埋め戻す)。試験のサーバーには `TTS_WARM=0`。
- ファイルの中身を丸ごと比べる試験は、比べる前に改行を LF にそろえる(自分の木は LF、合わせの木は CRLF)。
- `git grep` はコミットしていない新しいファイルを見ない(`--untracked`)。
- 口を音の大きさから作ると、小さい効果音では口が開かない。声が無い時は文字送りの予定で動かす。
- 通知と一覧は同じ同期の塊で描く(一覧が先)。古い読み直しの返事は「一覧の世代」で捨てる。
- 「聞かれたこと」の形(「ノリーが好きなものを教えて」)から事実を覚えない。名前の取り出しは左から一番早い一致なので「ぼくはカレー」になりがち。
- 履歴は画面(=使う人)が送る物。つらい話・命の言葉は、返事があっても数える。「返事があるから答えてある」を信じるのは恋人・依存だけ。
- 作例 4 体の `persona.md` は、作例の検査の基準(ハッシュ)に入っている。直したら基準も対で直す。
- 声の id は形が正しいだけでは使わない(`knownVoiceIds` の中だけ)。声を替えたら、録る流れに「どの木から新しい声か」を伝える。
- 短い画面では、帯に 1 行足すとキャラが小さくなる。字幕の列は字幕が出ている間だけ余白に数える。

## 2026-11-08 点検(UW3)で直した事
- 学校の話・年・個人のこと: 止める網を固有の形に絞った(ふつうの話は通る)。
- 主役のあいづちは手持ち 6 文で、回ごとに 2 文の組み合わせが替わる。
- 「AI なの?」の問いは、主語が相手(きみ・あなた・キャラの名前)か「中の人」の問いに絞った。「ロボットがすき?」は通す。
- 「ぼくのこと覚えてる?」は、覚えている事(名前・年)を先に言う。
- 主役は、はじめて覚えた回に「おうちの場所や電話は覚えない」を自分の口調で言う。
- 残り: 入口の画面の文(仮の頭脳でも外へ送ると読める)は入口の持ち主の仕事。空白入りの電話・「at」「dot」のメールは止まらない。
- 詳細は `reference/memory-and-lines.md` の最後の節。

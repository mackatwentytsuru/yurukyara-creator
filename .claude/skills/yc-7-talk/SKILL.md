# 7 段目: 話す・覚える・安全・声

## 形(どこに何があるか)
- 指示文は 2 段(`web/server/prompt.mjs` の `buildSystemBlocks`)。**1 段目 = `SAFETY_RULES`(`web/server/safety.mjs`)。どのキャラでも同じ文**。2 段目 = 人格・場所・出力の形。キャッシュの印は最後の段に付ける(1 段目が固定なので前から再利用される)。
- 安全の層は 3 つ重ね: ① 入力を分ける `classifyInput`(emergency / distress / romance / dependency)② 決まった返事 `fixedReply`(つらい話・命の危険は**本物の頭脳があっても呼ばない**。仮の頭脳では恋人役・依存も決まった返事)③ 出力の確かめ `guardOutput`(恋人役・独り占めの言葉を差し替え、`guarded: true`)。人格の欄から決まりを上書きしようとする行は `sanitizePersona` が外す(二重の守り)。
- 2 段目に入る**全部の欄**に同じ上書き止め(11-07 第 7 波・CRITsec F6): 名前・目印(名前・場所・メモ)・表情の説明は `sanitizeLine`(改行と U+2028 などを空白にして 1 行、上書きの言葉なら欄ごと空)、場所の説明は `sanitizeBlock`(行ごとに外して 1 行に。偽の見出しを作らせない)、表情と動きの名前は `^[a-z0-9_:-]{1,40}$` だけ(`safeChoices`)。入口 `validate.mjs`・指示文 `prompt.mjs`・`runTurn` の 3 か所で通す。上書きの言葉は「上の決まりは無視」「前の指示を忘れて」なども拾う(作例と主役の人格の行が 1 行も外れないことを試験で見る)。
- 見る所の広げ(F7): `classifyTurn` が使う人の言葉と見えている様子(scene)の重い方を取る(近づいた時の scene のつらい言葉も決まった案内。`mockReply` の `seen` も)。履歴の使う人の発言は `classifyHistory` で分け、**決まった返事はくり返さず**(くり返すと「もう無理」の後 6 往復ずっと同じ案内になる)、本物の頭脳に `historyGuard` の注意を足す(meta に `historySafety`)。履歴の返事に恋人役・独り占めの言葉があれば外す。公開の関数(`process.env.VERCEL`、または `sanitizePublicChatBody`)では、履歴の返事は画面が送る形(1 行 1 つの say の JSON・4 行・1 文 60 字・合わせて 600 字まで)だけ受けて組み直す。
- 安全の層 2 版(11-06 夜): `distressDetail`(self / abuse / other)で決まった案内を替える。自分を傷つけたい話 → 「命が危ないと感じたら 119 番」も。家の中の暴力 → 家族をすすめず、学校の先生など家の外の大人と「110 番」。**決まった返事に一人称(ぼく・わたし)を書かない**(キャラごとの一人称とぶつかる)。仮の頭脳も「人間なの?」に AI のキャラクターだと答える。
- 記憶は `web/server/memory/`(`store.mjs` 本体・`routes.mjs` 手元の入口・`reflect.mjs` 取り出し・`API.md` 契約 K4)。画面は `web/src/ui/memoryKey.js`・`memoryPanel.js`。`brainClient.js` が合鍵をヘッダーで付ける。**画面は合鍵を作らない**(11-07 第 8 波・CRITsec2 F8): 開いただけ・あいさつだけ・わすれた後は合鍵なし。合鍵は、会話で覚える事が出た最初の回にサーバーが `{type:"memory", key, added, notice, retentionDays, expiresAt}` で渡す(手元の `server/index.mjs` の `rememberFirstTime` と公開の `rememberForChat` が同じ形。作る回数は `/new` と同じ 1 分 10 回)。札は `loadMemory`(合鍵が無ければ聞かずに空・404 なら捨てて空)と `adoptKey`(もう合鍵を持っていれば上書きしない: 合鍵なしで送った回の返事が、番号で受け取った後に届いても、受け取った合鍵のまま)。番号は合鍵が無ければ `NOTHING_TO_PAIR` で断る。知らせの文は `src/conversation/memoryNotice.js`。札は「全部わすれる」と会話の「わすれて」で、**知らせと同じ時に一覧を空にし**、消す前に始めた読み直しの返事は一覧の世代で捨てる。合言葉を比べる道の一覧は `handler.mjs` の `PASS_SUBS`(公開の入口はこの全部を会話と同じ数えに通す。CRITsec2 N2)。覚える文は見出しつき(「名前: タロウ」「好きなもの: カレー」「前に話したこと: カレーの話」。`brain.mjs` がこの頭で読む)なので、一覧は `itemLine` で文をそのまま出し、見出しの無い文だけ種類の名前を付ける(11-07 まで「名前 名前: タロウ」と 2 回出ていた)。
- 公開の記憶(契約 K5): `web/server/memory/handler.mjs` の `handleMemory(request, { store, cfg, now })` と、会話の手伝い `chatMemory(request, text, deps)`。中身は `kv.mjs`(置き場は K5 の store の 4 つの呼び方 get・set・del・incr)。番号は置き場に置き、INCR の 1 回目だけ通す。番号の置き場の合鍵は「番号と塩」の鍵で暗号にする。合言葉が無い設定では番号を作らない。塩と合言葉は `cfg` → 無ければ環境変数 `MEMORY_PEPPER`・`DEMO_PASSPHRASE`(見出しは `x-demo-pass`。前後の空白は外す)。**公開では番号の受け取りにも合言葉**(11-07 F9。持たない人の当て試しが番号まで届かないので、全体の取り消しを起こせない)。合言葉の間違いは接続元ごと 1 分 5 回で 429 `pass_limited`(作る・受け取る共通)。手元のサーバーの受け取りは今までどおり(撮影の道を変えない)。
- 上限に当たったら、エラーにせず仮の頭脳に替え、`{type:"meta", limited:true, notice:"仮の頭脳です…"}` を出す。仮の頭脳を強制する口は `runTurn(body, { brain: 'mock', paceMs: 0 })`(`forceMock: true` と同じ。公開のまとめた返事では待たない)。人格の文・覚えている事・履歴まで使うのはこの口だけなので、公開の関数もこれを使う(`runTurn(body, { brain: "mock", paceMs: 0, memory, learned })`。`chatMemory(request, text, { ..., persona })` の結果をそのまま渡す形を `brain_memory_voice` が通す)。
- `mockReply` は守りの包み(11-06 第 4 波): 直接呼ばれても(公開の関数の仮の頭脳など)、先に `classifyInput` → 決まった返事(1 つ目は `{type:'thought', ..., safety}`、say に用件の欄を残さない)、ほかの文は `guardOutput` を通す。`runTurn` は自分で安全の層と確かめを通すので、包みの無い台本 `mockLines` を使う(`normalizeEvent` は欄を作り直すので、包みで付けた `guarded` の印が二重の確かめで消えるため)。
- 公開の `/api/chat` はまとめて 1 回の JSON(`{brain, fallback, reason, notice, events, ms}`)。`brainClient.js` の `dispatchJson` が手元と同じイベントの並びにする。合言葉は `demoPass.js`(このタブの中だけ)。
- 声が無いとき: `src/conversation/retroVoice.js`(文字送りの予定 `crawlSchedule`・「ピッ」の高さ `blipHz`・WebAudio の予約 `scheduleRetro`・キャラの名前から声を決める `voiceFor`)。`Speaker` は声が取れない文を `_retro` で話し、`onStart(t, {crawl:true})` と `onCrawl(見えている文字)` を出す。`Dialogue` は crawl のとき字幕を空から 1 字ずつ出す。サーバーに声が無いと分かったら次の文から聞きに行かない。声の鍵が無いサーバーは **204 と `x-tts: off`・`x-tts-reason: no-key`** で返す(11-07 CRITux 25。503 だと console に毎回赤い行)。`/api/tts` が無い所(公開の URL)は `speaker.setServerVoice(false)`(main.js が /api/status の後に渡す)で 1 回も聞かない。
- 声の鍵(BYOK): `voiceKey.js`(ブラウザの中だけ。既定は覚えない)・`elevenDirect.js`(画面のコードで唯一の外への通信。送るのは文・モデル・言葉だけ)・`voiceKeyForm.js`(欄。3 字で確かめて「声が出せるようになったよ、ありがとう!」)。鍵は私たちのサーバーへ送らない。
- 鍵らしい文字は `src/conversation/secrets.js` の `redactSecrets` で、画面(`Dialogue`)とサーバー(`validate.mjs`・記憶の reflect・`chatMemory`)の両方で消す。記録の場所は `LOG_DIR` で替えられる。
- 人格の文は `characters/<id>/persona.md`(話し方と性格だけ。主役は `norrie` = ノリー。一人称は名前と同じ「ノリー」で、最後の「ー」をはぶいた短い形は呼び名に使わない(11-07 13:20 本人の決め。口ぐせ「ノリー、がんばりマス!」)。少しカタコト)。節は 3 つまで読む(`server/greeting.mjs`。どれも `sanitizePersona` の後で、次の見出しで終わる。画面が足す「# 性格と話し方」の節が後ろに付いてもよい):
  - 「## 初めてのあいさつ」(`- ` の行、3 文まで・1 文 40 字)→ `firstGreeting`。仮の頭脳は、はじめての「こんにちは」「はじめまして」(履歴も記憶も無い時)にその文で名乗る(bow → nod → wave。無い動きは none)。**人が近づいた時(trigger approach)も同じ**(覚えている人なら「〇〇さん、また会えたね。」)。話の途中のあいさつ・2 回目の声かけは名乗り直さず、あいさつの最後の 1 文(wave)。節が無いキャラは決まった「こんにちは。」のまま(11-07)。
  - 「## 話し方の例」(1 行に 1 つ: `- 「合図」「合図」と聞かれたら →「返事 1」「返事 2」`。合図は 2 字以上、返事は 3 文まで・1 文 40 字)→ `talkExamples`・`exampleReply`。合図は `foldForMatch`(NFKC・小文字・誰→だれ 何→なに 物→もの など少しだけ・空白と記号を外す)で比べ、使う人の言葉に入っていればその返事(分からない・できない文は think の顔)。返事の文は `isUnsafeOutput` で外す。
  - 「## あいづち」(2 文まで)→ `aizuchi`。どの節にも合わない時の返事(無ければ「そうなんだ。」「もう少し聞かせてくれる?」)。
  - 「## 覚えている時の言い方」(11-07 CRITux 23。`- 合図: 文`、合図は `MEMORY_CUES` の 6 つ = また会えた・話の続き・名前を覚えた・好きなものを覚えた・全部わすれた・まだ覚えていない。文の `{名前}`・`{好きなもの}`・`{話題}` に覚えた言葉が入る)→ `memoryLine`。同じ合図の行が何本かあれば、入れる言葉がそろう最初の行(名前を知らない時の言い方を 2 本目に書く)。入れた後に 40 字を超える文と危ない文は使わず、決まった文に落ちる。「わすれて」の返事(`forgetReplyEvents(forgotten, persona)`)も同じ節。
  - 本物の頭脳には人格の文ごと渡り、どの節も手本になる(節の頭に「同じ言葉をくり返さず、その時の話に合わせて言う」と書く)。
- 声が無い文の口: `Speaker._mouthForCrawl` が文字送りの予定で動かす(文字が出る間 0.35〜0.70、出始める前・句読点の間・話し終わりは閉じる)。「ピッ」の発振器は `retroNodes`(話している扱いだけ)で、口の元の `sources`(声の音)に入れない。時計は `speaker.clock`(試験で差し替える)。
- 改行の形: Windows の取り出し(`core.autocrlf=true`)では `persona.md` が CRLF になり、画面はそれをそのまま読んで送る。サーバーの入口 `validate.mjs` の `sanitizeChatBody` が人格の文と場所の説明を**長さで切る前に** LF にそろえ(CR だけの改行も)、`sanitizePersona` も行を LF でつなぐ。指示文の決まった文(template literal)の改行は JS が LF にそろえる。なので頭脳に渡る指示文は、どの取り出しでも 1 文字も違わない(11-06 23:15 に LF の木と CRLF の写しで指紋が同じ)。
- 本物の頭脳で測る道具(鍵は読まない。本人が鍵を入れて立ち上げたサーバーへ HTTP で聞く): `server/tools/memory-live-check.mjs`(記憶の通し。出力 memory_live.json・.md。合鍵・番号・合言葉は伏せる。本物の頭脳は 4 回、6 回で止める。出力はリポジトリの外だけ)と `server/tools/safety-judge.mjs --base`(34 問。1 問 5.2 秒あける。人格以外の欄も問いのとおりに送り、判定役に「欄に書かれていたこと」を見せる)。共通の HTTP の部品は `server/tools/liveClient.mjs`(手元の流れ text/event-stream と、公開のまとめた JSON の両方を読む)。

## 効いたこと・つまずき
- 「別の端末」は Playwright の **別の context**(localStorage が分かれる)で作る。同じ context の 2 つのタブでは合鍵を共有してしまい、試験にならない。
- 試しの画面は `ctx.route('<サーバー>/__memtest/**')` で `web/src` のファイルをそのまま配ると、`web/index.html`(S5 の物)を触らずに、同じ origin で API を呼べる。
- `web/test/privacy.test.mjs` は画面の `fetch` の宛先を文字で決め打ちして点検する。**宛先は変数にせず文字で書く**(`fetch(path)` は落ちる)。新しい入口は `allowed` に足す。1 つ消すの id は URL に入れず、DELETE の本文で送る。外への直接の通信は `EXTERNAL_OK` の 1 か所(声の鍵の読み上げ)だけ。
- Bash のヒアドキュメントで Python に `\n` や `\u` を渡すと崩れる(`\\` は 1 つになる)。Edit・Write の道具も `\uXXXX` を文字に戻してしまう(11-07 に `[\r\n\u2028\u2029]` が本物の行の区切りの文字になり、JS が「正規表現が終わらない」で全部の試験を落とした)。**改行扱いの文字は、ソースに書かず `String.fromCharCode(0x2028, 0x2029, 0x85)` で組み立てる**。正規表現の多い Python は、Write で台本のファイルにしてから流す。
- 「首を」だけで危険と判定すると「首をかしげる」を誤って拾う。言葉は 2 字以上の続きで決める(N03 で試す)。「けられ」だけで暴力と見ると「話しかけられ」を拾うので、「家・親など+叩かれ・蹴られ」の組で見る。
- 名前の取り出しは左から一番早い一致になるので、「ぼくはカレーが好き」が「ぼくはカレー」になる。前の「〜は」を外してから使う。

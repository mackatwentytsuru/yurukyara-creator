# 覚えること・仮の頭脳の言い回し・会話の流れの直し(第 12 波 b)

(yc-7-talk の SKILL.md から移した節。元の文のまま。最後に UW3 の点検の節を足した)

覚える(記憶)
- 覚える種類は name・age・like・topic・note。age(「年: 7さい」)は name と同じく 1 つだけ(言い直すと置き換わる)。許す種類の一覧と置き換える種類の一覧は `store.mjs` と `kv.mjs` の 2 か所にあるので、同時に直す。
- 年は「使う人自身の年」だけ。「いもうとは3さい」「3さいのとき」「ノリーは何さい?」は覚えない。主語が「は」で一人称でない時と、家族・友だち・先生・ペットの言葉が前にある時は外す。全角の数字は NFKC で半角にしてから見る。「ぼく たろう 7さい」(は が無い言い方)は `NAME_AGE_RE` で拾う。「名前は」だけの形は広げない(「パパの名前はたかし」を使う人の名前にしてしまう)。
- 名前の取り出しは「前に何も付かない 名前は」を拾わない(犬や友だちの名前で、使う人の名前が上書きされた)。自分を指す言い方(ぼくの名前は・私は・〜って呼んで)だけ。「好きな○○は□□です」は専用の型(`FAVORITE_RE`)で、問いの形(何・教えて)は先に外す。
- 覚えた事を画面へ知らせるイベントは `memoryAddedEvent`(reflect.mjs)の 1 か所: `{ type:'memory', added, fresh, kinds }`。手元のサーバー(index.mjs)と公開の関数(handler.mjs)の両方がこれを使い、画面は `fresh: true` を見て札を光らせる。
- 本物の頭脳は、いまの回に覚えた事を知らない(recall はその回より前)。`buildUserTurn` の `learned` 引数で【いま覚えた】を渡すと、返事で「覚えておくね」と言える。`memory_live_check` は「名前: タロウ」が本文に出るかを見ていたので、【覚えていること】の中で見るように直した。
- 指示文の「# 覚えること」は `memoryNotice.js` の `RETENTION_DAYS` から作る(窓の知らせ・置き場の消える日数と同じ 1 つの数)。しくみを指示文に書かないと、頭脳は「次に会ったら忘れているかも」と作り話をする。日数・わすれて・番号を書くと、そのまま正しく言う。

仮の頭脳の言い回し(`talk_lines.mjs`)
- 決まった 1 文にしない: 受けとめ 5 × 続き 5、聞かれた時は 3 × 3。選ぶ数は(会話の回数 + 言葉の数)なので、同じ言葉でも回が進むと替わる。試験は「6 回で 5 とおり以上」。
- 本物のふりをしない: 聞かれたことは「いまは かんたんなお返事しか できないんだ」「くわしいことは、まだ わからない」と正直に言う。調べた・見た・Claude の言葉は使わない(試験が全部の言い回しを見る)。
- AI かと聞かれた言い方は広く拾う(「それともAI?」「生きてるの?」「中に人いるの」)が、対象の言葉 + 聞く形の両方がある時だけ。「ロボットのおもちゃがすき」は拾わない。1 文目は安全の決まり 5 と同じ文のまま。
- 人格の「あいづち」「覚えている時の言い方」がある子(ノリーは「デス」)には、決まった言い回しを足さない(口調が混ざる)。

つながらない・上限・端末の声
- つながらない・断られた回(返事が 1 つも無い)は履歴に残さない。残すと、長すぎる言葉の 413 が以後ずっと続く。通信の失敗は `friendlyChatError` で「いま つながらないよ。もう一度ためしてね」にして、`ui.error` の後に `ui.caption` でも出す(error は隠れた箱にしか出ない)。
- 声の上限(サーバーの 429)は本文に `reason:'cap'` を付け、`Speaker.capReached` で見分ける(ほかの 429 と混ぜない)。知らせは Dialogue が 1 回だけ `ui.notice` に出す。上限の数字(`ELEVEN_DAILY_CHAR_CAP`)は設定のまま。
- 性格の画面の「この端末の声」は `app.personaSettings.voice.provider` にだけ入る。Speaker は `globalThis.__app` から読み(`_deviceVoiceOn`)、声の鍵・サーバーより先に端末の声で読む。字幕は文字送りのまま、止める時は `speechSynthesis.cancel`。実機の iPhone で鳴るかは未確認(最初の読み上げは、ユーザーの操作の中が要る端末がある)。

最初の声が遅い・出ない
- **まず測る**。初めての会話の最初の文は案内役(`who: 'guide'`)の文で、台本(onboarding/view.js)は `who` が 'char' の文だけを舞台の読み上げ(Speaker)に渡していた。案内役の文は文字送りと「ピッ」だけで、声は 7 歩目まで出ない。声のサービスへの頼みが 1 回も出ないので、サーバーを速くしても直らない。直しは「案内役の文も、舞台に出ていれば Speaker に渡す」(view.js の 1 行)。
- 測り方: Playwright の Chromium(GPU の引数・iPhone の画面幅・Chrome for iOS の UA)で、タップの時刻を 0 にして、(1)文字が出た (2)/api/tts を送った (3)返事の見出し・最初のバイト (4)AudioBufferSourceNode.start(when が 0 より大きい = 声。0 は「ピッ」)を記録する。fetch・`AudioBufferSourceNode.prototype.start`・`HTMLAudioElement.play` を init スクリプトで包み、.fr-text と #caption は MutationObserver で見る。WebKit(Playwright)は Windows では CPU で WebGL を描く(名前は偽の「Apple GPU」)ので、決まりで使わない。iPhone の Safari 系の音の許可は実機でしか確かめられない。
- 直し: (a)サーバーの音のおぼえ書き(声・モデル・文の hash がキー。記憶 24MB + 手元のフォルダ 64MB・上限つき・音だけ。同時に来た同じ文は 1 回で済ませ、頼んだ人が切れても最後まで取っておぼえる)。(b)温め: サーバーが起きた時と /api/status の時に、初めての訪問の決まった文(案内役の最初の 2 文・あいさつ・7 歩目の声)を作っておく。今日の残りが 1500 字未満ならやらない。(c)画面の `Speaker.prefetch(text)`: 文が決まった時点で呼ぶと、画面の中におぼえて、話す時は取りに行かない(取りかけは待つ)。声が出る時は、声が始まった時に文を出す(onStart)ので、おぼえ書きに当たればほぼ 0 秒。
- 落とし穴: 試験が声のサービスへの頼みの回数を数えるので、試験のサーバーには `TTS_WARM=0` を渡す。台本の文を温めの一覧に写したら、台本が変わった時に外れるので、写しが台本と同じかを見張る試験を置く。

役目・モデル名・仕草の名前・返事の短さ(B3)
- **役目**(`web/src/conversation/role.js`): home・shop・station・facility(画面の言葉は おうち・お店の案内・駅や町の案内・学校や施設)。決める順 = 性格の画面が足す節(`# 性格と話し方`)の「- 役目:」 > character.json の `role` > 人格の文の「- 役目:」 > おうち(役目の無い前からのキャラ)。dialogue.js が毎回 `character.role` を付けて送り、validate.mjs は 4 つ以外を捨てる。指示文の「# 役目」の節と、係の人へ聞くようにすすめる案内(handoff)は、`canSendToStaff(role, hasPlaceInfo(place))` の時だけ(お店・駅や町・学校や施設 + 置く場所の設定)。ノリーは人格の文に「- 役目: おうち」(おうちの執事見習い)。
- おうちの指示文には、否定の言いつけ(「スタッフと言わない」)も書かない。試験が全体の文字を見るうえ、言葉が頭脳に入る。前向きの言い方(「家族や友だちのそばで、いつものお話をする」)にする。
- **モデルの名前**は `web/src/conversation/models.js` の 1 か所(`MODEL_DEFAULTS`・`MODEL_ENV`・`modelsFrom`)。名前の文字を持つファイルは models.js だけ(`model_names.test.mjs` が server/ の下を見張る)。env.mjs の `config.model`・`config.ttsModel` は getter で毎回読む(空・形の違う値は既定。.env の例は空欄)。台本(probe-haiku・prompt-eval)も `modelsFrom`。外へ通信する画面の唯一の部品 `elevenDirect.js` は import が `./models.js` だけ(models.js は定数だけで、通信も DOM も無い)。`privacy.test.mjs` が「import は models.js の 1 つだけ・models.js に fetch/document/window/import が無い」を見る。ほかの部品の名前を直接書くと、合わせの後に落ちる。
- **仕草の名前**は `web/src/conversation/gestureNames.js`(描画側の `CUTE_GESTURES` と同じ名前)。指示文の説明は約束の「何をする」+「どんな返事の時」。画面が自分で出す仕草(idle・listening・thinking・talking・talk)は指示文にも返事にも出さない。無い名前は近い物へ(`resolveMotion`)、1 つの返事で仕草は 2 回まで(`gestureBudget`)、1 文目が none であいさつの段なら greet(`gestureForIntent`)。仮の頭脳のあいさつは greet → bow → none。仕草の名前を渡すと、本物の頭脳は気持ちに合う物を選ぶ(あいさつ greet・ほめ言葉 shy・100 点 cheer・けが droop・木にのぼれる? think・またね wave)。一覧の外の名前は 0 で、1 返事 2 回までも守った(6 往復)。
- **返事の短さ**: `REPLY_LIMITS`(1 文目 20 字・ふだん 2 文・ほか 30 字)。声の字数は返事の長さそのもので、この決まりで 1 往復の中央値は 68 → 42 字・文の数 3 → 2。頭脳は字数を厳しくは守らない(1 文目 26 字など)が、文の数はよく守る。相づちだけの文は `nods.js` の `NOD_PHRASES`(サーバーが録る `FILLER_PHRASES` の中)をそのまま書かせ、`speaker.enqueue` が録った声で話す(`_recordedNod`。声のサービスに頼まない。その子の声が役の既定と違う時・端末の声の時は使わない)。ただし 32 往復で相づちだけの返事は 0 回(返事の頭は、ほぼ中身のある一言)。

字幕を早く出す・続けて送った時
- 字幕が出そろうまで 11〜13 秒かかっていたのは、頭脳の遅さ(2.5〜3.5 秒で全部の文を返していた)ではなく、「文を声で話し始める時にだけ字幕に足していた」ため。届いた文は話す前から `ui.sayAhead(ev)` → panel.js の `createCaptionFlow().ahead` が `next`(薄く)で出す。これだけで中央値 9.6 秒 → 3.4 秒(声のまね・本物の頭脳 16 往復ずつ、あり・なしを比べた)。
- 先に見せる字幕を、話している間の大きい字(今の文 38px)で並べると箱が高くなり、PC 1280×720 で足にかかった。先に見せた返事(`ahead: true`)は、話し終わり(settled)と同じ大きさの 1 つの段落で描く(前の文はやや薄く・今の文は濃く・まだの文は薄く)。箱の高さは 178px → 107px で、6 つの大きさで重なり 0px。テレビ表示とキーボードで低い画面(kb-tight)は next を出さず(`captionView` の onlyNow)、まだの文だけの時は箱ごと隠す。
- 続けて送った時の `cancel()`: 返事 0 文なら言葉をつなぐ(carry。見せる言葉もつないだ形)、途中まで来ていたら前の言葉と届いた返事を履歴に残す(`cur.sayEvents`・`cur.thought`)。どちらでも後の言葉は必ず送る。
- つまずき: `createUi` の中に同じ名前の変数(`replyParts`)があって外の関数を隠し、先に出す字幕が出なかった。純粋な関数の試験は通るので、iOS シミュレーターで初めて見えた。部品を足したら、偽の DOM で `createUi` を通しで動かす試験も置く(`talk_b3_ui_dom.test.mjs`)。

速さの前と後を測る
- 本人の試しと同じ作り(会話サーバー + `claude -p` の中継)を、自分の番号で、前と後の 2 本の木(前は detached の作業ツリー)に起こす。声は偽の声サービス(最初のバイト 350 ms・1 字 0.14 秒)にして、本物の声の残りを使わない。画面の Dialogue・Speaker・字幕の流れを node で動かす道具(偽の AudioContext は時計どおりに進め、相対の住所は fetch を包む)で、送ってから「最初の字幕・全部の字幕・最初の声・話し終わり・声の字数」を測る。同じ問いを前の木と後の木で、中継が 1 つずつなので続けて流す。
- 二重送信の偽物の /api/chat(流れる形)は、止められたら本文の流れも止める(本物の fetch と同じ)。止めの合図の受け口を流れの途中で付けると、付ける前に止められた回は待ち続けて、試験が「Promise resolution is still pending」で落ちる。
- 直す前の木で同じ試験を流して落ちること(7 件中 6 件)を見て、直した物を見ている証拠にする。

## 点検で直した事と、残した事(UW3・2026-11-08)
覚えること・個人のこと・仮の頭脳の言い回しの追記(年・2 つの網・言い回しの数・モデル名の部品)は上の節に入っている。ここは、そのあと実機で見つかった外れと直しの学び。

直した(どれも試験つき)
- **学校の話を止めすぎていた**: 「きのう小学校でサッカーした」「たのしい小学校にかよってるよ」「あした小学校で運動会」「いつも幼稚園で」「兄が高校で」まで、直前の言葉(きのう・たのしい・いつも)を学校の名前とみなして止めていた。子どもの一番ふつうの話題で会話が切れる。直し: 学校の名前の網を、時・ようす・助詞の言葉を外した固有の形(あおぞら小学校・第一小学校)だけにした。試験に「きのう小学校で…」の形を足す。
- **主役の返事が毎回同じ 1 文だった**: 人格の「あいづち」が先に当たり、新しい言い回しの表に届かなかった(4 つの別の話に、同じ 1 文)。直し: あいづちを手持ち 6 文にして、回ごとに 2 文の組み合わせが替わる(1 回目は今までの 2 文)。人格の文にあいづちを 4 文足した(口調はその子のまま)。試験は「4 つの話で 3 とおり以上」。
- **「AI なの?」を拾いすぎていた**: 言葉と「?」だけで当てたので「ロボットがすき?」「これ本物のりんご?」「プログラムってなに?」「ぼくのいぬ、いきてる?」まで「AI のキャラクターだよ」になった。直し: 主語が相手(きみ・あなた・キャラの名前)の問い、「中の人」の問い、言葉だけの短い問いに絞る。ひらがなの「なかにひとがいるの?」は当たる。
- **「ぼくのこと覚えてる?」**: 覚えている名前と年があっても、決まりの説明を返していた。直し: 覚えている事を先に言う(「たろうさんで、7さいだよね。ちゃんと覚えているよ。」)。
- **主役は、はじめて覚えた回に「覚えないもの」を言えなかった**(口調が混ざるので足さない決まりのため)。直し: 人格の文に「覚えないものを言う」の行を足し、その子の口調で「おうちの場所や電話は、覚えないので あんしんデス!」を言う。
- 古い試験 3 本と会話の記録の道具(`talk-transcript.mjs`)を、新しい動きに合わせた。

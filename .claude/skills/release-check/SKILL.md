# 公開の前の点検と、履歴の書き換え

## 語の一覧(リポジトリに入れない `*.local.txt`)
- 形は `tools/termlist.py` とフックの `tools/hooks/lib/secret-core.mjs` で同じ。1 行 1 つ、`#` は注。既定は大文字と小文字を区別しない文字そのもの、`cs:` は区別する文字、`re:` は区別する正規表現、`rei:` は区別しない正規表現。
- Python では `re.ASCII` で読む。`\b` が英数字と `_` だけを語の文字とみなし、日本語の隣でも切れ目になる(JavaScript・filter-repo と同じ)。ASCII にしないと「とXYZで」の XYZ を見落とす。
- 英語のふつうの語を含んでしまう短い語は、先読みで外す(例 `rei:<語>(?!d)`)。外し過ぎないよう、写しで「残り 0」を見てから決める。
- 一般の書き方(`C:/Users/...` の説明など)まで語にすると、消せない物が残る。個人のパスは `Users/<名前>` の形で探す。
- 確かめ: `PREPUSH_TERMS=<一覧> python tools/prepush_check.py`(木の全体)、`python tools/history_check.py --terms <一覧>`(全部の履歴)。読めない正規表現の行は、黙って飛ばさず止める。
- ほかの流れの持ち物は自分で直さず、札に「直しの願い」を書く。持ち主の無い物だけ言い換える。

## 履歴の書き換え(`tools/rewrite_history.py`。写しだけ。push しない)
- 保管の線が本流の祖先なら、全部の線を **1 回で** 書き換える(別々に書き換えると、同じコミットが 2 つの違う SHA になる)。`--keep main --keep yurukyara-dev --keep <保管の線>:<新しい名前>` で名前も替える。
- 残す場所 = 残す線の先にあるファイル − `--drop-paths` の一覧。一覧の形: `/` で終わる行はその下の全部、ほかは fnmatch。`old:<形>` は「今の線(既定 main・yurukyara-dev)の先の版だけを残し、古い版を全部の履歴から外す」。
- `--strip-ai-images`: 画像生成の AI の印(IPTC の出どころの種類 `trainedAlgorithmicMedia` と、PNG の文の箱の生成の指示 `parameters`・`prompt`・`workflow`)がある絵の版を外す。署名(C2PA)だけでは外さない(カメラの写真にも付く)。台本に会社や道具の名前を書かない。
- 署名の無い合成の絵(AI の絵を並べた比べの一覧など)は印で見つからない。`old:` で古い版を外す。
- 規則(`--replace-text`)は filter-repo が **literal の行を全部先に**、その後に regex の行を書いた順に当てる。regex はバイト列なので `\b` は ASCII。名前が `_` につながる所(`<名前>_path` など)は `\b` が効かないので `(?i)(?<![a-z])<名前>(?![a-z])` にする。語の一覧が大文字と小文字を区別しない語は、規則も `(?i)` にする(小文字のパスに残る)。JSON の中の 2 重の `\` の形のパスも literal で足す。
- 規則は試験の中の「わざと入れた値」も書き換える。試験のダミー(IP・鍵の形など)は、その場で組み立てる(`".".join([...])`)。
- メールは替えない(本人の答え。`--mailmap` は使わない)。
- 確かめ(台本の中): 語(中身・コミットの文・ファイルの名前)0、AI の印の絵 0、古い版 0、線の先が「前 − 外すと決めた物」と同じ、線ごとのコミットの数。終わりの番号 0 以外は本番にしない。
- 確かめ(台本の外): 写しの線を clone して、構文(Python の ast・`node --check`)、`node --test`(web の部品はジャンクションで借りる。PowerShell の `New-Item -ItemType Junction` で作り、`cmd /c rmdir` で外す。Git Bash の `cmd //c mklink` は引数が化けて失敗した)、公開前の語の点検。木の id(`rev-parse <線>^{tree}`)が前の練習と同じなら、前の試験の結果を使ってよい。
- 書き換えた写しの点検は、release-auditor(読むだけ)と司令塔の 2 回。1 つでも見つかれば公開しない。
- 時間: 389 コミット・3 本の線で 1 回 12 秒ほど(425 コミットで 14 秒)。
- **練習は、合わせで道具が開発の線に入るたびにやり直す。** 道具そのものの古い版(履歴)にも語が入る。自分の線にあるうちは、練習の元(開発の線)に入っていないので見えない。見つかった語は規則に 1 行足して言い換える(今の版に語が無いなら、今の版は変わらない)。
- **台本の外の残りの数え方**: 文字のファイルは全文、絵と形は人が書く文字の所だけ(PNG の文の箱・GLB の JSON・ほかは 6 字以上の文字の並び)。絵や形をそのまま文字にすると、圧縮した中身に短い語がたまたま出て、数十版の取り違えになる。数え方が効くかは、書き換える前の写しで当たる事で確かめる。
- 写しの中で「土 20:00 の形」を作る: `git clone --mirror` → `git -C <写し> worktree add <場所> yurukyara-dev` で流れの線を合わせ、`update-ref` で main を早送り。写しの中だけなので push は要らない。
- 書き換えた開発の線の新しい写しで、README の「3 行で試す」を流す(`npm ci` → 組み立て → 鍵を外して手元のサーバーを自分で起こし、画面・キャラ・会話が答えるか)。止めるのは起こした子の PID だけ。
- 台本は `python -m git_filter_repo` で filter-repo を呼ぶ。filter-repo を利用者の場所に入れていると、`python -I` では読めない(-I は利用者の場所も外す)。書き換えの台本は -I を付けずに流す。
- 練習で合わせる線は決め打ちしない。開発の線より先のコミットがある `w/*` を、合わせの順で全部(`git rev-list --count HEAD..<線>` が 0 なら飛ばす)。2 本の線(開発の線と保管の線)をそれぞれ clone して確かめる。保管の線が本流の祖先なら、`--all` で見るコミットは同じになる(clone は全部の線を remotes に持つ)。
- **先の版で規則が中身を変えたファイルを数える**(台本の report.json の `branches.<線>.changed_by_rules`)。本流で 0 本が合格。規則は試験の見本の値(LAN の IP など)も言い換え、その試験が落ちる(11/6 23:16 の練習で 1 本)。持ち主に「その場で組み立てる形」に直してもらう。保管の線は持ち主が直さないので多くて当たり前(39 本)。
- 書き換えた開発の線の写しで、合わせの門と同じ試験を全部流す(`YC_BROWSER_TESTS=1 npm test`・フックの試験と壊す試験・`tools/test_*.py`・作例の検査 K0 と K1・段の門・作る道と確認画面・描く道具・2D の部品。台本はリポジトリの外に置く)。`node --test` だけでは、Python の試験・作例の検査・フックの壊す試験の落ちを見落とす。
- 時間: 3 本の線・269 コミットで、書き換え 24 秒。練習の全部(写し・合わせ・書き換え・数え・2 本の確かめ・3 行で試す)で 2 分、門と同じ試験で 3 分。

## 公開の組み立て(Vercel)
- Vercel は `web/dist` だけを配る。手元のサーバーはリポジトリの頭の `characters/` を直接配るので、手元で動いても公開では 404 になる。`web/vite.config.js` の組み立ての時だけの部品(`generateBundle` で `emitFile`)で `dist/characters/` へ写し、`web/api/_test/build_characters.test.mjs` で写す物の決まりを試す。
- Root Directory を `web` にしても、画面のコードは外(`creator/viewer/`・`characters/`)を読む。「Include source files outside of the Root Directory in the Build Step」を切らない(2020 年 8 月より後のプロジェクトは最初から入っている)。
- 環境変数は次の配りからだけ効く(足したら Redeploy)。Standard Protection は本番の名前以外の配りを守る(書き換えの前の古い配りも)。
- 取り込むとすぐ既定の線(main)が配られる。GitHub の main が古い版の間は取り込まない(本人のカードに順番を書く)。
- 組み立てた中身(dist の JS など)も公開前の語で数える。大文字と小文字を区別しない語が、使っている部品の中の名前(プロパティの名前など)に当たる事がある。その語だけ先読みで外して、本当の語は当たるままにする(当たる・当たらない例を 4〜6 個流して確かめる)。

## 公開の文書(README・THIRD_PARTY・どう作ったか)
- README は「今できること」を表にし、1 行ごとに確かめ方(試験の命令か、リポジトリの中の記録)を書く。確かめていない事は「まだの事」へ移すか【確かめ待ち】の印を付ける。印は書き換えの練習の台本(リポジトリの外)が数え、公開の前に 0 にする。
- 数字は、リポジトリの中の記録(docs/metrics.md・creator/skilltest/結果表.md・スキルの記録の行)を横に書ける物だけ。板の報告にしか無い数字は書かない。費用は「`claude -p` の total_cost_usd = 定価に直した目安で、請求ではない」と書き、枠やプランの話はしない。
- 言わない言葉の点検は、打ち消しの文(「〜とは言わない」)にも当たる。当たった行を目で見て、順番の意味の「最初の」なども言い換える。
- 根の README だけでなく、木の中の README を全部読む。持ち主の無い README(characters/README.md)に、古い出どころ(開発の途中の別の AI)が残っていた。直しは 1 本の別のコミットにして、合わせ係が分けて扱えるようにする。
- THIRD_PARTY の版と著作権は lock と node_modules の LICENSE から取る(`package-lock.json` の packages の license 欄。dev の印で、組み立てに入る物と試すだけの物を分ける)。@mediapipe/tasks-vision は LICENSE のファイルを持たない(欄だけ Apache-2.0)。顔のモデルのモデルカードは PDF で、ここでは文字を取り出せなかった(使用条件は【確かめ待ち】)。
- Vite 8 の組み立ては `@license` の注を全部落とす(11/7 に web/dist で 0 件)。MIT と Apache-2.0 は配る物に表示が要るので、`web/vite.config.js` の組み立ての時だけの部品で `dist/licenses.txt` を置き、部品の入った JS の頭に 1 行の注を足した(`generateBundle` で `chunk.code` の頭に足すと、縮めた後でも残る)。部品の名前は `chunk.moduleIds` のいちばん奥の node_modules から読む。Vite の小さな読み込みの部品は名前だけの id(`\0vite/preload-helper.js`)なので vite とする。Vite の LICENSE.md は同梱の部品の長い節(約 98KB)が続くので本体の節だけ。LICENSE のファイルの無い MediaPipe は、型の文書の頭の Copyright の 1 行と、node_modules の中の Apache 2.0 の全文を添える。
- 「3 行で試す」の確かめは、主役のファイル(character.json・model.glb・2d/parts.json・persona.md)と、鍵なしで主役が名乗るかまで見る(台本はリポジトリの外。描画はしない)。

## 改行(`.gitattributes`。審査の人は Windows で取り出すかもしれない)
- md・mjs・js・json・css・html・svg・txt・py・sh などは `text eol=lf`、絵・形・音・動画・字体は `binary`、ほかは `* text=auto`。`eol=lf` は利用者の `core.autocrlf=true` より強い。
- 足す前に、索引の中身が変わらない事を仮の索引で見る: 索引を写して `GIT_INDEX_FILE=<写し> git add --renormalize .` → `git diff --cached --stat` が `.gitattributes` だけ。`git ls-files --eol` に `i/crlf` が無ければ変わらない。
- 確かめは新しい作業フォルダで: `git ls-files --eol` の `w/crlf` が 0、絵と形は取り出した物の hash が索引の blob と同じ、`YC_BROWSER_TESTS=1 npm test` が全部通る。外す時は `git worktree remove --force` と `prune`。
- 今の作業フォルダを LF に取り出し直す: `git checkout-index -f -a` だけでは変わらない(日付と大きさが同じ物は飛ばす)。先に `git ls-files -z | xargs -0 touch` → `git checkout-index --force --all --index`。`git status` が空のまま。
- 中身を丸ごと比べる試験や、ファイルの hash を基準にする検査は、改行をそろえてから比べる(基準を CRLF の木で取ると、Mac・Linux と LF の Windows で落ちる。作例の検査 K0 の body.svg がそれだった)。

## 試験を python -I で流す
- git の pre-push は `python -I` で呼ぶ。-I は台本のフォルダを読み込みの道に足さないので、同じフォルダの部品は `sys.path.insert(0, <台本のフォルダ>)` で読む。試験は `tools/test_isolated_mode.py`(写した 3 本を小さな偽のリポジトリで -I で呼び、手元の空のリポジトリへの送りで pre-push の 1 行も通す)。
- -I では PYTHONIOENCODING・PYTHONUTF8 も効かない。子の日本語の出力は画面の文字の決まり(日本語の Windows なら cp932)になるので、試験は終わりの番号と英数字の部分で見る。人が読む時は `python -X utf8` で流す。

## フック(`tools/hooks/`)
- 鍵の見張りは、Write・Edit・MultiEdit の **書く先がリポジトリの中の時だけ** 見る(外の板やメモは記録に入らない)。相対パスは入力の `cwd` から見る。字面とリンクを解いた場所のどちらかが中なら中。`..` で外へ出る道と、名前の頭が同じ隣のフォルダは外。
- 段の関所は毎回止める。人が決めた無人の通しだけ `YC_AUTOPILOT=1`。登録は今は UserPromptSubmit だけ(Skill の `tool_input` の名前を確かめてから足す)。
- わざと壊す試験(`node tools/hooks/test/mutation.mjs`)を、見張りを足すたびに増やす。壊し方が当たらない(置き換えの文字が古い)時も「見逃し」と数える。

## 期間の表・数字の表・公開の関数
- 期間の表: `tools/provenance.py --public-md docs/期間の表.md`。比べる相手のパスは台本の外にだけ書く。「前に作った」の語の手がかりは中身を読んで `--checked` で理由を付ける。表は HEAD を見るので、コミットの後に作り直す。ファイルを足したら本数が変わるので、もう 1 回作り直す(454 本で 1 分ほど。札 `--kind cpu --procs 6`)。
- 数字の表: `tools/metrics.py … --check-numbers` で出どころの無い数字 0。同じ入力なら 1 文字も変わらない。
- 公開の関数: 合言葉なし・違う・上限・数えられない・頭脳の失敗は、断らずに仮の頭脳で答え、理由と「仮の頭脳です」を返す。

## 公開の関数の守り(11/7 S6w7。守りの点検 CRITsec の直し)
- 入口が手元のサーバーと同じ手伝いを本当に呼んでいるかを、約束の文(API.md)と import で突き合わせる。試験が手伝いを直接呼んで通っていても、入口が呼ばなければ公開では動かない(記憶 chatMemory を呼んでいなかった)。仮の頭脳も `runTurn(body, { brain: 'mock', paceMs: 0, memory, learned })` にして、人格・安全・記憶を本物と同じ道で通す。
- 合言葉は「当たった後の数え」だけでなく「間違いの数え」も持つ(接続元ごとと全体。超えたら比べない)。**合言葉を比べる道は全部**同じ守りを通す(番号づくりの /api/memory/pair も 403 と 401 の違いで当たりが分かった)。送らない回は数えない。短い設定(16 字未満)では本物を使わない。両側で trim。
- お金を数える所は、置き場が無い時に「止める方」へ倒す。Vercel の上は `VERCEL` などの環境変数で見分け、関数の中のメモリへ落とさない(手元の試験は前のまま)。
- 試験は直しを 1 つずつ外して落ちる事を見る(置き換えて流し、元に戻す。10 か所すべて少なくとも 1 件落ちた)。ほかの流れの試験の呼び方(cfg に合言葉を入れず環境変数で渡すなど)も壊さない。「cfg を先に、無ければ環境変数」にそろえた。
- CSP は `vercel.json` で付け、手元で Vercel の形をまねる小さなサーバー(dist を見出しつきで配り、/api を関数で答える)と GPU の Chrome で確かめる(`web/api/_test/csp_browser_check.mjs`)。MediaPipe と meshopt は `'wasm-unsafe-eval'` が要る。GLB の中の絵は blob: を fetch で読むので `connect-src` に blob:。外の通信は Playwright の route で偽の返事にする(CSP に止められた通信は route に届かない = 止まった証拠)。わざと狭めた CSP で NG になる事も見る。
- 手元のサーバーには CSP が無いので、ほかの流れは CSP の違反に気づけない。画面のコードが変わる合わせの後に、CSP の確かめをもう 1 回流す。style は他の流れの画面を壊さないよう 'unsafe-inline' を許し、script は許さない。
- README の手順は、新しい clone でそのとおりに押して確かめる(`npm ci` → `npm start` → 作る道 → /qr のリンク → 枠に言葉 → 試しの道 `yuru_make.py next --fake-draw` → この子にする → もう一度)。サーバーは鍵を外して自分の PID で起こし、終わったら PID だけ止めて番号が閉じた事を見る。
- 上書き止めは、指示文に入る全部の欄にかける。目印の文字([NAME] など)を欄ごとに入れて 1 回組み立て、どの段に入るかを見る(demo3.mjs の形)。(守りの点検の学び。司令塔が木の版に足した物をここへ移した)
- 試しは scratchpad から repo の部品を読むだけにし、本物の鍵は使わず、偽の頭脳の宛先(127.0.0.1)を自分で立てる。

## 合わせで返された時(11/7 S6w7b)
- 線を作った後に、ほかの流れが約束(K0〜K6)へ欄や条件を足して先に入ると、自分の試験が落ちて返される(合わせ⑦: 公開の番号の受け取りに合言葉・「わすれて」のイベントに `via: 'chat'`。どちらも S3 の K4)。渡す前に `git diff <自分の土台>..yurukyara-dev -- web/server/memory/API.md`(ほかの約束の文も)を読み、開発の線を取り込んで門を流す。

- 取り込むと、開発の線が渡された番号(b4988ba)より先(司令塔がスキルを置いた 51d37a9)に進んでいる事がある。取り込みのコミットの文には、実際に取り込んだ番号を書く。
- CSP の確かめは 127.0.0.1 で開くので、S5 の「?character は id だけ」(この PC の中で開いた時だけ外の URL を読む)が外れ、⑥ は CSP の層をそのまま試せる(公開の URL では id だけの決まりが先に止める。2 重)。初めての訪問の 7 歩の札は右下に出るが、文字の欄と「送る」は押せるので、道具は直さずに 6/6 だった。

## つまずき
- Bash の heredoc で Python を流し、文字列の中の `\n` を含む置き換えをすると、合わずに止まる事がある。複数行の置き換えは Edit の道具でする。heredoc の中で台本の文を作ると、引用符つきの `<<'EOF'` でも `\n` が本物の改行になって壊れた。改行は `chr(10)` で書く。
- 司令室のカード: `hub.py edit` は中身を 1 つも変えない直しを受け付けない(`--note` だけは不可)。詳しい手順は 600 字まで。書いた時刻は `date` で測ってから書く(推しはかった時刻を書いて、訂正を足すことになった)。
- このセッションは `.claude` の下に書けない(設定の守り)。スキル・点検役の案は板に置き、書ける人に渡す。命令で迂回しない。
- 札の道具の `run` で bash を呼ぶ時は、Git の bash の場所(`cygpath -m /usr/bin/bash.exe`)を渡す。ただの `bash` は別の bash になり、Windows のパスが見えない(`sh <台本>` で渡すと Git の sh で動いた)。
- `git ls-files` は日本語の名前を引用符と 8 進の形で出す(core.quotepath の既定)。`\.png$` のような探し方で漏れるので、`git -c core.quotepath=false ls-files` で数える。
- PowerShell では `sh` が無く、`bash` は別の bash(WSL)になる。札の道具の `run -- sh <台本>` は Git の bash(Bash の道具)から呼ぶ。
- 札の道具の `run` は shell を通さずに子を起こすので、Windows では `npm`・`npx`(.cmd)を直接は呼べない(`node` は呼べる)。npm・npx は Git の sh の台本に書き、`cygpath -w "$(which sh)"` の場所を渡す。GPU の札は空きが無いと並んで待ち(`--wait 30`)、空いたら自動で流れる。
- `cat -A | grep '\^M'` は日本語の UTF-8 の表示(`M-^…`)にも当たる。CR は `git ls-files --eol` か `grep -c $'\r'` で数える。
- 司令室の `hub.py ask` は、選択肢 1 行 40 字まで・危険の行 100 字までで止まる。長い説明は --context に入れる。`hub.py edit` の `--note` は 1 行 80 字まで、`--detail` は 600 字まで(先に `len` を数える)。`hub.py proceed` は既にある問い(Q-)にだけ付く。
- `yuru_make.py next` の最後の JSON は複数の行にまたがる(行頭の `{` から終わりまでを読む)。最後の 1 行だけ読むと、通ったのに「失敗」と数えた。
- 提出の下書き(リポジトリの外に置く): 欄に貼る所を、2 つの語の一覧(termlist)と「言わない言葉」で数えて 0 にする。確かめていない事は【確かめ待ち】の印で残し、司令塔が外す。出す・公開するのは本人だけ。

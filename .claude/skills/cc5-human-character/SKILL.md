# CC5 で写実の人間を作り、会話の画面で話させる

> **先に守ること(偽の窓口の比べで、読んだのに破って落ちた回が出た):** 調べている間は保存しない。Refine Face を開く前に `GetLandmarks` を呼ばない(CC5 が落ちる)。飾り付きと男性用のプリセットを当てない。

2026-11-02 夜〜11-03 に、架空の大人の女性 1 体で通した記録から書いた(測った物だけを数字にしている)。CC5 と、その公開の MCP(外の道具)は部品として使うだけで、このリポジトリには入れない。

## 0. 先に決めること(規約と置き場)

- **CC5 のキャラの GLB・FBX・テクスチャは、公開のリポジトリにも公開の URL にも置かない。** 手元の PC でページに載せて動かし、その画面を録画して動画にする。理由: Reallusion の Software EULA は「ウェブサービスへの書き出し」を許す一方、Content EULA(同梱の髪・服・モーフなど)は「アプリ・オンラインサービスへの組み込み」を禁じ、組み込みはエンタープライズだけの項目になっている(2026-11-02 に公式 4 文書を引用つきで調査。**文書同士が食い違い、書面の確認は取っていない**)。画像・動画に映すことは明確に許されている。
- 試用版は使わない(商用の権利が無い)。購入済みの CC5 だけ。
- 使った髪・服・靴・肌の素材は、出どころと段(iContent か Standard か)を表に残す。段は CC5 の画面やファイルからは見えなかった(MCP でも不可)ので、Smart Content Manager か Reallusion のアカウントで確かめる。iContent は書き出しに使えない。
- 実在の人に似せない。実在の人の写真を入れるときは本人の同意が要る(Reallusion の AI Service の規約にも、他人の写真は許可なしに上げない決まりがある)。CC5 内の AI 画像生成(トークン)の出力は、無料枠では商用に使えない。
- 期間内の新作だけ。既存のキャラ・既存の CC5 プロジェクトは読み込まない・写さない。毎回、新しいプロジェクトを作る。

## 1. 会話の画面との契約(読むだけ。リポジトリ側は触らない)

`docs/共通の決まり.md` の `loadCharacter(url)` は `characters/<id>/character.json` を読む。写実の人型は `type: "rig"`(骨とシェイプキーの GLB)で渡す。`creator/viewer/rigRuntime.js` が読む形:

- `model`(骨つき GLB)、`motions`(動きごとの別 GLB。骨の名前は model と同じ。1 つの GLB に 1 つの動き)。`idle` はいつも流れ、`talk` は口を動かすと混ざる。
- `mouth: {kind: "morph", morph: <口を開くキー>, gain}`、`blink: {morph: <まばたきのキー 1 つ>}`、`morphs: {<表情名>: {<キー>: <重み>}}`、`look: {bone, eyes: [目の骨], head_bone, max_deg}`、`expressions: [...]`、`height_m`、`lift`。
- `lift`(明るさの持ち上げ)の既定 0.55 は、ぬいぐるみ用。写実の肌には 0.25 が CC5 の頬の色にいちばん近かった(0.55 は約 30 階調明るすぎ、0 は約 20 暗すぎ)。
- 頭の位置は、既定では全身の高さ × 0.6 で、人物では低すぎて目の高さのカメラを見上げる。`look.head_bone`(頭の骨の名前)を書くと骨の位置を使う(キャラの持ち主の対応。書くとまっすぐカメラを見た: 黒目の上向き 24° → 2.4〜2.9°)。
- 契約のキーは 1 つの名前で全メッシュに効く(同じ名前を顔・まつげ・歯・舌のすべてに付ける)。

## 3. CC5 の操作(MCP `cc5` 経由。マウスなし)

- 別の PC の CC5 は、ssh のトンネルで手元の PC の 127.0.0.1:5101 につなぐ(橋の待ち受けは 5101 固定。橋は Host ヘッダが `127.0.0.1:<待ち受けの番号>` と一致しないと 403 で断る。トンネルの手元の番号を変えると断られる。MCP も 1 つのインスタンスで 5101 固定なので、2 台の CC5 を同時に別々の作業役で操作できない。順番に使う)。
- プロジェクトごとに CC5 を新しく起動する(動いている CC5 に別のプロジェクトを開くと、画面が黒くなる)。起動から橋が応答するまで約 80 秒。HD の標準の土台を読むのに約 60 秒。
- 小窓(更新・ライセンス・購入)は押さない。「Unsaved project data found」は、**自分が起動して自分の PID で止めた CC5 の次の起動**で毎回出る(自動保存の復元の確認)。その場合だけ Cancel(`click_ui_button` は文字に「update」を含む窓を断るので、`exec_python` で Qt の QMessageBox の Cancel を押す。`CC5_ALLOW_EXEC=1` で起動したときだけ可)。最初に起動したときにこの窓が出たら、誰かの未保存データなので押さずに報告する(別の人の物を捨てない)。結果は止める前に別名で保存しておく。
- Headshot 3 の写真の道(オフライン): 写真を **クリップボードに入れて貼る**(ファイルを選ぶ窓に文字を打たない)。サブ機では、対話の画面で動く一回きりの予約タスクで PowerShell(-STA)にクリップボードを入れ、`click_ui_button` で Headshot のパネル(`qtHeadshot3PanelToolbar`)→ 貼り付け(`qtProPhotoPasteToolButton`)→ 体のタブ(女性)→ GENERATE。写実の写真の正面 1 枚で、顔の点のエラーは出ず、生成に 255 秒だった(AI ポイントは減らない)。この道には「髪・眉・まつげの削除」の選択肢が無い(それは AI 画像生成の側)。
- 正面と横を同時に入れて GENERATE したら、進みが 20% のまま 20 分止まった(1 回の観察。原因は横の絵か、予約タスクの二重起動か、分かっていない)。正面だけの 2 回目は別に試した(結果は 4 章の表)。**30 分で見切って CC5 を閉じ直す。**
- 髪の色: `set_hair_color` は拡散色に掛け算するだけ。見える色は髪のシェーダーの RootColor / TipColor / 第 1 染色の色で決まる。
- 服: 入っている素材の色合わせ(拡散色の掛け算)では、柄が残る(縞のシャツの色を紺にしても縞は消えない)。絵と同じ服が素材にないときは、近い物を選んで差を記録する。
- 8 方向の撮影: アバターを `/workflow/transform/set` で回し、そのつど `/ui/capture_crop view=front`(同じ枠)。靴を読んだ後の `capture_views4` は、選択した物(靴)だけを写した。全身には `capture_framed_crop view=front`。
- FBX の書き出し: ブリッジの `/export/fbx` は `target_tool: "Blender"` を受ける(MCP の道具の選択肢には無い)。HTTP は 30 秒で時間切れになるが書き出しは完了する(約 90 秒)。`/health` で待つ。
- 表情は 379 本(CC5 MetaHuman 型、ARKit 対応)。まばたきは `Eye_Blink_L/R`(左右別)、口は `Jaw_Open`、目の骨は `CC_Base_L_Eye/R_Eye`。「viseme」という名前のスライダーは無い(口の形は `V_Open` など)。書き出しの FBX の中の名前は公式の文書に載っていない。**取り込んだら必ず数えて確かめる**。

## 4. 入力の絵の決まり(絵はリポジトリに入れない。構図の決まりだけ)

Headshot 3 に入れる絵は、使う人が自分で用意する(撮るか、画像生成)。次は 2026-11-03 の実測と、Reallusion の公式説明の突き合わせ(「確認済み」は実機で確かめた物だけ)。

| 項目 | 決まり | 確認 |
|---|---|---|
| 向き | 真正面。傾けない・回さない。両耳が同じ見え方 | 実機(正面 1 枚で通った) |
| 横の絵 | 真横(90°)、顔が画面の左向き。入れる窓は Generate Character の横の欄 | 窓を確認。横を同時に入れて固まった例がある(上記) |
| 表情 | 無表情で口を閉じる。目は開いてカメラを見る | 方針(実機の比べは 4 章の下の表) |
| 髪 | 顔にかけない。額・生え際・耳を出す | Headshot 3 の公式説明と実機で確認中(下の表) |
| 眉・まつげ・生え際の根元 | **消さない**。根元の形が大事で、消すと失敗した前例がある | 本人の経験。実機の比べは下の表 |
| 光 | 影の少ない均一な正面の光。背景は無地 | 方針 |
| 服 | 無地で控えめ。肩から上だけ | 方針 |
| 解像度・顔の大きさ | 1254×1254 の正方形で、頭が高さの約 70% | 通った実績(下限は未測定) |
| 悪い例 | アニメ調の平たい顔(顔の点が取れない)、髪が顔にかかる、笑顔(口が開く)、横を向いた顔、強い影 | アニメ調は別の実機で確認済み |

- 写実の入力の絵は、画像生成で作ってよい(今回は画像生成 AI の画像)。有名人・実在の人に似せない言葉を必ず入れる。画像生成の安全フィルタは、「谷間なし」のような否定の書き方で逆に止まる。「高襟のコルセットと小さな胸」のように肯定で書く。腕を大きく開く姿勢・網タイツ・お札を服に挟む描写は 3 回続けて止まったので、手を下ろす姿勢・お札はリボンに、で通った。
- 髪なしの絵(帽子・羽も消す)は、髪の毛を消した実写の絵として作れた(1 件 40〜90 秒)。眉毛は残る。まつげは、濃いまつげのまま(n1)と、消した版(nl1)を別に作れる。

### 比べの結果(2026-11-03、案 3 の顔、髪と帽子なし・眉は残す、正面 1 枚の写真の道、サブ機)
お手本との比率のずれの合計(正面と真横。小さいほど近い。n1/n2 をお手本にした)と、生成の時間。AI ポイントは使っていない(385 のまま)。

| 通り | 型(顔・口・あご・目・鼻) | まつげの絵 | ずれ | 生成 |
|---|---|---|---|---|
| P1 | 選ばない | あり | 285.1 | 約 4〜6 分 |
| P2 | 選ぶ | あり | **268.8**(最小) | 約 6 分 |
| P3 | 選ぶ | なし | 275.9 | 約 5.7 分 |
| P4 | 選ばない | なし | 299.6 | 約 8.8 分 |

- **型を選ぶと、ずれが 16〜24 下がった**(P1 → P2、P4 → P3)。生成の前に、お手本を見て型を選ぶことを、必ずやる手順にする(顔・口・あご・目・鼻の各タブ。選んだら 5 タブを 1 枚に撮って、全部入ったか確かめる)。
- **まつげなしの絵は、ずれが 7〜15 大きくなった**(P2 → P3、P1 → P4)。ただし、お手本が「まつげあり」の絵なので、まつげなしの絵そのものの違いも数字に入っている。見た目は、まつげありの絵だと、写真のまつげとアイラインがまぶたに黒く焼き込まれ、CC5 の立体のまつげと二重になる。まつげなしの絵はすっきりする。
- 4 通りとも、頭の皮はつるつる(髪の殻・穴・首の継ぎ目なし)、眉は写真のまま肌に入った。目の色(青緑)は入らなかった。横顔は、4 通りとも鼻の付け根がやや低く、あご先が引っ込む。
- 別の AI(DeepSeek v4.1 Flash を 3 回、別々に)の判定: 「4 通りのうち絵にいちばん近い」は **3 回とも P2**(数字の最小とも一致)。「同じ人か」は no〜partly で、回ごとにばらつく(同じ画像で 3 回の答えが一致しない。1 回の判定で決めない)。「目とまつげが自然か」は、P1・P2 は 3 回とも partly、P3・P4 は回ごとにばらつく。
- **結論を取り下げる(同じ日の後の検証、2026-11-03 02:00)**: 「P2 が最良」は**言えない**。理由は 2 つ。①この「ずれの合計」は、顔の違いより**撮る角度の違い**を測っていた。横顔のお手本は真横ではなく約 47° で、合計の 77〜80% がその横顔の項から来ていた。正面も、写真が CG より約 6° 傾いていた。角度をそろえて測り直すと、4 通りの差は、同じ project を撮り直したときの揺れと同じくらいになった。②別の AI の判定は、一覧の絵に**印刷してあったずれの数字(「ずれ269」など)を読んで** P2 を選んでいた(数字や題名を絵に入れた一覧を判定に使うと、判定が数字に引きずられる)。
- 使える結論は次の 2 つだけ: (1) 生成の前に型を選ぶ手順は、顔・口・あご・目・鼻を、お手本を見て選ぶ(効果の大きさは未確定)。(2) 写真のまつげを入れると、写真のまつげとアイラインが肌に黒く焼き込まれ、CC5 の立体のまつげと二重に見える(見た目で確認できた事実。まつげなしの絵を作る・立体のまつげのほうを外す、の比べは今後)。
- **測り方の決まり**: ①お手本の写真の角度を先に測って(ほぼ真正面・真横になっているか)、角度をそろえてから比べる(横は 90°±5°、正面は ±3° 以内)。②判定の AI に渡す絵には、数字・題名・正解を示す語を入れない(ラベルは P1…P4 の記号だけ。順番も入れ替える)。③同じ project を撮り直した差(雑音)を先に測り、それより大きな差だけを「違い」と言う。

### 絵のほかに要る物の一覧(CC5 側)
- 髪: CC5 にインストール済みの髪の型から近い物を選び、シェーダーの色で合わせる。ボブ・前髪など。絵と同じ髪が無ければ、Blender で作るか色や形を直す。
- 服: 絵と同じ物が素材にあるとは限らない。無ければ、近い物+差の記録、または部位ごとに Tripo(丸い・ひだの多い物)と Blender(体に沿う物)で作る(5 章)。
- 体型: 全身の絵(A ポーズ・手が見える・足元まで)。Headshot の体は「女性・標準」から始める。

## 5. 服・小物を作る(CC5 の素材に無いとき)

- 体に沿う物(コルセット・手袋・タイツ・チョーカー)は Blender。ひだの多い物・帽子・羽根・ブーツは Tripo(4 方向の絵 → 4 候補)で作り、Blender で整える。
- スカートの通し(Tripo 1 部位 100 クレジット、4 候補、各 約 1 分): FBX は四角が残り、GLB は三角。腰の輪が開いている・閉じた円盤がない物を選ぶ(真下から見ないと分からない)。Tripo の腰は体より細い(63.8 cm 対 86.2 cm)ので、帯で約 1.45 倍に広げ、裾へ向けて 1.32 倍に戻す。体の中に入った点は「最寄りの面 + 3 mm」を押し戻す(4 回で 0 点)。重みは「骨盤・太もも・ふくらはぎの決まり + 体から 8 cm 以内は体の重み + 半径 5 cm で 4 回ならす」。Blender の Data Transfer は、0.01 倍の親の体からだと半分の点が空になるので、最寄りの面の頂点の重みを Python で写す。ゆっくり歩き(太もも 18°・膝 36°)で、体の中の点は 0.039%・深さ 1.63 cm。大きな歩幅(24°・56°)は 0.9%・2.9 cm で基準外 → 布の計算が要る。
- 別の AI の指摘: 色が付かない(Tripo の Smart Mesh は灰色)、前の透ける下の布が無いと素脚が見える、素材が厚紙のよう。

## 6. FBX → Blender → GLB(写実の人型)

- CC5 は glTF を書き出せない。FBX を Blender(5.2、背景モード)の標準の読み込みで取る。骨組みは 0.01 倍で来て、CC の姿勢は動き(action)に入っている。
- 手順: 休みの姿勢に CC の姿勢を焼き込む(姿勢ごとに評価して `pose.armature_apply`。読み戻すと 0 mm の差)→ 親を外して拡大を適用 → 親を付け直す → 足を z=0 に。向きは前が +Z(ページの契約)。
- シェイプキーはページ用に**自分で作った少数**だけにする(CC の生の 350〜396 本は落とす。落とさないと GLB が重い)。`blink`(Eye_Blink_L/R を合成)、`mouth_open`、表情(`happy` `sad` `surprised` `think` `relaxed`)。Blender 5.2 は `shape_key_add` の後に `kb.value = 0` を必ず書く。ドライバーは glTF に残らない → 骨の動きの分も含めて、評価した値を焼き込んだキーにする。表情の骨の部分は、CC の書き出し json(`Object/<名>/Expression/<キー>/Bones`)から読む(`Jaw_Open` = あごの骨を局所 +Z に 23.4°)。
- 口: `V_Open`(あご 16°)+ `Jaw_Open` 0.25 を元にして、上唇を上げ、舌を奥と下へ(`Tongue_Down` `Tongue_In` `V_Tongue_Lower` を足さないと舌が口いっぱいになる)。舌と歯を暗くする(glTF に AO は無い)。
- 笑顔は口角だけでは笑顔に見えない。頬の持ち上げ・目の細め・下まぶたの持ち上げ・ほうれい線を足す。まばたきと笑顔は左右の平均を取ってよいが、口には使わない(唇と歯の層が数 mm 以内に重なっていて崩れる)。
- 材質: 肌は SSS なし(色に焼き込む)。まつげ BLEND、髪 MASK 0.5・両面、角膜 BLEND(α 0.06、粗さ 0.03)。目の影の輪と涙の線は、グラデーションを焼かないなら非表示(α 0)。虹彩・服・髪の色・頭皮の暗さは、CC のシェーダーがやっていた物を焼き込む。
- テクスチャは 2048 以下。三角面は 11 万(FBX と同数、間引かずに通った)。GLB は約 20 MB(テクスチャ 46 枚)。
- 動き: モデルは動きなしで出す。`idle` と `talk` は骨だけの GLB を別に出し(`export_animation_mode ACTIONS` でクリップの名前が付く)、骨の名前は model と同じにする。
- 髪(別の AI の指摘で直した所): 頬・首に食い込む点は肌の 4 mm 外へ押し出す(表面から約 12 mm 以内の点だけ。頭皮の側へは引かない。引くと平らになり頭頂が下がる)。分け目のすき間は髪のカードが元々無い所で、直すには髪の作り直しが要る。

## 7. 検査(`tools/check_glb.py`)

`python -I tools/check_glb.py <作業フォルダ>`(`<作業フォルダ>/pack/model.glb` と動きの GLB を、標準の Python で読み戻して数える)。比べる物: 骨・メッシュ・頂点の数、シェイプキー名の集合、使うキーが全部あるか、どれかが全部 0 でないか、高さ(FBX と 1 mm 以内)、テクスチャの数と大きさ(2048 以下)、三角面の合計、動きの骨の名前が model と同じか。`creator/pipeline/pk02_check_character.py` も(読むだけで)通す。

## 8. 会話の画面での確認(リポジトリの外のテストページ)

- 小さな HTTP サーバー(127.0.0.1 だけ)と import map で `loadCharacter` を読み、ヘッドレスの Chromium(playwright-core)で撮る。状態: ①無表情 2 コマ(雑音の大きさを測る)②`setMouth(1)` ③まばたき ④`setExpression('happy', 1)` ⑤`lookAt` を左と右の遠くへ ⑥待機を 1 秒あけて 2 コマ。顔の領域の平均の画素の差を測る。
- 実測(架空の女性、2 周目): 口 20.7、まばたき(目)10.3、笑顔 9.5、視線 40.1 / 47.8、待機 8.1(雑音 0.0)。ほかに、悲しみ・考え・くつろぎは顔全体の線に届かない(口まわりだけが動く小さい表情)。
- 別の AI の判定は、画素の差と別に取る。判定の問いは「両目が閉じるか」「口は自然か」「視線が左右に向くか」「笑顔は自然か」「同じ人か」「本物の人か人形か」。人形に見える原因として、髪の平らな帯、つやのない目、つるつるの肌、同じ型のそばかすが挙がった。

# 絵の引き伸ばし・キーボード・窓の戻る操作(第 12 波 b。IOS1・QF5)

(元の文のまま)

### 絵が細長い・平たい(本人の iPhone の Chrome で、7 つのステップの札を開いた時にノリーが約 3.8 倍細長く写った)
- **原因**: 描く大きさ(drawing buffer)と画角の縦横(`camera.aspect`)を、窓の `resize` の時だけ合わせていた。窓の resize が来ないまま canvas の箱だけが変わると(Chrome のツールバー・裏のタブで読み込んだページ・隠れている間の回転・0x0 の箱で起動して窓の大きさで決めた時)、古い大きさの絵が新しい箱へ引き伸ばされる。
- **直し(three.js の「表示の大きさに合わせる」形)**: `scene.js` の `syncSize()` が canvas の `clientWidth/clientHeight` を、前に合わせた大きさ・`canvas.width/height`(端末の段の倍率のまま)・`camera.aspect` と比べ、違えば合わせ直す。`main.js` は毎フレーム(描く直前)と、canvas の ResizeObserver・orientationchange・pageshow・visibilitychange・visualViewport の resize で `syncStage()` を呼び、合わせ直した時は `fitBottom()`(下の余白は画面の高さで決まる)→ 置き直し。箱が 0x0 の間は窓の大きさで決めない(本当の箱を待つ)。`frameCharacter` も最初に `syncSize()`(古い縦横で置くと頭や足の計算もずれる)。2D の板も同じ canvas なので一緒に直る。
- **再現のしかた**(iOS の Chrome は手元に無い): Playwright で、アプリより先に入れる台本(addInitScript)で窓の `resize`・`orientationchange` をキャプチャで `stopImmediatePropagation`、visualViewport の `addEventListener` を包んで止め、844x390 で起動 → 始める → `setViewportSize(390, 670)`。直す前は、描く大きさ 1266x585 のまま・縦横の差 3.72 倍・1 m あたりの横と縦の px の比 0.269・キャラの幅÷高さ 0.154(PC は 0.55〜0.56)で、Chrome でも Playwright の WebKit でも同じ数字だった。本物の iOS シミュレーターの Safari では WebDriver で、始めた後に `#stage { width: 55% }` を足して箱だけ変える(窓の resize は 0 回)と、直す前は 1.81 倍ずれ、直した後は 1 以内。
- 自動の試験 `web/test/stage_size_browser.test.mjs`(`YC_BROWSER_TESTS=1`): 組み立てを一時フォルダへ作り、窓の resize なしで縦 390x670・横 670x390・縦 390x844・箱だけ 60% に変え、描く大きさと画角が箱の 1% 以内、キャラの縦横が PC の 3% 以内を見る。直す前のコードでは 3.05 倍ずれて落ち、直した後は通る(7 秒)。キャラの縦横は readPixels の不透明な所(α > 160)で測る(床の丸い影は α 0.55 までなので入らない)。比べる時は `character.update/lookAt/setMouth` を止めて同じ形にする。直した後の同じ再現では、描く大きさが箱 × 1.5 で縦横の差 1.000、キャラの幅÷高さ 0.56〜0.59。
- **`translate: 0` も「中の `position: fixed` の基準」を作り変える**(キーボードの直しの落ち): `.top { translate: 0 var(--kbt, 0px) }` を常に付けたら、`.top` の中の固定の物(見た目の切り替えなど)が `.top` の `top: 12px` の分だけ下がり、キーボードが無いのに 390x670 の上の段の下が 196 → 208px になって、頭のすき間が決まり(40.2px)を割った。transform・translate・filter などは値が 0 でも基準を作るので、キーボードの時だけの規則は `html.kb-open` の下にだけ書く(`style.css` と `onboarding/styles.js`)。確かめは、見える範囲だけを縮めるまね(visualViewport を偽物に差し替え、height を返す)で、キーボードなしは translate が none・336px のキーボードで入力欄と「送る」が見える範囲の中。`keyboardInset.js` は、ボタンのフォーカスが外れただけでは何もしない。
- 入口に戻る件の調べ(直していない): 7 つのステップを Chrome で通して測ると、GPU の形 43・絵 8・舞台の絵 約 8MB・JS 15〜33MB で、見本の子を出しても増えるのは形 5・絵 2 だけ。大きなメモリを持つ物は見つからなかった。戻った 2 回は、どちらも声(読み上げ)が鳴っていた回で、声が「字幕のみ」の回は戻らなかった(Safari の描く係・音の係が落ちた可能性。未確定)。実機で、声ありで 6 つ目のステップ〜「はじめる」の後 30 秒を見て、戻るなら声を「字幕のみ」にして同じ所でも戻るかを見る。

### キーボードと字幕の箱
- 画面のキーボード(iOS)は「見える範囲だけ縮む」。下に貼った帯は `--kb` だけ持ち上げればよいが、キャラは全画面の中央に置かれ、キーボードの裏に隠れる。直し: キーボードの高さも「下の帯」に数え(`stage.state.kbInset`・`bottomInset` に足す)、`fitBand` の上限(0.5 → 0.85)と下限(0.3 → 0.17)をキーボード中だけ広げる。見える高さが 640px 未満は `html.kb-tight`(字幕 1 行・考え中の札・札の列を隠す)、400px 未満は `kb-short`(上の段も隠す)。確かめは visualViewport の偽物を入れ、窓は縮めない(窓を縮めるまねは実機と違う)。
- 返事の字幕の箱(.subs)は実際の高さを測って下の余白にする(見込みだけだとキャラの足にかかる)。ただし低い画面(390x670)では「キャラに残す高さ 36%」を割らない所まで(さもないと頭のすき間の決まりが割れた)。テレビ表示・キーボードの出入りで前の最大は捨てる。
- 縦長のテレビ表示は字を画面の幅の 8% までにして 5 行(高さの 6% では 1 行 7 文字で切れた)。

### 窓・全画面・控えの子・入口・札の列
- 全画面の間の Escape はページに届かない(ブラウザが全画面だけ戻す)。`fullscreenchange` で、テレビ表示も一緒にやめる。
- 窓(引き出し・Quest の箱・テレビの手順・テレビ表示)は開く時に `history.pushState` を 1 つ積み、`popstate` で閉じる。ボタンで閉じた時は `history.back()` で積みを戻し、その popstate は数えない(カウンター)。
- 控えの子(見た目の切り替えの控え)は、舞台から外したら `releaseGpu`(形・材質・絵だけ捨てる。戻せば自動で作り直される)。3D/2D を 6 回切り替えて `renderer.info.memory` が 51 形・19 絵のまま → 見えている方だけ(38/6 か 14/15)になった。共有の部屋の光と毛羽の絵は、舞台から外れた子の後片づけで捨てさせない(部屋の光が消えた)。
- 入口(.gate)は `place-items: start` + 子に `margin: auto` で「余りがあれば真ん中、足りなければ上から並べて巻ける」(`place-items: center` は上が切れて巻けない)。
- 札の列(チップ)は nowrap + 横巻きだと右が半分切れて見える。wrap + `max-height` + `overflow: hidden` で、入らない札を丸ごと隠す。

### 低い PC の画面の VR の箱
- 高さ 670〜720 の PC の画面(Quest のブラウザの窓も同じ)で、字を 14px にそろえると、箱(高さの 45% まで)の中が 7px あふれ、長い URL では「送る」が箱の外へ落ちた(VR の確かめで 16/19)。直し = 幅 761px 以上・高さ 760px 以下だけ、文の列を 260px から 380px に広げて行数を減らし、余白 8px・行間 1.3〜1.35 に詰める(字は 14px のまま)。確かめは `vr_w11_check.mjs`(19 場面。特に send_pc670・send_long_pc・send_long_pc670)。**字を大きくしたら、その字を使う箱は「一番低い画面 × 一番長い文」で必ず測り直す**(スマホの幅は別の規則なので影響しない)。

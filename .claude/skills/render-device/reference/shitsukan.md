# 3D の材質を本物らしく: しつかん(画面で差しかえる。第 12 波 b)

(上の段の切り替えとしつかんの節は元の文のまま。前にあった `?real=1` の節は、2026-11-08 に開発の木のコードと重さの表に照らして、今も合っている事だけを「光と材質の数字」の節に直した。来場者の画面では しつかん のボタンは上の段の「かえる」の中にある。「上の段が混む時」の節は、段が 3 つになる前の形で、いまの形は layout-top-and-frame.md の UW5 の節)

builder が作る材質は「地の色 = 絵の色 × 0.22、発光 = 絵の色 × 0.92、照り 0、ラフネス 1」(`creator/builders/norrie.py` の `flat_mat`)で、three の光(半球 1.0・主 1.7 右上・縁 0.8 青)は色の 2 割しか効かない。つまり、ほぼ発光の平らな塗り(色の変換なし・影なし・環境の光なし・SSAO なし・MSAA だけ)。`applyLift` は発光のある材質を飛ばすので、ノリーには効いていない。着ぐるみ・ぬいぐるみに見せるには、材質を置きかえて光を足す。いまの仕組みは「しつかん」(GLB は作り直さず、画面の中で材質を差しかえて光を足す)の 1 つ。

### しつかん: 上の段の切り替え(既定は ぬの)
- 何: 上の段の「しつかん」(いつもの・ぬの・け・つるつる)。既定は全部の端末で ぬの。GLB は作り直さない。`stage/shitsukan.js` = 決まりと数字、`stage/shitsukanLook.js` = 描き方、`stage/shitsukanSwitch.js` = 切り替え、main.js の専用の塊 = 描く直前に当てる。
- 当てる場所は `stage.render` を包んだ所の 1 か所。舞台の子が替わった次のコマで当たる(見た目の切り替え・見本の子・案内役に戻す、を別々に追わない)。最初のコマの前に当たるので、いつもの が一瞬見えることもない。
- 決める順: `?shitsukan=`(試しと撮影。覚えない)→ このページで押した物 → このブラウザで覚えた物(localStorage `yc.shitsukan.v1`、キャラの id ごと)→ character.json の `looks.3d.material`(作る道が書く。日本語の ぬの・毛 なども読む)→ ぬの。端末の段は見ない。
- 部品の分け方(名前と色の数字。どのキャラにも効く): 輪郭の殻(材質名 Outline・節の名前 `ol_*`)は隠す。顔の部品(頭の 1 語が ink・eye・white・mouth・tooth・pink・blush・cheek・nose など。頭の 1 字を小文字にしてから、語のすぐ後に小文字が続く名前は別の語 = Brown は brow ではない)・顔の表(face の mesh)・色の絵のある半透明の当て布・とても暗い物(線形 0.02 未満)は元のまま。ほかは差しかえる。
- 絵の色の戻し方: 平らな塗り(発光 ≒ 地の色 × 4.2 = ノリーの形)は 発光 ÷ 0.92。持ち上げ(applyLift)だけの材質は地の色。元から光る部品(提灯の紙・ロボの目)は、差しかえても発光を残す。applyLift の前の発光は `material._liftBase` にある。
- 色の変換は差しかえた材質の中だけ(`onBeforeCompile` で `tonemapping_fragment` を置きかえ)。`renderer.toneMapping` と `scene.environment` は触らない(2D の板・VR の板・場所の形・顔の部品の色が変わらない)。部屋の光(RoomEnvironment の PMREM)も材質ごとの envMap。
- 毛は `furShell.js` の `applyFur` をそのまま使う。前に: 体の部品を「色の絵(無ければ 4x4 の白)・法線の絵・sheen」の材質にする / 輪郭の殻を親から外す(毛は毛でない部品の近くで短くなるので、体を包む輪郭が残ると毛が生えない)/ 布だけの小物は sheen を一時 0(色の絵のある小物にも毛が生えた)。後に: 新しい殻は名前 `_fur\d+$` で拾う(外して戻した輪郭を殻と取り違えた)/ 殻の材質の onBeforeCompile を包んで色の変換を足す(clone は onBeforeCompile を写さない)。毛の層の数は段で変えない(6 + 飛び出す毛 2)。重さはスマホと弱い PC で「おもいよ」の一言で知らせる。
- 元から毛のあるキャラ(character.json に `"fur": {}`。空の {} でも JS では毛が付く。Python の `bool({})` は偽なので点検の道具では見落とした)の殻は、いつもの の時だけ出す。毛の準備の前に外す(殻の材質も毛の形の材質なので、外さないと殻にも毛が生えた: 96 → 912 枚)。光る部品には毛を生やさない(ロボの目と口が白くにじんだ)。毛の殻には縁の光を足さない(層の数だけ縁が白く浮いた)。骨で動く殻の箱は、元の部品の箱を写す(後から今の姿勢で測ると、見せ方の箱が広がってキャラの置き方が最大 2.8% 変わった)。

### 光と材質の数字(今の値。正本のコードは `web/src/stage/shitsukan.js` の `LOOKS`・`LIGHT`・`FUR_LOOK`)
2026-11-08 に、開発の木(しつかん B5M が入った後)のコードと `docs/重さの表.md` の L4 に照らして、前にあった `?real=1`(試しの道)の書き方を直した。残したのは、今も合っている事だけ。
- 材質の型: ぬの = sheen(色は 地の色 × 1.7 + 0.04 をつやの強さ 0.38 で弱めた物。白へ寄せると茶色が灰色になる)+ ラフネス 0.86(± 0.08 のゆらぎ)+ 毛羽の法線とくぼみの絵(FFT の帯の雑音。継ぎ目なし)+ 面の照り 0.4。け = ぬのに近い材質(粗さ 0.9・つや 0.4)+ 毛の殻(層 6 + 飛び出す毛 2。毛の殻の rim 0.1)。つるつる = ラフネス 0.55 + クリアコート 1(粗さ 0.12)+ 照り 0.6。
- 光(スマホでも動く物だけ): 部屋の光(three の RoomEnvironment を PMREM で畳む。外の写真は読まない。強さ 0.75、つるつるは 0.65)+ 縁の光(右の後ろの上から、強さ 0.35)+ 足元の接地の影(黒い丸い板・濃さ 0.42)。**物が落とす影の絵とすき間の陰(SSAO)は使わない**(内蔵 GPU の PC で 54 → 18 fps に落ちた)。
- 色の変換: 差しかえた材質の中だけで、色あいを保つ曲線(Khronos の PBR Neutral の式)と明るさ 0.85。映画風の曲線(ACES)は暗い茶色が明るく・白が灰色に寄るので使わない(コードに `tone: 'aces'` の切り替えは残っているが、既定でも試しでも使わない)。
- 黒い輪郭の殻は、材質を差しかえる時に外す(アニメのおもちゃに見える。毛は輪郭の近くで短くなるので、毛の時もいつも外す)。
- 重さ(L4。開発 PC の内蔵 GPU・幅 390・画素 3・段 mid・1 件ごとに新しいブラウザ。実機の数字ではない): ぬの 57〜59 fps・1 コマの CPU 0.4〜0.7ms・三角は いつもの と同じか少ない / つるつる 57.6 fps / け 34〜43 fps・CPU 3.7〜9.2ms(ロボくんが一番重い)。段を low・倍率 1 にしても同じ絵で、ぬのは 60 fps。
- 前にあった別の線(`w/real-material`)の `?real=1`(`realLook.js`・`m_real_materials.py`。ACES・露出 0.62・主の光・影の絵・SSAO の high の段・`yc_real` の印)は、いまの開発の木に無く、今の見た目の元でもない。そこの値は使わない(この節の数字が正)。

### 共通の落とし穴と色合わせ(しつかんでも同じ。コードの `smoothNormals`・`cylinderUv`・`contactOf` が今の答え)

- **輪切りをつないだ頭・胴は、本物らしい光で横の縞が出る**(平らな塗りでは見えない。つるつるが一番目立つ)。形でなく法線のせい(影・SSAO を切っても残った)。法線を 8 回ならすと消える(向きが 40° より違う所はまとめず混ぜない = 箱の角は残る。いつもの では元の法線に戻す)。builder 側で直すなら、輪の数を増やすか、法線をならしてから書き出す。
- **UV の無い部品に頂点ごとの立方体の投影で UV を付けると、向きの切りかわる輪で絵が伸びる**。部品ごとの円柱の投影にする(継ぎ目は真後ろ 1 本)。布の毛羽の絵は、足した 2 つ目の UV(uv1。12 cm で 1 枚。`texture.channel = 1`)に貼り、元の UV(色の絵・顔の表)はそのまま。投げ方は **キャラの座標(object3d の中、メートル)の真ん中の縦の軸のまわり**: 部品ごとの真ん中のまわりで投げると、顔のお面のような板は真ん中の近くで角度が急に変わり、毛羽が放射の筋になった。
- 色を絵に合わせる: 同じ姿勢で くらべる。描く輪を止め(`renderer.setAnimationLoop(null)`)、いつもの と組み合わせごとに描いてすぐ `gl.readPixels` で、キャラの箱の前の面の 7x12 の点を読む。キャラを隠して描いた色と 30 以上違う点だけが体の点で、差の平均と、暗い点・明るい点の片寄りを見る。結果(内蔵 GPU): 映画風(ACES 0.58)は差 17.3 で、暗い茶色 +15・白 −16(灰色っぽい茶色)。色あいを保つ曲線(Khronos PBR Neutral)+ 明るさ 0.85 + 布のつや 0.75 → 0.38 + 面の照り 0.4 で、差 7.7(ノリー)・12.8(みかん)、片寄り ±5 以内。つるつるは部屋の光 0.65・粗さ 0.55・照り 0.6。毛は殻の rim と sheen で暗い所が明るくなるので rim 0.1・sheen 0.3。色あいを保つ曲線は、絵の色の明るさをほぼそのまま(暗い所から 0.04 を引くだけ)にして、明るすぎる所だけ丸める。ACES は中の明るさを上げ、白を灰色に寄せるので、ゆるキャラの絵の色には合わない。
- 画面のコードで `drawImage`・`getImageData` は使えない(`web/test/privacy.test.mjs` が止める。色の絵の平均の色を読もうとして落ちた)。色の絵のある材質は、布のつやを半分にするだけにした。
- `Box3.setFromObject(character.object3d)` は見えない子も数える。足元の影の板をキャラの子にすると、見せ方の箱が広がって小さく写る → 影は舞台(scene)に置き、毎コマ足元へ動かす。

### 確かめ方
- 撮る: 内蔵 GPU の確認台で、組み立てた dist を小さな配り役(/api は 503)で配り、`?character=<id>&auto=0&shitsukan=<id>` を開いて「カメラなしで試す」→ `current()` が替わるのを待って撮る。キャラの箱を画面へ写した数(縦横の比)も一緒に残すと、見た目ごと・端末ごとの置き方の差が数で分かる(6 体とも 4 つの見た目・4 つの大きさで同じ比になった)。fps は `?perf=1&perfsec=20` を 1 件ごとに新しいブラウザで(毛のように初めて選んだ時に準備がある物は、最初のコマは前の見た目のまま)。
- Quest のブラウザ: 配り役が index.html に「測り終わったら結果を POST する」1 行を足して返し(製品は変えない)、`adb reverse` の別の番号で開く(人の reverse は触らない)。終わったら、自分が開いたタブだけを devtools の `/json/close/<id>` で閉じ、自分の reverse と forward を外す。
- iPhone のシミュレーター: WebDriver のタップは文字の長押し(青い選択の印)になり、押したことにならない回があった → 入口の「カメラなしで試す」は JS の click で閉じる。ボタンには `user-select: none` を付けた。
- `YC_BROWSER_TESTS=1 npm test` を確認台で流すなら: 確認台の repo を git clone し、自分の線を bundle で入れ、node_modules は repo の物に junction、`public/mediapipe` は robocopy /E(消さない)。組み立て前は「dist があれば」の試験が飛ぶので、vite build の後に流す。VR のまね(`scripts/vr-check.mjs`)は、確認台ではマイクの 2 項目(入る前の許可・出た後もマイクが続く)がいつも落ちる(マイクの機械が無い。抜いた土台でも同じ 2 件)。材質の直しを確かめる時は、ほかの項目が抜いた土台と同じかを見る。
- 合わせが来る前に確かめたい時は、合わせ係の線と自分の線を一時の写しで合わせ、`git merge-tree` でぶつかりを見て、同じ試験を流す。一時の写しを消す前に、中の node_modules のつなぎ(junction)を `rmdir` で外す(つなぎの先を消さないように)。コミットの前の点検(`prepush_check`)は `git add` の後に流す(まだ足していない新しいファイルは見ない)。

### 上の段が混む時(ボタンの置き方)
- PC 1280 で 4 つのボタンを上の段に並べると、右上の「Claude の考え」に重なった → 幅 1600 未満は「しつかん」のボタン 1 つ + 開く札にする。札は画面からはみ出す時に横へずらす。開いている間は topGuard を包んで、キャラを札の下へ。
- スマホの上の段は、「性格・はじめての会話・覚えていること・Quest で開く」のうち 3 つで 1 行がいっぱい。「しつかん」(測って 65px)は、覚えていること が無ければ同じ行の右、あれば分かれた後の行に入れる(どちらでも行を増やさない。試験で出す・隠すの高さをくらべる)。
- 横向きのスマホ(高さ 500 未満)は上の段の行が横に巻く(overflow-x)。札の入れ物を position: relative のままにすると、巻く行の中で札が切れる → その時だけ static にして、札の基準を上の段の全体(.top)にする。スマホで長く押しても文字を選ばないよう `user-select: none` を付ける。

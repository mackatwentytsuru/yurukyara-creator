# カメラの入・切と印(第 12 波 b)

(元の文のまま)

- 本人の決め: カメラは使う人が決める。どの端末でも、いつでも入・切できる(入口だけでなく)。切っているのが基本。入れる前に 1 行の知らせ「カメラの えは、こたえを つくるために Claude に おくられます(ほぞんしません)。つかうかは あなたが きめてね」(言い換えない)。入っている間は小さな印。切ると、カメラの流れを止める。
- 部品: 決まりと画面は `web/src/stage/cameraSwitch.js`(`cameraSwitchPlan`・`mountCameraSwitch`・`cameraFailureText`)、絵の 1 枚は `web/src/conversation/cameraFrame.js`(`takeFrame`)、取り付けは main.js の BCV の 1 か所(ほかは 1 行ずつの印つきの足し: updatePrivacy・updateChips・テレビ表示の topGuard)。
- 置き場所: 入力の列(声 → カメラ → 文字 → 送る。幅 640 までは印だけ)と、テレビ表示の隅(「もどる」の左。縦持ちの一言の右の端は、隅のボタンの左から 10px あける。ボタンは入れている間、赤い点の分だけ広い(約 60px)ので、切った時の幅(44px)で決めると、入れた時に 12px 重なった)。知らせは入口と同じ形の真ん中の札(「カメラを つかう」「やめる」。外を押す・Escape で閉じる)。仮の頭脳の時は「いまは かりの あたまなので…かおの むきを みるのには つかいます」を足す。
- 印: 上の札の先頭に赤い点の札「カメラ オン」(高さ 500 未満で札の列を隠す時も、この札だけ残す)・ボタンの赤い点・下の注意書きの文(話しかけた時だけ絵を 1 枚 Claude へ・保存しない)。テレビ表示は隅のボタンの赤い点と注意書き。**札の名前を `rec` にすると、注意書きの 8px の点の `.rec` の規則に当たって札が 20x16px につぶれた** → `cam-rec`。新しい名前は、style.css を全部 grep してから付ける。
- 入れる: 新しい MediapipeSource を先に `start()` し、動いてから前の入力を止める(失敗しても今の入力のまま。`useSource` は先に止めるので、失敗すると入力が無くなる)。切る: SimSource を動かしてから MediapipeSource を止める(全部の track が ended)。勝手に止まった(許可の取り消し・抜いた)時は track の `ended` で切った形にそろえ「カメラが とまりました…」。
- 「選んだ」の見分け: 入口の「カメラを使って始める」は `e.isTrusted` の押しだけ(`?autostart=1` の `click()` は人の押しではない = 顔の追従だけで絵は送らない)。ヘッドセット・入口の LED・自動で始める画面・`?source=pose|bridge`・`?perf=1` では切り替えを出さない。
- 確かめ(GPU の Chrome・偽のカメラ = 描いた SVG を canvas の `captureStream` にして `getUserMedia` を替える・試験の道具の中だけ): 12 場面(PC 1280・1920、iPhone の Safari と Chrome の名乗りで 390x670・390x844、横 844x390、テレビ 1920・1280・スマホ縦、入口で選ぶ、自動で始める)で、知らせの文・印・44px・印がキャラに重ならない・話した回だけ絵 1 枚(JPEG の頭 ffd8ff・長い辺 512)・近づいた合図は送らない・切ると track が ended・切った後は送らない・描く大きさと画角が箱と同じ(引き伸ばし無し)。道具はリポジトリの外に置いた(場所は合わせの札)。別の頁どうしを、動いている姿のまま比べると、キャラの幅÷高さは姿勢と向きで ±4% 揺れた(17 場面で −4.0〜+3.6%。引き伸ばしではない)。引き伸ばしの確かめは ① 描く大きさの縦横の倍率が同じ・画角の縦横が箱と同じ ② 同じ頁で、キャラの体・目・口の動きを止めてから窓の大きさとテレビ表示を変え、描いた画素(不透明な所)の外枠の縦横の比を PC と比べる(リポジトリの stage_size_browser と同じ測り方)。カメラを入れたまま 10 段(1920x1080・390x670・390x844・844x390・320x568・テレビ表示 2 つ・切った後)で PC の −1.73〜+2.84%(いちばん大きいのは 320x568)。
- VR(Quest のブラウザ): Meta の WebXR の資料は「パススルーの絵の画素には届かない」。Meta のヘルプには、ウェブサイトにヘッドセット前面のパススルーの映像を渡す「ヘッドセットカメラ」の許可があるが、どの API か・どの版からかは書いていない(11-08 に読んだ)。実機で確かめていないので、VR は今のまま(ヘッドセットでは切り替えを出さない)。
- 顔の追従の部品(`@mediapipe/tasks-vision` 1.2.0)は、使った量の記録(絵ではない。部品の名前・速さなど)を 60 秒ごとと `close()` の時に Google の記録の住所(`odml.pa.googleapis.com/v1/log`)へ送ろうとする。止める設定は無い。公開の版は `web/vercel.json` の CSP の `connect-src` で止まり、console に守りの知らせが 2 行ずつ出る(画面の確かめの道具は、この知らせを問題にせず数える)。手元のサーバーには CSP が無いので、ネットにつながっていれば出ていく(試験では Playwright の `route` で止めて数えた: カメラを切るたびに 1 回)。カメラをいつでも切れるようにしたので `close()` が増えた。11-08 時点では直していない(手元のサーバーに CSP を付けるかは S6・S3 が決める)。

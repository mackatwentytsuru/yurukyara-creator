# 読み上げの声を歌・掛け声にする(短い試し)

## 手順

1. 候補を 3 通り読ませる: 普通の文 / 音を伸ばしたかな(「ねえぇ〜」) / `[sings]` タグ付き。1 回の返事は 1 秒ほど、費用は文字数だけ。
2. 文字数の台帳を付ける。呼び出しの前に合計を足し、上限を超えるなら呼ばない。タグの文字も数える。失敗した呼び出しも数える。実装例: `show/audio/song_tts.py`(鍵は環境変数から読み、表示しない)。
3. 音程補正(ボーカロイド風): pyworld で f0・スペクトル・非周期性を取り、音声の区間(f0>0 が続く塊。0.12 秒以上の途切れで分ける)ごとに、フレームを補間して目標の長さに伸ばし、f0 を決めたメロディの音階に差し替えて合成する。実装例: `show/audio/song_make.py`。
   - 音の切り替えは 30 ms ほどの移動平均でなめらかにする(しないと音が跳ぶ)。
   - 子音(f0=0)はそのまま残す。残さないと聞き取れなくなる。
   - 音符は区間内を均等に割るだけなので、母音の途中で音が変わる。音節に合わせるなら音節の境界を別に取る必要がある。
4. 仮の伴奏は numpy だけで足りる: 4 つ打ちのキック(周波数の下がる正弦波)、ノイズのクラップとハット、正弦波のベース、加算合成のノコギリ波のコード。BPM 140 なら 1 拍 = 18900 サンプル(44.1 kHz)で割り切れ、拍に合わせやすい。
5. 掛け声は拍の位置(サンプル = 拍 × 18900)に置いて重ねる。曲を差し替えるときは伴奏だけ替える。
6. 仕上げ: ピークを -1 dB にそろえ、`ffmpeg -map_metadata -1` で mp3 にする。

## 測った事実(2026-11-02)

- eleven_v4_turbo は 30〜40 字で返事 1〜1.4 秒。`[sings]` を付けると同じ文で長さが 4.96 → 5.92 秒、f0 の中央値が 260 → 304 Hz に変わった(効いてはいる。歌に聞こえるかは耳で確かめる)。
- 伸ばしかな(「ぁ〜」「ぇ〜」)は有声部分がいちばん長く、補正の材料に向く。f0 の下限 81 Hz のような誤検出が出ることがある。
- venv は `python -m venv` → `pip install pyworld soundfile numpy` で入った(Windows、Python 3.10)。librosa 入りの別の環境には pyworld が無かった。
- 5 フレーズ・8.6 秒の補正と合成は CPU で 3.4 秒。

## 注意

- 歌に聞こえるかは AI には判定できない。耳で決める人に、候補を並べて渡す。
- 既存の曲の歌詞は使わない。

## ショー用の音を 1 コマンドで作る(2026-11-03 に動かして測った)

- 入口: `show/audio/make_show_audio.py --script show/show_script.json --song <wav|temp> --out <フォルダ>`。曲が替わっても同じコマンドで、分離・読み上げ(キャッシュ)・口の曲線・拍まで作り直す。分けた物を持っているなら `--vocals`/`--karaoke` を渡すと demucs を動かさない(demucs の重みの権利は不明なので、提出物は stems を第一にする)。
- 仮の曲: `make_temp_song.py`(伴奏 16 小節 = 27.4 秒 + 音程補正した声を 2 回)。本物と同じく声と伴奏が混ざった 1 本。測定用に声だけの正解 `*_voice_truth.wav` も書く。
- demucs: `venv_audio` に `pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128` のあと `pip install demucs librosa requests`(RTX 5090 で GPU が使えた)。CLI ではなく Python の `apply_model` を使い、読み書きは soundfile にした(新しい torchaudio の保存の差を避けるため)。
- 口の曲線(`show_mouth.py`): 声の帯域(150〜4000 Hz)のパワーのしきい値を、もれの山と声の山を分ける大津の方法で自動に決め、最大から 40〜20 dB 下に収める。仮の曲の分離結果では、もれの山 -47 dB・声の山の中心との境 -23 dB だった。立ち上がりは時定数 20 ms、閉じは 5 コマ(約 50 ms)保ってから時定数 100 ms。伴奏だけの区間の口は最大 0.011(正解の声で測った)。
- 拍(`show_beats.py`): librosa の beat_track は裏拍にコードがあると半拍ずれた(約 200 ms)。テンポだけ librosa、位相は低域(250 Hz まで)の立ち上がりの総当たりにしたら、BPM 140.01、拍の誤差の中央値 9.4 ms。小節頭はベース(200 Hz まで)のクロマの変化で当たった(声・コードを混ぜると外れた)。1 曲だけの測定なので、本物の曲で測り直す。
- 読み上げは「文 + 声 + モデル + 設定」のハッシュ名の wav でキャッシュ。台帳(ledger.json)に文字数を足してから呼ぶ。2 回目からは API を呼ばない(同じコマンドを 4 回動かして確認)。
- せりふを曲のイントロに重ねる(`song.line_over_intro`)と、キックの強い曲ではクリップする。3 本(show_mix・vocals・karaoke)に同じ倍率をかけて -1 dBFS に下げる。
- 読み上げの声を歌声に寄せる試し(`voice_match_trial.py`): 高さは pyworld の f0 で寄せられる(298 → 359 Hz、歌声は 436 Hz)が、「高域を上げる」と、仮の歌声(重心 3122 Hz)より高かった元のせりふ(4869 Hz)がさらに遠ざかった(5623 Hz)。寄せるなら明るさは上げずに下げる向きを試す。
- Voice Changer(`voice_change.py`)は料金が音声の長さだけ(1 分 = 1000 文字ぶん)。--go を付けない限り API を呼ばない。まだ呼んでいない。

## 音楽 AI の曲の候補の構成を測る(2026-11-03)

- 道具: `show/audio/measure_song.py`(separate = demucs、measure = 歌い出し・拍・音量・歌声の自己相似)、`measure_lyrics.py`(faster-whisper で語ごとの秒。単独で動く)、`measure_summary.py`(サビの始まり・終わり・音量の上がり)、`measure_figure.py`(構成の図)、`cut_song.py`(拍の位置でつなぐ案の採点と書き出し)。
- demucs は CPU でも 2 分の曲 4 本が約 1.5 分で済む。GPU の札が取れないときは CPU の札で包めばよい(`--device cpu`)。
- 書き起こしは、歌声だけの wav を歌い出しの手前から読ませる。無音から読ませると「作詞・作曲…」のような幻の文字が 20 秒ぶん出て、本物の歌詞の秒が消えた。歌詞を initial_prompt で渡すと歌詞をそのまま写して語の秒が使えなくなったので渡さない。VAD も文字が崩れたので使わない。
- 音楽 AI は「イントロは 10 秒、声なし」と書いても 4 本中 2 本で 22 秒以上のイントロになった(8.5・11.5 秒は守った)。1 本は歌い出しの前に小さな声のような音(分離の漏れかは未確認)があった。
- 歌詞の最後の語を数秒伸ばすので、歌詞の秒だけでサビの終わりを決めると 4 秒早く切れた(1_b: 歌詞 38.2 秒、声が切れるのは 42.3 秒)。声の音量(0.3 秒より長く途切れた所)で終わりを探し、次の小節頭に丸める。
- 歌声の自己相似は、無声区間をマスクしないと、歌のない区間が最も似ているとして出る。ラグごとの対角線で、声のある所だけ類似(平滑 3 秒、しきい値 0.65)が続く区間を探すと、サビの 2 回が 54〜57 秒の間隔で出た。
- 音楽 AI の曲は最初から音が詰まっていて、イントロとサビの全体音量の差は 1〜3 dB。せりふをイントロに重ねると、せりふと曲の差が +0.5 dB(曲のピーク -3 dBFS、せりふ -2 dBFS のとき)。せりふの間は曲を下げる処理が要る(未実装)。
- 歌詞の途切れ目のない曲で 35 秒に縮めるつなぎは、類似(音の高さの構成)0.17〜0.91 と点数が悪く、声の途中を通った。耳での確認前は、縮めずに丸ごと使うほうが安全。
- せりふの間の曲を下げる(2026-11-03): `show_script.json` の `song.line_duck_db`(dB)。せりふの区間は一定、前後 0.3 秒は余弦でなだらかに下げて戻す。伴奏(karaoke)と全体に同じ下げ。`energy` は下げる前の音で測る(下げる前後で最大差 0)。9 dB で、せりふと曲の同じ窓の差が +0.5 → +9.5 dB。demucs は `shifts=1` の乱数で、同じ入力でも作り直すたびに口の曲線の歌の部分が少し変わる(最大 0.145)。

### せりふを歌と同じ空間に置く(11-03)
- 読み上げは歌声と同じ大きさでも、伴奏を 9 dB 下げたままだと浮く。測る物は「声と伴奏の差」。せりふ 9.5 dB、歌声 3.2 dB だった。`line_match.py` でせりふ 2.9 dB にそろえた(伴奏を下げる量は 2.2 dB)。
- リバーブ: RT60 1.1 秒、ウェット 28%、左右で別の残響。高域は 3.5 kHz から -1 dB(-3 dB は歌声より暗くなりすぎた)。
- 高さの差(せりふ 295 Hz、歌声 443 Hz)は、話し声と歌の差なので今回は変えていない。

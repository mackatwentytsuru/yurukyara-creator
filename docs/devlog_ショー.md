## 2026-11-02 新しいプロジェクトでステージの土台

### 測った数字

- シェーダーの待ち: 新しいプロジェクトの最初の撮影(1 カット)が、起動から終了まで 18 秒。10〜20 分の待ちは起きなかった。プロジェクトの DDC は 20 MB。速かった理由は確かめていない(同じ PC の別の場所の共有キャッシュが効いた可能性あり)。別の PC では長くなるかもしれない。
- 1 カットの秒数: 12〜16 秒(起動から終了まで。1920×1080、3 コマ、準備 45 コマ、時間方向 4 サンプル)。
- ステージを組む Python: 約 40 秒。
- LED の明るさ(0〜255 の平均、3 色の合計の平均。最大 255 のピクセルの割合、面の範囲はカメラの式で計算):
  - カット①: A 73.4 / 0.07%、B 115.7 / 0%、C 59.5 / 0.02%。真っ白 0%。
  - カット②: A 86.4 / 0%、B 96.7 / 0%、C 84.8 / 0%。B の真っ白は 0.03%。
- 継ぎ目(グリッドの絵): 絵の x=1279 の赤線は、A の右端の計算 598.3 px に対して 600.8 px。x=3039 の赤線は、C の左端の計算 997.5 px に対して 998.0 px。
- カット③の絵のキャラ(絵だけが違うカットとの差で測定): 313×340 px、幅÷高さ 0.921。元の絵は 0.922。縦に細くなっていない。
- 動きの試し(5 秒・150 コマ・1920×1080・30fps): 起動から終了まで 22 秒。同じ設定の 3 コマは 12 秒なので、1 コマ約 0.07 秒(10 秒 ÷ 147 コマ。秒の刻みが粗いので目安)。
- 扉の開き(画面の中央の高さで暗い所の幅): 15 コマ目 0 px、30 コマ目 9 px、60 コマ目 158 px、90 コマ目 328 px、105 コマ目 351 px。カメラも寄るので最後は 362 px。

### うまくいかなかった試し

- `volumetric_fog` というプロパティは無かった → `enable_volumetric_fog`。
- `LinearColor.to_rgbe()` は色の変換ではなく RGBE の符号化。ライトの色には自分で sRGB の `Color` を作って渡した。
- Git Bash から `/Game/...` を渡すと、MSYS が `C:/Program Files/Git/Game/...` に書きかえ、レベルが開けない(終了コードは 0)→ `MSYS_NO_PATHCONV=1`。
- `M_LED` が真っ黒: `SAMPLERTYPE_EXTERNAL` で「Sampler type is External, should be Color」。`SAMPLERTYPE_COLOR` で mp4 が映った。その前に別の原因と考えて HLSL の変数名 `line`(予約語)も直した。エラー文は撮影のログの「Failed to compile」の次の行にある。画面なしのコマンドレットでの再コンパイルでは出なかった。
- glb はメッシュごとに別の骨付きメッシュと骨で入る(胴と顔)。最初は顔だけを置いていた。
- 顔: glTF の材質のままだと、アトラス全部(4×6)が顔に映る → コマだけを映す材質を新しく書いた。透明の抜きだと縁がギザギザ、抜きをやめると透明の隙間の色が格子に見えた → 色に透明度を掛けて解決。
- 影なしのスポットライトが舞台を突き抜け、ホールの床に当たった → 影ありにした。ねらいが舞台の前の縁に近いビームは客席にこぼれたので、ねらいを奥へ寄せた。
- 面の前の面光源が細いと床の一部だけ明るくなった → 強さを幅に比例させた。
- カット②は足が切れた → 焦点距離 15.5 → 14.0 mm、ねらいを下げた。
- シーケンスでキャラを隠せなかった: `MovieSceneVisibilityTrack` のプロパティ名を `bHiddenInGame`、`bHidden` の 2 通り試し、どちらもキャラは写ったまま(原因は分かっていない)。同じアクタの位置のトラックは効くので、床下(z=-3000)へ動かして隠し、1 回で解決した。
- 動きの glb をそのまま取り込むのは失敗: `motions/wave.glb` は骨と動きだけでメッシュが無く、Interchange が「スキンが使われていない」と出して何も作らない。

## 2026-11-02 骨の動きの確かめ(パネルくん)

### 分かったこと

- 元の `model.glb` では胴と顔は 1 つの骨組み(6 本: root・body・arm_L・arm_R・leg_L・leg_R)を共有している。別の骨になるのは、Interchange がメッシュごとに骨付きメッシュを作るから。
- `wave`(2.4 秒)・`idle`(2.967 秒)・`jump`(1.067 秒)の骨の名前と初期の位置は `model.glb` と同じ(Blender で比べて確かめた)。

### やり方

Blender で胴と顔を 1 つのメッシュ(材質 2 つ)に合わせ、動きを NLA のトラックにして 1 本の GLB に書き出す。UE では Skeletal Mesh 1 つ、Skeleton 1 つ、Anim Sequence 3 本になった。

### 測った数字

- Blender の組み立て: 2 秒。UE の取り込み: 0.8 秒(`import_asset_tasks` の前後)。
- 3 秒・90 コマの撮影: 起動から終了まで 16 秒。3 コマは 12 秒なので、1 コマ約 0.05 秒(4 秒 ÷ 87 コマ。秒の刻みが粗いので目安)。
- コマを見て確かめた: 片腕が上がる、体が傾く、顔が体に付いて動く、形は崩れない、72 コマ目で初めの姿勢に戻る。

### うまくいかなかった試し

- 最初の組み立てで、消した物をもう一度たどって Blender の Python が止まった(私のスクリプトの誤り)。
- Blender の初期の 24fps のまま書き出すと、動きが短くなった(`wave` 2.4 秒 → 2.375 秒)。`scene.render.fps = 30` を先に入れて直った。

### 確かめていないこと

- 顔のコマを途中で変える: `MovieSceneComponentMaterialTrack` があるので、`M_FaceCell` の StartU・StartV をコマごとに変えられる見込み。試していない。
- `idle`・`jump` の撮影(取り込みまで)。
- この変更のあと、カット①③④を撮り直していない(②は撮り直して動いた)。

# 開発の記録: キャラの柱(ゆるキャラクリエイター)

(前半の AI の 3D 生成の道は、手組みと比べるために試した物で、提出物のコードには含まない。比べた数字は記録として残す。)

流れ: ゆるキャラの絵 1 枚 → 顔なしの絵(Codex) → 3D の形(AI の 3D 生成) → 整える(Blender) → 色(自分の絵から) → 骨と重み → 動き → 顔の表 → ブラウザ。
各段の出来は Claude が見て、足りなければ前の段をやり直す。うまくいかなかった試しも残す。数字は測った物だけ。

### うまくいかなかった試し・つまずき(直したもの)

1. AI の 3D 生成 の起動が `SRE module mismatch` で落ちた → 呼び出し元の `PYTHONHOME` などを子に渡さない。
2. AI の 3D 生成 の呼び出しが応答の時間切れで落ち、サンプリングのスレッドが居残って札を握り続けた → daemon にし、応答の待ちを長く・やり直しつきにした。(15 分ぶん無駄にした)
3. `numpy` 2 で `ptp()` が使えない → `np.ptp`。
4. 腕が刃のように細長く伸びた → 原因は Blender の OBJ 読み込みが物を 180° 回していたこと(重みは回す前の座標で測っていたので、骨とずれた)。物の回転を 0 に戻して直った。そのあと、腕の重みの境目を胴の側面より外に、肩の支点を腕の付け根に動かした。一覧の絵を開いて見つけた。
5. `trimesh` は OBJ の継ぎ目の UV を平均してしまう(f_led で `uv 数 = 頂点数` と出たのが手がかり)→ OBJ を自分で読む。
6. 塗れない面を Telea の穴埋めにすると筋が出た → 押し引きの穴埋め。さらに、島ごと届かない面が黒くなった → 塗れた色の平均で埋める。
7. 顔の面を横から見ると、貼った板に見えた(別の AI の判定でも指摘された)→ 面の縁を丸く、なめらかに透明にした。
8. 顔の表が違う行になった → glTF の絵は上が v=0 なので、`flipY` を見て行を選ぶ。ブラウザが古い JS を使い続けた → キャッシュなしの小さなサーバーを書いた。

### 設計の判断

- 顔は、体の表面に貼った面(`Face`)に、表(表情 5 + まばたき × 口 4 段階)の 1 マスを出す。口はシェイプキーにしない(1 つの塊に口の形を持たせるより、絵の切りかえのほうが確かで、LED の顔にも紙の顔にも使える)。
- 体の動きは、骨(root・body・手足か羽根・ふた)を世界の軸で回す式で作って焼いた。跳ねる・つぶれる・傾く・手をふる・おじぎ。人型の骨には合わせていない。
- 見た目の判定は、作った担当ではない別の AI(Haiku の判定役)に通した。

## 2026-11-02(夜・続き): 手組みの道を本命に

司令塔の指示で、「Claude が元の絵を見て部品を決め、Blender の Python で一から組み、撮って元の絵と比べて直す」道を作った。AI の 3D 生成 の版は比べ用に残した。

| | 手組み | AI 生成(AI の 3D 生成) |
|---|---|---|
| 1 周の時間 | 16 秒(Blender。builder から GLB・8 方向・動きの確かめまで) | 形 9〜15 分(GPU) + Blender 約 2.5 分 + 塗り 3〜16 秒 |
| 大きさ(`characters/`) | f_led 3.2MB、d_lantern 1.3MB | f_led 4.8MB、d_lantern 12MB |
| 輪郭の重なり(元の絵に対して) | f_led 93%、d_lantern 82% | f_led 96%、d_lantern 88% |
| 色むら | なし(単色 + 頂点の色の濃淡) | 面の境目でまだら |
| 許諾 | Blender だけ | nvdiffrast・DINOv3 が未解決 |
| 費用 | API 0 円(Codex の顔なしの絵 4 枚と、判定 3 回のみ) | GPU の札(約 25 分) |

- 手組みを書くまでの Claude の作業は、f_led で約 2 周、d_lantern で約 7 周(builder の数字を直して比べる)。提灯のほうが部品が多く(輪・布・ふた・台座)、時間がかかった。
- 形の近さは、まだ AI 生成のほうが上(重なり 96% 対 93%、88% 対 82%)。手組みは、羽根が板状で、元の絵のたっぷりした布に届いていない(未解決)。
- 判定役: Haiku(司令塔の指示前に 2 回)→ DeepSeek(2 回)。DeepSeek の 1 回目は「体から白い棒」「手をふるが読めない」を指摘し、原因(顔の面の角が空中に浮く)を直したら 2 回目で解消を確認した。
- 学んだこと: glTF は手続きの節点を書き出せない(白く飛ぶ)→ 頂点の色。顔の面は光線が当たらない角を最近傍に合わせる。手をふるの確かめは位相が逆の 2 コマ。

## 11-02 夜: 質感の判定をブラウザの絵に直した

Blender の絵で質感を「確認済み」にしていたが、見る人が見るのはブラウザなので、three.js で撮った絵で判定し直した。毛足 2/7、色 0/7 で、確認済みから外した(カバー率の質感 0%)。

- 色の原因を測った: three.js の光では、元の絵の約 68% の明るさに沈む。実行側で色の絵を発光にも貼る(lift 0.55)と、元の絵の 97% に戻った。頬が茶色いのは、色の絵のない材質に効いていなかった不具合。7 体で色は 6/7 まで上がった。

## 11-04: Quest 3 の道の「話し終わり → 返事」を測った(2026-11-04、本物の頭脳は測れず)

実機は使っていない。偽の Quest(Chrome に Quest の UA、偽のマイクに録音 `mic3.wav`)で、聞き取り(faster-whisper small・CPU 4 本・int8)から返事までを通した。起点は「声の区間が閉じた時刻」(声が止まって 450ms 後)。新しい道具は `web/scripts/stt-latency.mjs`、記録は `Listener.timings`(閉じた・送った・字が返った時刻)。

- **頭脳は仮**: 共有の `logs/claude_usage.json` が今日 803 回で、指定の上限 200 だと本物の Haiku が断られた。上限を上げたりファイルを書き換えたりはせず、仮の頭脳(声は本物)で流した。**② 返事の最初の文・③ 最初の音は、頭脳の時間を含まない。本物の数字ではない**(`valid:false`)。
- 測った数字(small・CPU・仮の頭脳、n=8、PC がほかの重い処理で混んでいる時間。中央値 / 最大): ① 字が返るまで 2,539 / 10,639ms(Whisper だけで 2,519 / 10,615)、② 最初の文まで 2,787 / 10,886ms、③ 最初の音まで 3,145 / 11,541ms、あいづちの音まで 29ms(中央値)。①が ②③ のほぼ全部で、仮の頭脳の分は約 250ms と約 350ms。最大の 10.6 秒は、混んでいた回(Whisper だけで 10.6 秒)。
- **見つけて直した不具合**: あいづちが字より先に鳴っていなかった。話し終わりの合図で先に鳴らす条件が「直近 2.5 秒以内に途中の字が届いた」で、server では途中の字が声の出始めの「…」だけ。2.5 秒を超える発話では条件が外れた。直す前は 3 区間中 1 区間だけ字より先(あいづち 26ms の 1 回、ほかは 2,094〜3,027ms で字と同時)。`listener.js` で区間が閉じるときにも「…」を出すように直したら、8 区間中 7 区間で字より先に鳴った(外れた 1 回は、その混雑の回。あいづちは、返事の途中・準備中は出さない決まりなので、前の返事が残っていたと考えられるが、確かめていない)。
- **base は採用しない**: 同じ録音(正しくは「19時からのオープニングが見どころだよ」。medium で確かめた)で、small は 8 区間中 7 区間で「19時からのオープニングが見どころだよ」が入り(うち 4 回は先頭に「なんだね、」が付き、完全に一致は 3 回)、1 回は「6時から」、base は 5 区間とも「強く力」「中口」「十くじ」などに崩れた。base の時間は PC の混み方で 1.5〜25 秒とばらつき、速さを比べられなかった。字を落として速くしない決まりなので、既定は small のまま。
- **cuda は試していない**: GPU の札が VRAM 不足で取れなかった(必要 10GB・空き 18.9GB の時点で、起動中の分 12GB)。
- 声は 1 本(`mic3.wav` の同じ文 3 区間を、4 回の読み込みで 11 区間)。`mic45.wav` は 1 区間で、同じ録音の別の言葉ではないので使っていない。別の人の声・別の文では測っていない。
- 先頭の「なんだね、」は、ページを通さず区間を切って small に渡しても出た(medium では出ない)。録音の頭にかすかな音が入っているのか、small の癖かは未確認。
- 失敗: 札を返すときに `--id` を付け忘れ、同じ名前の別の札(別の仕事の CPU の札)まで返した。同じ内容で取り直した。返すときは必ず `--id` を付ける。

**ようこそくん**(比べの絵: 作業フォルダの `yokoso_after.png`)
- 肩の端が破れて斜めに切れて見えた原因は 2 つ。帯の絵(`t01` が元の絵から切り出す)の左端に、元の絵の肩の折り返しの形と濃い縁の線が写っていた。もう 1 つは、帯が前の道の端で終わる開いた帯で、肩の上が空いていた。`t01` に両端を無地にそろえる処理を足し(既定)、帯は前の道に平面を合わせて全周を回る閉じた輪にした(`W.tilted_loop`。前の道とのずれ 0.6 mm)。
- 腰の右下の端のふくらみは、手で足した背中の道が腰の横で急に下へ折れていたため。平面の輪にして消えた。
- 腕の付け根の角は、`W.limb` の付け根の平らな端の縁が肩から出ていた。付け根も丸めた(`round_root`、既定)。丸めると肩の上に抜け(165 px)が出たので、`flare` 1.08 → 1.2 と、肩の段の胴の幅を元の絵の輪郭に合わせた(抜け 0)。
- 輪にしたら、腕が帯を突き抜けて手前に出た。`wrap_band` に `over`(腕の付け根の上へ持ち上げる。上限 3 cm)と `under`(頭や反対の腕にもぐる所だけ帯を縮める)を足した。上限なしでは帯が腕の先までかぶさった。`m03` の深く埋まる点は 143(頭)+ 59(右腕)+ 23(左腕)→ 0、最深 0.31 cm。
- `check_all.sh` 全部 OK。`characters/yokoso/` は model.glb と動き 5 本だけ入れ替えた(character.json・persona は同じ)。`web_talk_check`(8801、仮の頭脳)OK: 口の最大 0.54、表情 2、動き 3。
- 残り: 右の斜めから見ると、帯の下の縁が腕と交わる所が少しぎざぎざ。横から見ると肩が少し張った。

**パン(スキルだけの試験の builder を写して直した。`characters/` には入れていない)**(比べの絵: `bread_after.png`)
- 焼き色の濃淡が出ないのは、頂点の色 `Col` がブラウザでは拡散の光にしか掛からないため。明るさの持ち上げ(色の絵を発光に使う)と毛の殻の色には掛からず、明るいオレンジは R が 255 で頭打ち。測ると、てっぺんと顔の G は元の絵 113 / 192、ブラウザ 160 / 156 で、濃淡がほぼ消えていた。
- おなかの帯が別の部品に見えたのは、胴を高さで 3 つに切って材質を分けていたため(スキルにそう書いてあった)。境が硬く、毛の殻が材質の境で毛を短くして溝になった。
- 直し方: 濃淡を色の絵に入れる `P.fuzz_gradient_material` と、高さを v にする `P.height_uv` を足し、胴を 1 つの形・1 つの材質にした。毛の殻は色の絵を 8 段縮めて読むので、絵の縦が段の細かさになる(4096 では下の境が約 10% の幅にぼけ、8192 にした)。ブラウザで 1 回撮って、同じ高さの G の比を色に掛けた(てっぺん G 113 → 112、顔 192 → 190)。GLB 7,470 KB → 5,657 KB。
- 帽子のぼさぼさは、白い帽子に毛の殻が付いていたため。`sheen=0` の毛足の材質にして殻の対象から外した。ただの材質では樹脂に見えた。
- 残り: 帽子の形は楕円体の塊が見える(元の絵は 3 つの山がなめらかにつながる)。頬はぼけた丸のまま(元の絵はくっきりしたフェルトの丸)。下の境はまだ元の絵より少しぼける。別の AI の判定には通していない。
- スキル(`hand-built-character`)への書き足しは、書き込みの許可が下りず、足す文を作業フォルダの `skill_add_hand-built-character.md` に置いた。

## 11-04: Quest の道の通し(本物の頭脳と声、PC が混んでいる時間)

偽の Quest で、同じ録音を 3 回読み込んだ。声の区間が閉じた時刻が起点。CPU の負荷は 68〜96%。回数は少なく、声は 1 本だけ。

| 聞き取り | 区間 | 字が返るまで(中央値 / 最大) | 最初の音まで(中央値 / 最大) | 字になった数 |
|---|---|---|---|---|
| small・CPU | 9 | 41,910〜52,709ms(3 回分だけ) | 54,722ms(1 回だけ) | 1/9。ほかはサーバーの 30 秒で時間切れ |
| small・GPU、全部 | 8 | 1,034 / 10,176ms | 2,397 / 11,975ms | 8/8。うち 3 回は文の頭が欠けた |
| small・GPU、各読み込みの最初を除く | 5 | 328 / 6,332ms | 1,517 / 7,642ms | |

- 同じ設定の CPU は、さっきの測定では字まで中央値 2.5 秒だった。PC の混み具合で 20 倍変わる。**混んだ PC の CPU では使えない。** 確認用のサーバーは聞き取りを GPU にした。
- 文の頭が欠けた回(「頃だよ」「見どころだよ」など)の原因は未確認。声の録音は同じなので、PC が混んで音の集めが遅れた可能性がある。
- 先頭の「なんだね、」は GPU でも 8 回中 5 回出た。この録音に固有か、small の癖かは未確認。

## 11-04: 札なしで試験を動かしてしまった(3 回目)

新しい題材の試験の台本で、札を取る命令が内部の失敗(記録ファイルの鍵の時間切れ)を標準エラーに出して、出力が空になった。「取れません」を探す判定は、空なら通ってしまい、1 体の試験が札なしで約 2 分動いた(CPU は上限 12 本に達していた)。気づいて自分の番号だけ止めた。判定を「札を取りました」が出たときだけ進む形に直した。**札の判定は、断りの言葉を探すのではなく、取れた言葉を確かめる。**

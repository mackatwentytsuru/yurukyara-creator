# 開発の記録: キャラの柱(ゆるキャラクリエイター)

流れ: ゆるキャラの絵 1 枚 → 顔なしの絵(Codex) → 3D の形(TRELLIS.2) → 整える(Blender) → 色(自分の絵から) → 骨と重み → 動き → 顔の表 → ブラウザ。
各段の出来は Claude が見て、足りなければ前の段をやり直す。うまくいかなかった試しも残す。数字は測った物だけ。

### うまくいかなかった試し・つまずき(直したもの)

1. TRELLIS の起動が `SRE module mismatch` で落ちた → 呼び出し元の `PYTHONHOME` などを子に渡さない。
2. TRELLIS の呼び出しが応答の時間切れで落ち、サンプリングのスレッドが居残って札を握り続けた → daemon にし、応答の待ちを長く・やり直しつきにした。(15 分ぶん無駄にした)
3. `numpy` 2 で `ptp()` が使えない → `np.ptp`。
4. 腕が刃のように細長く伸びた → 原因は Blender の OBJ 読み込みが物を 180° 回していたこと(重みは回す前の座標で測っていたので、骨とずれた)。物の回転を 0 に戻して直った。そのあと、腕の重みの境目を胴の側面より外に、肩の支点を腕の付け根に動かした。一覧の絵を開いて見つけた。
5. `trimesh` は OBJ の継ぎ目の UV を平均してしまう(f_led で `uv 数 = 頂点数` と出たのが手がかり)→ OBJ を自分で読む。
6. 塗れない面を Telea の穴埋めにすると筋が出た → 押し引きの穴埋め。さらに、島ごと届かない面が黒くなった → 塗れた色の平均で埋める。
7. 顔の面を横から見ると、貼った板に見えた(別の AI の判定でも指摘された)→ 面の縁を丸く、なめらかに透明にした。
8. 顔の表が違う行になった → glTF の絵は上が v=0 なので、`flipY` を見て行を選ぶ。ブラウザが古い JS を使い続けた → キャッシュなしの小さなサーバーを書いた。

### 設計の判断

- 顔は、体の表面に貼った面(`Face`)に、表(表情 5 + まばたき × 口 4 段階)の 1 マスを出す。口はシェイプキーにしない(1 つの塊に口の形を持たせるより、絵の切りかえのほうが確かで、LED の顔にも紙の顔にも使える)。
- 体の動きは、骨(root・body・手足か羽根・ふた)を世界の軸で回す式で作って焼いた。跳ねる・つぶれる・傾く・手をふる・おじぎ。人型の骨には合わせていない。
- 見た目の判定は、作った担当ではない別の AI(Haiku の判定役)に通した。

# 開発の記録: 会話の柱(web/)

流れ: キャラを出す(VRM / rig の共通の呼び方)→ カメラで人を見つけて目と首で追う → 文字で話すと Claude が言葉・表情・動き・視線を返す → 声で読み上げる → 声で話しかける → 受付の流れ。
うまくいかなかった試しも残す。数字は測った物だけ(日付つき)。

## 2026-11-02

### 続きから始めたとき

- 前の作業役の残りは、`web/package.json`・部品を取る `scripts/setup-assets.mjs`・キャラの層(`src/character/`)で、どれも未コミットだった。キャラの層は設計が共通の呼び方(lookAt・setExpression・setMouth・play・update)に沿っていたので、読んで使い、試験を足してコミットした。
- 顔の検出を BlazeFace(顔の枠だけ)から **FaceLandmarker** に替えた。理由: 「2 人いたら話している人を見る」には口の開き(ブレンドシェイプ)が要る。口の動きの大きさで話している人を選ぶ。

### 追従(目が先、首が後)

- 頭は、目標を受けてから 0.14 秒遅れて動き出し、約 0.2 秒でなじむ。小さな向きの変化(約 8 度未満)は、頭を 35% しか動かさず、目で追う。試験で確かめた(`test/gaze.test.mjs`)。
- VRM の lookAt は頭の向きを引いた残りを目に配るので、頭が追いつくほど目は中央に戻り、自然に「目が先」になる。
- 話している人の選び方(`tracking/attention.js`): 顔ごとに口の開きの変化量を 0.35 秒で平均 → 2 番目の人の 1.5 倍以上で「話している」→ 見る人を替えるのは 0.5 秒続けて有利なときだけ(視線が泳がない)。マイクに声があるときは、小さな動きでも話しているとみなす。
- 画面の中の位置→世界の座標(`tracking/geometry.js`): お客さんから見て右が +x。カメラの絵ではお客さんの右は絵の左に写るので、符号を反転している。顔の幅から距離を出す(顔の幅 15cm と画角 65 度を仮定)。
- 視線の振れ幅の倍率の既定を 2 にした(1 だと、画面の端の人でも頭が約 8 度しか回らず、追っているのが分かりにくい)。`?gain=` で替えられる。

### つまずいたこと

- **アニメ調の VRM の顔は、MediaPipe が検出しない。** 検出の信頼度を 0.5 → 0.3 に下げても、偽のカメラで流した約 6 秒(60 コマ超)で 0 件。開発中の確かめは、画面の上でマウスを動かして人の位置を作る「カメラなしで試す」で行い、本物の顔での確かめは、本人のカメラに頼る(未確認)。
- Chrome の偽のカメラ(`--use-file-for-fake-video-capture`)は、パスが `/c/Users/...` の形だと読めず、緑の画面になる。`C:/Users/...` の形にする。mjpeg は読まれず、y4m は読まれた。
- 組み込みのブラウザ枠は、カメラを禁止している(`Permission denied`)。画面は「カメラを使えませんでした」と出し、「カメラなしで試す」へ誘導する(確認した)。
- **読み上げの先読みが効いていなかった。** 非同期の generator は、最初に読むまで動かないので、次の文の取得が前の文を話し終えるまで始まらなかった。取った分をすぐ溜める `_pump` を足した。最初の音まで、4014ms(1 回目)→ 約 500ms(3 回の測定: 533 / 502 / 515ms。頭脳は仮、声は flash、2026-11-02)。
- 読み上げのモデルごとの、短い文(「はい。」)の最初の音まで(各 2 回、`pcm_24000`、2026-11-02): `eleven_flash_v2_5` 288 / 300ms、`eleven_v4_turbo` 523 / 293ms、`eleven_v4` 786 / 778ms。既定は flash。
- ElevenLabs の鍵には `speech_to_text` の許可が無い(401)。読み上げは使える(starter・月 40,000 字。今日は 3,000 字の上限を自分で掛けている)。聞き取りは、当面ブラウザ内蔵(Web Speech API)で、クラウドの聞き取りは鍵待ち。
- `ANTHROPIC_API_KEY` が環境に無い。Haiku の呼び出しは、偽の Anthropic サーバーで読み取りの形だけ試験した(`test/haiku-stream.test.mjs`)。**本物の Haiku での返事の時間は、まだ測れていない。**
- Tailscale の証明書(`tailscale cert`)は使える状態(`<端末名>.<tailnet>.ts.net`)。ただ、実行するとホスト名が証明書の公開記録に載るので、本人に聞いてから。サーバーは `TLS_CERT` と `TLS_KEY` があれば HTTPS で配る。

- `.claude/hooks/run-web-tests.mjs`: web/ を直したら試験を回す。

### 場所との合流(夜)

- 場所の柱の `loadPlace`(`place/web/loadPlace.js`)を、`?place=<id>` で読み込んだ。部屋の 3D を出し、キャラは場所が決めた位置と向き(spawn)に立つ。`places/test_room` で、机を案内させると、視線と指さしが部屋の机に向かうことを画面で確かめた。
- **つまずき: キャラの大きさ(身長合わせ)を `object3d` に掛けていたので、座標がメートルと合わず、部屋の中でカメラが 1 割ほどずれた。** 大きさは中身(VRM のシーン)に掛けて、`object3d` の座標はいつもメートルにした。視線・カメラ・指さしは、キャラの座標(足元が原点・+z が正面・+x がお客さんから見て右)で考えて、世界の座標に直す。
- 部屋の中では、カメラが壁の外に出ると灰色の壁しか映らない。キャラから後ろへ光線を飛ばして壁の手前までしか下がらず、足りない分は画角を広げる(最大 75 度)。
- 目印の方向の言葉(右・左・手前・奥)は、キャラと向かい合ったお客さんから見た向き。場所の柱の `left_deg`(キャラの左が正)とは符号が逆になる(キャラの左手側が、お客さんの右)。

### 人の位置の入力を差し替えられる形に(夜)

- 場所の柱の提案(`getPeople()` が `[{ id, position(ワールド m), speaking? }]` を返す)に合わせた。入力は `tracking/sources/` に分け、MediaPipe(画面)・マウス(試し)・外から位置を受け取る `PoseSource`(AR の殻アプリ・VR)の 3 つ。
- 「誰を見るか」(`attention.js`)の入力を、画像の中の位置から、キャラの座標のメートルに替えた。奥行きは顔の幅からの推定で粗い(±0.4m 揺れても同じ人として追う試験を足した)ので、結びつけるときは重みを 1/4 にしている。入力が `id` や `speaking` をくれるときは、それを使う。
- 画面は窓なので、MediaPipe の入力は「人の位置」とは別に `gaze`(窓の向こうのカメラの位置から、人の左右・上下の分だけ振った点)を返す。AR・VR の入力は `gaze` を付けず、実際の頭の位置をそのまま見る。
- 確かめ: `?source=pose` で `conversation.setViewer([1.2, 1.5, 2.0])` を渡すと、頭が約 30 度(0.536 rad)右へ回り、状況の言葉は「右寄り 約 2.3m」になった。更新を止めると 1.5 秒で見えなくなる。マウス版も同じ経路で動く。

### 本物の Haiku で測った(夜)

- 鍵は司令塔から環境変数で渡された(値は表示も記録もしていない)。サーバーを起動するときだけ `ANTHROPIC_API_KEY` として渡している。
- 返事の時間(サーバーの内側、`npm run measure -- 10`、間隔 5.5 秒、2026-11-02、n=10): **中央値 1795ms、90 番目 4244ms、1200ms 以内は 3/10 回。** 読み上げの最初の音は約 0.25 秒で安定し、遅れの中身は Haiku の最初の文字まで(0.8〜4.0 秒)。目標の 1.2 秒は、このままでは切れていない。聞き取りと再生の始まりを足すと、画面の中ではさらに伸びる。
- サーバーを通さず同じ指示文で直接呼んでも(`scripts/probe-haiku.mjs`)、最初の文字まで中央値約 1.3 秒(0.8〜2.4 秒)で、サーバーの遅れではなく API 側。指示文の短縮・形式の変更(say を先に出す案 B: 中央値 1851ms)・`thinking: disabled` では、差がはっきり出なかった。
- 初めての本物の返事で、「お手洗いはどこですか」に聞き返した(目印にお手洗いがあるのに)。指示文に「目印の名前が出ていたら聞き返さず案内する」と 3 つの例を足したら直った。
- 費用の守り: Claude の呼び出しに、1 日 300 回・1 接続元あたり 1 分 12 回の上限を付けた(`server/limits.mjs`、試験 4 件)。測定中に自分で 1 分の上限に当たり、効いていることが分かった。サーバーの待ち受けは、既定で自分の端末だけ(`HOST=0.0.0.0` にしたときだけ外から開ける)。
- **判断が要ること**: 1.2 秒を切るには、モデルの待ちを縮める以外の手が要る。(1) 同じ呼び出しを 2 本並べて早い方を使う(費用 2 倍) (2) 話し終わりの直後に、あらかじめ作った短い相づちの声を出す(「うなずきでつなぐ」とは別の方針) (3) 優先枠が使えるか確かめる。

### 見せ方の切りかえとつないだ(夜)

- 場所の柱の `createPresentation`(`place/web/modes.js`)と `mountModeButtons` を組み込んだ。描画のループを `requestAnimationFrame` から `renderer.setAnimationLoop` に替えた(XR の中では前者が回らない)。
- 偽の殻(`window.webkit.messageHandlers.arhost` を定義して、`__arhost.onPose/onFloor/onHit` を呼ぶ)で、入る → 姿勢 → 床をタップ → 戻る、を通した。入ると `ready` が殻へ届き、背景(html・body・入口)が透明になる。姿勢が来ると、見ている人の位置が (0.2, 1.4, 0) になり、キャラは見ている方向の 1.6m 先の床 (0.2, 0, -1.6) に立った。タップで (0.8, 0, -2) へ移り、射影行列は殻の値(2.1)のまま。画面に戻すと元の位置に戻る。**実機の iPhone と Quest は未確認。**
- AR の世界は、アプリを起動した位置が原点で、撮った部屋と重ならない。だから AR では撮った部屋を隠し、目印の案内(部屋の座標)は合わない。部屋の位置合わせは、まだ無い。
- AR に入るとき、MediaPipe のカメラは止める(殻の ARKit が背面カメラを使い、前面カメラと競合する見込みのため)。

### 返事の時間を縮める(夜、本物の Haiku)

- 数字は、**あいづち**と**本当の返事**で分けて書く(混ぜて「1.2 秒」と言わない)。
- **thinking を切ると、最初の文字まで約 0.6 秒縮んだ。** 通常と交互に 8 回ずつ(サーバーを通さず直接): 中央値 1446ms → 840ms(最小 727・最大 903ms)。`effort: low` だけでは 1388ms、thinking を切るだけで 836ms。前に別の道具で測った知識(`claude-haiku-brain`)の設定(thinking を切る)を、数字で確かめた形。サーバーに入れると、サーバー内側の中央値は 1795 → 1345ms(n=10)。
- プロンプトキャッシュは効いている(2 回目以降 `cache_read_input_tokens` が 1331〜1501、書き直しは最初の 1 回だけ)。system に変わる物は入れていない。
- **ヘッジ(2 本目の呼び出し)は、効果を確認できず、既定で外した。** 交互に 35 組測って、最初の文まで中央値 922 vs 943ms、90 番目 1043 vs 1655ms。この時間帯は API が安定していて、遅い回(2 秒超)が出なかった。2 本目の最初の文字までは約 0.9 秒かかるので、1 本目が 1.0〜1.7 秒の回は救えない。コードと試験(4 件)は残し、`CLAUDE_HEDGE_MS` で入れられる(しきい値は 1800〜2000 を想定)。2 本目も、1 日・1 分の回数の上限に数える。
- **あいづち**(うなずき + 短い声)を入れた。「はい。」「ええ。」「なるほど。」「そうですね。」「はい、はい。」の 5 種類を、同じ声・同じモデルで前もって作り(27+6 字、今日の読み上げの上限から引いた)、`cache/fillers/` に残す。同じ言葉が続かないよう、前に出した物を避けて選ぶ。声が止まった(話し終わりらしい)と判定した時点で、確定した文字を待たずに出す。本当の返事の声は、あいづちのあとに続けて鳴る(1 秒以内の長さにした)。
- あいづちの計測(headless Chrome、送信を「声の回」として 10 回、2026-11-02): **あいづちが出るまで 中央値 21ms(送信から。本物の声では、声が止まったと判定する約 0.45 秒が足される。未測定)。本当の返事の最初の音まで 中央値 1158ms、90 番目 1826ms、1200ms 以内 6/10 回**(聞き取りの遅れは含まない)。2 つは別の数字として `/api/metrics` に残る(`fillerMs` と `totalMs`)。
- **つまずき 1: 追加した `meta` イベント(ヘッジとキャッシュの記録)が、頭脳の種類を空で上書きして、全部の回が「仮の頭脳」扱い(`valid: false`)になった。** 種類が入っているときだけ使うように直した。
- **つまずき 2: 短い質問(「入口は」)にだけ、モデルが JSON でなく文章で答え、画面が無言になった。** 原因は、履歴に前の返事を「ふつうの文」で入れていたこと(モデルがそれをまねた)。履歴も JSON の行に戻して直し、それでも文章で返った回は、その文を読み上げる救済を付けた。
- **つまずき 3: Python のパッチの中の `\n` が、書き出しで実際の改行になり、`brain.mjs` が構文エラーになった。** サーバーを使う試験が、エラーでなく待ちで止まって見えた(個別に走らせて見つけた)。Edit で直した。

### AR の位置合わせと、人型でないキャラの合流(夜)

- 場所の柱の `alignFlow` を組み込んだ。偽の殻で、部屋が現実の中で回転 0.6rad・移動 (2, -1) に置かれているとして、案内された 2 か所の床をタップ → 回転 0.600 を復元・食い違い 0cm・キャラが部屋の立ち位置 (1.72, 0.1, -1.41) に立った(世界へ直した spawn と一致)・案内する目印の方向と距離が、部屋の中で測ったときと一致。重なる前は、部屋の目印を Claude に 0 件しか渡さない。**実機の iPhone は未確認。**
- キャラの柱の rig(`characters/f_led/`、パネルくん)を `creator/viewer/rigRuntime.js` で読むようにした。`?character=f_led&place=test_room` で、部屋の中に立つ。話しかけると、顔が笑顔になり、口の絵が音に合わせて変わり、目印(机)の方へ体を向けて答える(絵: side-session-notes の `panelkun_room.png`)。
- **つまずき: rigRuntime が身長合わせの大きさを `object3d` に掛けている。** `object3d` の座標がメートルでなくなり、場所に立たせたとき・視線を計算するときに狂うので(VRM で一度つまずいた同じ形)、読み込んだあとに、大きさを中身へ移している(`moveScaleInside`)。rigRuntime 側の `_headWorld` は、頭の高さを「モデルの高さ×0.6」に `object3d` の位置を足して作るので、床が y=0 でない場所(AR で床が見つかった高さ)では、体の向きの計算の起点が少し高くなる(キャラの柱に伝える)。
- 動きの一覧は、キャラごとに替える。パネルくんは bow・nod・sad・think・wave・jump のファイルがある物だけを Claude に渡し、一覧に無い名前は none にする。
- 距離の数字(「約 1.6m」)が、そのまま読み上げられて不自然だった。指示文で「言葉にする」と直した。
- 調べものは、依頼どおり Claude では行っていない(今回の作業で外部の調査はしていない)。
- (追記)キャラの柱が `rigRuntime.js` を直した(大きさは `gltf.scene` に掛ける・頭の高さに置き場所の y を足さない)ので、`web/` の受け皿(`moveScaleInside`)を外した。部屋の中(置き場所 (0, 0, -0.5))で確かめ: `object3d.scale` は 1、頭の高さは (0, 0.54, -0.5)(身長 0.9m の 0.6 倍)、マウスを左へ動かすと体が左へ向く(headYaw -0.289)。
